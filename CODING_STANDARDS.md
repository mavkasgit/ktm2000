# Стандарты кода — KTM-2000

Файл читает **ревьюер** (skill `code-review`, ось Standards); реализатору
достаточно `AGENTS.md`, `backend/AGENTS.md` и `frontend/AGENTS.md`. Правило,
которое можно проверить линтером, тестом или гейтом, живёт в проверке, а не
здесь: здесь — суждения о диффе, для которых проверки нет.

## Домен и данные

1. **Edge cases** — валидация, ошибки и крайние случаи в том же изменении; без
   placeholders и «сделаем потом».
2. **Backend — только `AsyncSession`.** Синхронная сессия в новом коде —
   нарушение.
3. **Stock ledger** — `StockTransaction` единый источник правды; детали →
   [`docs/project-overview.md`](docs/project-overview.md). Второй источник
   остатка (колонка, кэш, «удобная» таблица) — нарушение.
4. **Transfer ↔ StockTransaction** — инварианты проверяются
   `assert_no_invariants_violations` в тестах, которые трогают передачи.

## Тесты

5. Тест, который трогает БД, берёт сессию у Cleaner'а пакета
   (`async with cleaner.session() as db` либо фикстуры `session`/`client`) и
   **не открывает транзакцию руками** для изоляции. Стратегии и guard →
   [`backend/tests/AGENTS.md`](backend/tests/AGENTS.md), решение →
   [ADR-0072](docs/adr/0072-izolyaciyu-testovoy-bd-derzhit-cleaner.md).
   Исключение — миграционные пакеты (`test_migrations.py`,
   `test_hanger_norm_key_migration_218.py`): они гоняют alembic на своей базе
   `ktm_mig_*` и открывают транзакции сами — это роль `ScratchDatabase`, а не
   изоляция теста.
6. Регресс проверяет **наблюдаемое поведение**, а не реализацию: удаление
   сломанной ветки кода должно ронять тест. Тест, зелёный на сломанном
   инварианте, — не регресс.
7. Ответ API, который читает клиент, описан моделью (`response_model` у
   FastAPI), а не сырым `dict`: форма проверяется на сервере, поле не может
   молча сменить тип (`null` вместо массива) или исчезнуть.

## Frontend

8. **FSD** — без cross-imports между `features` одного слоя; общее — в
   `entities`/`shared`.
9. Данные экрана читаются через `useQuery` и фабрику ключей; после мутации —
   `invalidateAfter` с бизнес-действием, а не точечный `invalidateQueries` в
   фиче (`frontend/AGENTS.md`, «Свежесть данных»).

## Тексты для оператора

10. Строки, которые видит оператор (лейблы, причины пропуска, тосты, заметки
    сидов, подписи в предпросмотре), не содержат номеров задач, ссылок на
    внутренние документы, путей к файлам кода и имён функций. Основание
    решения и провенанс живут в спецификации/ADR/журнале, а не в тексте на
    экране.
11. Операторский текст объясняет **что произошло и что делать**, а не как это
    устроено. Две подписи одного состояния (лейбл и дублирующая его заметка)
    схлопываются в одну.
12. Внутренние термины и аббревиатуры без расшифровки — нарушение, если
    оператор не может их прочитать из соседнего текста.

## Коммиты и PR

13. Коммиты — Conventional Commits на русском (`feat: …`, `fix: …`).
14. PR закрывает issue только английским `Closes #N` / `Fixes #N`; русское
    «Закрывает» GitHub не распознаёт.
15. Проверки PR читаются `gh pr checks <n> --watch` или `gh run watch`, а не
    ручным опросом.
16. Дев-данные правятся прямым SQL (`npm run db:sql`), миграция — под схему и
    прод, где нужны версии «до/после». Миграция ради текста в dev-БД —
    замечание ревью, а не «строгость».
