# E2E: отладка, разбор падения, `run-tier.mjs`

Справочник к [`frontend/e2e/AGENTS.md`](../../frontend/e2e/AGENTS.md).

**Когда читать:** тест упал и нужен порядок сбора доказательств; запускаете
`--debug`/`--headed`/UI mode; сомневаетесь, что именно делает обёртка
`run-tier.mjs`; ищете, где артефакты прогона.

## Аргументы и обёртка

Аргументы после `--` уходят скрипту как есть: `run-tier.mjs` передаёт их
`run-e2e.mjs`, а та дописывает только порты и передаёт их в `playwright test`.

`test:e2e:ui-mode` — тот же ярус `ui-e2e`, но с `--ui` от Playwright:
`run-tier.mjs` узнаёт режим по этому флагу, не навязывает свой
`--reporter=list` (в UI-режиме репортер задаёт сам Playwright, иначе панель
отчётов пустает) и отдаёт терминал ребёнку через `stdio: "inherit"` — иначе
интерактивный прогон молчал бы до закрытия окна.

## Если тест упал: доказательства

1. Воспроизведи по одному тесту, без ретраев и на одном воркере
   (`--workers=1` — флаг этого разбора, а не дефолт прогона: без него конфиг
   даст два воркера и две БД):

   ```bash
   npm --prefix frontend run test:e2e:ui -- e2e/<файл>.spec.ts \
     --retries=0 --workers=1 -g "<имя теста>"
   ```

   Для разбора в браузере добавь `--trace=on` (след останется в
   `test-results/`).
2. Собери доказательства, а не догадки: шаг падения из `error-context.md`
   рядом со скриншотом и видео в `test-results/<тест>/`, ответы API и логи
   backend из вывода прогона, состояние БД стенда
   (`docker exec ktm2000-postgres-test psql -U ktm2000_user -d <БД из .env.e2e> -c "…"`).
3. Только потом правь. Ассерты не ослаблять, тесты не пропускать: `test.skip`
   и `test.fixme` — не способ закрыть задачу.
4. Один коммит на одну причину; в сообщении — результат до и после.

Красный по одному прогону ещё не флейк, а зелёный по одному не доказывает,
что флейка нет: флейк оценивается серией (минимум 10 прогонов). След зелёного
не с первой попытки печатает [`green-on-retry-reporter.ts`](../../frontend/e2e/green-on-retry-reporter.ts)
— см. [`pass-cache.md`](pass-cache.md).

## Единственная точка входа — `run-tier.mjs`

Все `test:e2e*` ведут на [`run-tier.mjs`](../../frontend/e2e/run-tier.mjs), и звать Playwright
мимо них нельзя: без портов от `run-e2e.mjs` конфиг падает на чтении.

Скрипт нужен ради **двух блокировок**. База теперь своя у каждого прогона
(клон шаблона, [`db-stand.md`](db-stand.md)), поэтому соседние прогоны больше не затирают
друг другу данные; лок `node_modules/.e2e-run/current.lock` остался ради
ресурсов **дерева** (отчёт Playwright, `test-results`, кеш браузеров у дерева
одни), а число одновременных прогонов на машине держит счётный семафор
(`run-slots.mjs`, `E2E_MAX_PARALLEL_RUNS`).

Лок лежит внутри репозитория — это ровно его область действия: соседний
worktree его не видит, и потому ограничение прогонов на машине живёт в
слотах семафора вне репозитория.

Тиры: `all` (полный прогон, `test:e2e`), `smoke`, `ui-e2e`, `ui-narrow`,
`mobile`. У яруса `mobile` (`test:e2e:mobile`) до прогона печатается окно
проекта и список `@mobile`-спеков — см. [`tiers.md`](tiers.md).
Лок подбирается, если держатель **мёртв** (`taskkill`, отмена задачи, падение
ОС) — тогда следующий прогон снимает лок и сносит оставшийся клон БД по
`runId` из лока. У живого держателя лок не отбирается ни при каком возрасте
(#375): `E2E_LOCK_STALE_MS` (40 мин) — порог подозрения, при котором возраст
называется в логе ожидания одной строкой. Зависший прогон поэтому виден, а не
исчезает чужим снятием; решение убивать pid — за человеком. То же правило у
слотов семафора (`run-slots.mjs`).

Отчёт: `frontend/playwright-report/` после прогона с failures.
