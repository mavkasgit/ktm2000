# Не принято, и почему

Записи отвергнутых инструментов и решений — по образцу донора
(`mokevnin/dev-quality-gates/docs/not-adopted.md`), но по нашему стеку. Смысл
файла в том, чтобы следующий агент не переспоривал то же решение заново. Это
журнал решений, а не список плохих инструментов: у каждой строки есть то, что
изменило бы ответ.

Причины, которые используются ниже:

- **пересечение** — работу уже делает принятый шаг;
- **не блокирует** — советчик с нулевым выходом;
- **недоступно на Windows** — официальная доставка не ставится так, чтобы
  работало на машине владельца без ручной PATH-обвязки;
- **имя занято** — npm-пакет с тем же названием является другим проектом, то
  есть «поставить через npm» означает поставить чужой код;
- **supply-chain** — сигналы по самому инструменту или его каналам доставки;
- **bulk** — принятие означало бы переписывание половины репозитория одним
  ударом, что вне правил волны.

Отсюда правило, важное сильнее любого отдельного отказа: **на Windows «ставится
через npm» не равно «официальный канал доставки»**. Имена инструментов заняты
чужими проектами, поэтому единственный безопасный путь — пакет того же
владельца, что и репозиторий (так стоит `lefthook`, `eslint`, `typescript`,
`vitest`, `playwright`), либо отказ.

## Отказано пока

| Инструмент | Причина | Что изменит ответ |
|---|---|---|
| mise | пересечение: пины языков живут в `.nvmrc`/`.python-version` и сверяются шагом `pins`, задачи — в `scripts/gate.mjs`; второй источник версий хуже одного | пины разъедутся чаще, чем ловит шаг, или понадобится toolchain на каталог |
| hk | имя занято; доставка — cargo/brew; lefthook уже стоит официальным npm-пакетом и умеет скоуп по staged | официальная npm-дистрибуция плюс письменное сравнение с lefthook |
| typos | имя занято; доки и коммиты на русском дали бы ложное срабатывание на каждой кириллической строке | официальный бинарь плюс словарь допустимых слов, проверенный на `docs/` |
| lychee, rumdl, markdownlint-cli2 | пересечение: битые ссылки и «карды» документации ловит `scripts/check-doc-links.js` (шаг `docs-links`, красный ход доказан); форматирование markdown — bulk-правка всего `docs/` | измеренный перевес по скорости на полном дереве плюс отказ от bulk-форматирования как класса |
| actionlint, jactionlint | проверка workflow полезна, но каналов доставки под Windows нет (см. таблицу); сейчас пины actions сверяет `check-registry`, а семантику workflow никто не проверяет | официальный бинарь через пакет владельца плюс прогон на наших шести workflow |
| pkl | конфигурация как типизированный язык ради одной таблицы инструментов; `tools.json` плюс схема и шаг `registry` закрывают то же | появится конфиг с ветвлением, которого не выразить в JSON-схеме |
| oxlint, oxfmt, Biome | аргумент донора (ESLint 9 EOL, TypeScript 7) к нам не переносится: границы FSD держит `eslint-plugin-boundaries`, у oxlint такого правила нет; переход означал бы переформатирование всего фронта | правило про границы, которого нет в ESLint-сборке, плюс миграция по одному feature, а не одним коммитом |
| mypy, pyright, ty (Python) | backend типизирован частично: pydantic v2 и SQLAlchemy без strict-режима дают поток отчётов, а блокирующий порог сегодня означал бы «правь 300 файлов». Донорский прогон того же вывода не опровергнут: ty 0.0.95 не ловит unannotated-поле pydantic | измеренный список ошибок по `backend/app/` (число, а не «когда-нибудь») и порог, который команда согласна держать |
| pre-commit, prek | npm-имя занято другим проектом; официальная доставка — Python-пакет, то есть ещё один тулчейн ради того, что делает lefthook | хук-каталог, которого нет в lefthook, плюс решение уходить от node-обвязки |
| shellcheck, hadolint | npm-обёрты третьих рук, скачивающие бинари; в репозитории четыре shell-файла, а политики compose (потолки логов, healthcheck, restart) проверяет `backend/scripts/audit_compose.py` — шаг `compose-audit` | рост числа скриптов в `infra/` до десятков, тогда нужна проверка синтаксиса, а не политики |

## Не закрыто (это дыры, а не отказы)

Честный список того, чего у нас нет вообще, чтобы зелёный гейт не читался как
«покрыто всё»:

- **поиск секретов в диффе** — ни один сканер не стоит; отсутствие `.env` в git
  держится на правилах репозитория и на `.gitignore`, автоматизации нет;
- **орфография и стиль markdown** — только битые ссылки;
- **статический анализ Python-типов** — см. строку про mypy/ty;
- **валидация workflow-файлов** кроме совпадения пинов (`check-registry`);
- **жив ли репозиторий инструмента** (`archived`/`renamed`) — шаг `freshness`
  знает эти коды находок, но источника статуса нет: см. строку про GitHub API;
- **сравнение с версиями апстрима в локальном гейте** — без `--online` он
  отвечает только на вопрос «как давно мы смотрели в пин»; сами более свежие
  версии видно лишь из понедельничного прогона freshness.yml;
- **дифф-покрытие** — порог общий (73 %), по изменённым строкам не считается;
- **параллельный pytest в CI** — упирается в перенастройка coverage-порога,
  #378 переведён в ready-for-human, замеры сняты (serial ≈ 1003 с против
  307–368 с на `-n 4`).

## Как добавлять строку

Отклонил инструмент или заменил рекомендацию — добавь строку: причина и то, что
изменило бы ответ. Половинка без половинки не считается: «не нравится» не
переиспользуется следующим агентом, а «имя занято, прогон 2026-11-03» —
переиспользуется.
