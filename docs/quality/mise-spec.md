# Спека: mise — единый источник версий тулчейн

Статус: **принято владельцем 2026-11-03** (решение по тикету [#391](https://github.com/mavkasgit/ktm2000/issues/391)).
Отказ от 2026-11-03 в [`not-adopted.md`](not-adopted.md) отменён: сработала вторая
половина его триггера — toolchain на каталог нужен. Редакция переписана под
текущий стек: соответствует фактическому состоянию шага 1 переезда.

## Зачем mise именно нам

mise (mise-en-place) — один CLI, который по файлу `mise.toml` в корне проекта
поднимает окружение разработчика: версии языков, версии CLI-инструментов,
переменные окружения, задачи, автоустановку при входе в директорию.

1. **Версия инструмента определяется каталогом, а не машиной.** Мы живём в
   git worktree параллельно (Orca, агенты): агент в отдельном checkout'е
   получает toolchain по файлу этого дерева, а не по состоянию машины.
   `npm run doctor` чужую минорную версию замечает, но не починит; mise —
   ставит.
2. **Нулевая рука нового человека и нового агента.** `mise install` заменяет
   часть шагов GETTING_STARTED и делает их декларативными, а `mise.lock` делает
   установку воспроизводимой: та же версия и та же чексумма сегодня и через год.
3. **Канал доставки, который раньше считался недоступным на Windows.** Тикеты
   #365 (jactionlint), #366 (rumdl/typos/lychee), #369 (osv-scanner) стояли не
   на «инструмент плох», а на «npm-имя занято чужими обёртками, официальной
   установки нет». mise.lock = официальный бинарь владельца + чексумма — это
   ровно то условие, которое каждая из строк
   [`not-adopted.md`](not-adopted.md) называла «что изменит ответ».

## Принято (шаг 1, коммит `3d1db39c`)

- **`mise.toml` — единственный источник версий всех инструментов.** 18
  инструментов с точными пинами: node 26.13.0, python 3.14.10, hk 2.11.0, ruff
  0.16.9, oxlint 1.90.0, oxfmt 0.75.0, knip 6.44.1, dependency-cruiser
  18.7.1, betterleaks 1.9.0, osv-scanner 2.7.0, hadolint 2.15.1,
  jactionlint 2.4.0, ast-grep 0.51.1, agnix 0.60.2, typos 1.52.0,
  lychee 0.24.2, rumdl 0.3.2, shellcheck 0.11.0.
  shellcheck (добавлен в `7ee220e0`) и hadolint закреплены **заранее**, как hk:
  канал доставки готов, шага гейта у них ещё нет — решение по каждому
  принимает тикет, который их включает (строка `shellcheck, hadolint` в
  [`not-adopted.md`](not-adopted.md) остаётся в силе).
- **`mise.lock` (lockfile v3 + `.mise/locks/`)** фиксирует точные версии:
  30 платформенных записей (windows-x64 и linux-x64 на каждый инструмент) с
  чексуммами и URL, для npm-инструментов (oxfmt, knip, dependency-cruiser) —
  граф зависимостей. `mise lock --dry-run` — дрейфа нет.
- **`[env] _.python.venv = "backend/.venv"`** — mise-директива привязки
  интерпретатора к venv проекта. Файлы `.env*` остаются источником правды
  для `DATABASE_URL` и секретов — mise их не дублирует.
- **`[tasks]`** — алиасы точек входа (`check`, `gate`, `gate-fast`, `e2e`,
  `pytest`, `scripts-tests`, `doctor`, `dev`), каждая — одна строка
  `run = "npm run …"`. Семантику гейта по-прежнему держит
  `scripts/gate.mjs` (ADR-0070) — mise не повторяет её и не становится
  второй точкой входа.
- **Runner задач.** Задача `check` сейчас ведёт на
  `npm run gate -- --strict`; перевод `check` на `hk check --all` — шаг 2
  переезда. hk 2.11.0 в `[tools]` установлен и зафиксирован заранее,
  чтобы шаг 2 не зависел от канала.

Проверено на шаге 1: `mise run gate-fast` — 17 шагов, 17 ok; `mise run check`
(ярус full) — 21 шаг; у 18 бинарей `--version` совпадает с пином (`mise exec --`).
Повторно сверено 2026-11-03 перед закрытием #391: `npm run check:registry` —
25 записей, дрейфа `docs/toolchain.md` нет; `mise run gate-fast` — 17/17 ok,
0 fail (73.5–90.7 с); `mise lock --dry-run` — 18 инструментов, 30 записей,
расхождений нет.

## Что mise сознательно не объявляет в `[tools]`

| Инструмент | Почему не здесь |
|---|---|
| `pkl` | hk v2 встраивает собственный pkl-оценщик, отдельный бинарь не нужен |
| `import-linter` | pypi-канал требует uv/pipx; библиотека связана с кодом backend и остаётся в `backend/requirements-dev.txt` |
| vitest, @playwright/test, pytest-плагины, typescript | их импортирует код проекта; они привязаны к `node_modules`/venv, а не к PATH |
| docker compose, gh, powershell-обвязка | системные, machine-специфичные; переносятся только по отдельному решению с проверкой канала |

## Шаги переезда

1. ✅ `mise.toml` + `mise.lock` + `.mise/locks/` + `[tasks]` (коммиты
   `3d1db39c` и `7ee220e0`, #391). Одним коммитом не вышло: второй добавил
   18-й инструмент `shellcheck` и обновил lock до 30 записей; тикет говорил
   про 17/28, спека приведена к факту. Это осознанное отклонение от «один
   коммит» в тикете, а не потерянная часть.
2. Разблокировать и выполнить #365 (jactionlint), #366 (rumdl/typos/lychee),
   #369 (osv-scanner) — канал теперь есть; проверки добавляются шагами гейта
   (локальный гейт и CI — одна точка входа по ADR-0070), с доказанным
   красным ходом по PLAYBOOK.
3. CI: во всех workflow, где читается тулчейн, — установка mise ≥ 2026.10.12
   (ниже CI не прочитает lockfile v3) и вызов проверок дословно через
   `mise run`.
4. Реестр: запись mise в `tools.json`, перевод `pinned_in` на `mise.toml`,
   регенерация `docs/toolchain.md`, зелёный `check:registry`, обновление
   карты гейтов.
5. Удаление старых параллельных источников (`.nvmrc`, `.python-version`,
   дублирующие пины) — только после шага 3, когда ничто кроме mise не читает
   версии.

## Риски и отвеченные вопросы

- **Supply-chain / исполнение кода при `cd`.** Сам по себе `mise.toml` может
  запускать только install; trust-модель mise включена;
  в GETTING_STARTED — предупреждение «прочитай mise.toml чужого репо».
- **Windows + Git Bash.** `mise activate` в bash-профиле агента;
  powershell-обвязка тестов (`scripts/test-run.ps1`) и docker compose
  собирают окружение иначе — совместимость venv-привязки проверена на
  `python`/`ruff`/`alembic`/`pytest` из venv (ruff 0.16.9 в venv совпадает
  с пином mise — дрейфа нет).
- **Python 3.12.10 в venv против 3.12.16 в lock.** `[tools]` держит префикс
  «3.12», lock — точную версию. Реальный интерпретатор пока 3.12.10;
  byte-for-byte match требует переустановки venv — отдельный шаг, не
  молчаливая подмена окружения.
- **Без `mise activate` задачи видят PATH машины, а не только `mise.toml`.**
  Измерено 2026-11-03 на dev-машине: `mise run gate-fast` исполнил гейт на
  системном node 24.11.1, хотя lock держит 24.22.2 — в PATH агента
  `C:\Program Files\nodejs` и устаревший shim-каталог стоят раньше
  `mise installs`. Пин «24» при этом соблюдён (шаг `pins` зелёный), а
  `mise exec -- node` и чистый PATH дают 24.22.2. Вывод: шаг 1 доказывает
  «версия берётся из файла», но не «PATH очищен»; точную привязку даёт
  активация mise (шаг 3), а до неё `mise run` и `mise exec --` не
  эквивалентны по порядку PATH.
- **CI на старом mise.** lockfile v3 не старше mise 2026.10.12 — любой
  workflow обязан ставить mise не ниже этой версии (шаг 3).
