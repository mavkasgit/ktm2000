# Формат Excel справочника сырья (#63, #177)

Единый формат для импорта **и** выгрузки справочника сырья. Выгруженный файл
правится в Excel и загружается назад без перенастройки колонок: набор колонок
выгрузки — ровно тот, что читает парсер.

Код: парсер и форматтеры — `backend/app/services/catalog_excel_import.py`,
эндпоинты — `backend/app/api/routes/catalog_import.py`.

## Точки входа

| Действие | Endpoint | UI |
|---|---|---|
| Скачать пустой шаблон | `GET /api/catalog-import/template-excel` | мастер импорта → «Скачать шаблон» |
| Предпросмотр импорта | `POST /api/catalog-import/preview-excel` | загрузка файла в мастере |
| Применить импорт | `POST /api/catalog-import/apply-excel` | «Импортировать» в предпросмотре |
| Выгрузить справочник | `GET /api/catalog-import/export-excel` | меню «Операции» → «Экспорт: скачать справочник (Excel)» |
| Импорт фотографий | `POST /api/catalog-import/preview-zip`, `/upload-zip` | меню «Операции» → «Импорт: фотографии (ZIP)» |

Права: запись справочника — `editReferences` (`apply-excel`). `preview-excel`,
`template-excel`, `export-excel` ролевой проверки не имеют — как и остальные
эндпоинты этого роутера; UI показывает меню «Операции» только тем, у кого есть
`editReferences`. Файл выгрузки — `final_catalog.xlsx`.

## Колонки (11)

Порядок и названия — `TEMPLATE_HEADERS`; заголовки ищутся в первых 30 строках,
обязательна колонка «Артикул». Лишние колонки игнорируются (`Фото`,
«Размерность» и прочие legacy-хвосты читаются как мусор, но не ломают строку).

| Колонка | Поле | Правило |
|---|---|---|
| Артикул | `sku` | ключ строки; пусто — ошибка строки, дубликат в файле — ошибка строки |
| Наименование | `name` | выгружается всегда как в БД; пустая ячейка ничего не затирает |
| Периметр, мм | `perimeter_mm` | число > 0 |
| Габарит, мм | `mount_width_mm` | число > 0 |
| Длины, мм | `product_lengths` | одна длина — числом, несколько — строкой `«2500, 2700»` |
| Кол-во на подвесе | `quantity_per_hanger` | ручные нормы позиционно по длинам: `«48, , 48»`; норма без длин — числом при пустой колонке длин |
| Примечания | `notes` | текст |
| Не дробеструится | флаг `skip_shot_blast` | `да` / `нет` / пусто (не трогать) |
| Ламируется | флаг `is_laminated` | `да` / `нет` / пусто (не трогать) |
| Эквиваленты | `aliases` | SKU через `«; »`; связь двусторонняя — выгрузка пишет обе стороны |
| Парный профиль | `product_pairs` | **только SKU** партнёров через `«; »`; норма пары — не здесь |

## Ячейки: точные форматы

- **Длины, мм.** Одиночная длина — число (`2780`), несколько — текст
  `«2500, 2700»`. Разделитель — запятая, порядок — по возрастанию.
- **Кол-во на подвесе.** Сегменты позиционные, по числу значений в «Длинах»:
  `«48, , 48»` — у второй длины ручной нормы нет. Пустая ячейка = «норм нет
  ни по одной длине»: это отличается от `«, »`, которое импорт прочитал бы как
  явные пустые записи и создал бы их в `quantity_per_hanger`.
- **Норма без длин (#177, Q2/Q11).** Если у артикула длин нет, а ручная норма
  есть, «Кол-во на подвесе» выгружается **числом** при пустой колонке «Длины,
  мм». В БД такая норма живёт legacy-скаляром `{auto: null, manual: N}` и
  раскрывается в per-length-словарь, когда у артикула появятся длины. Импорт
  принимает одну такую норму; две и более без длин привязать не к чему — ошибка
  строки.
- **Парный профиль.** Только перечисление SKU (`«ЮП-2616; ЮП-3158»`), пара
  симметричная, норма в импорте не задаётся. Старый формат файла
  `«ЮП-2616, 30»` **не поддерживается**: это ошибка строки с подсказкой
  «норма пары правится через pairs-API». Норма пары — `product_pairs.
  quantity_per_hanger` (`{"<длина>": {"manual": N}}`, ключ обязан входить в
  пересечение длин A∩B) и правится в карточке артикула / pairs-API.
- **Флаги.** Пустая ячейка = «не менять»; явное `нет` снимает флаг.
- **Числа.** Дробный разделитель — запятая или точка (`120,5` == `120.5`).

## Поведение импорта

- Строка = create или update; **отсутствие строки в файле — не удаление**
  артикулов (#177, Q9).
- Артикул без длин — черновик: создаётся/остаётся `is_active = false`
  (#177, Q3). Импорт не активирует артикул, пока у него нет длин ни в строке,
  ни в БД; как только длины появились — активирует.
- Вычисленное `auto` не переписывается: импорт пишет только ручные значения
  (#127), а `auto` по совпадающим длинам сохраняется.
- Ошибки строк не блокируют остальные: строка пропускается, остальные
  применяются. Ошибка партнёра (`Парный профиль X не найден`) не мешает
  обновить саму строку артикула.
- Пары создаются без нормы (симметрично, `quantity_per_hanger = {}`): N
  считает движок, ручное значение правится в карточке.
- Строки выгрузки упорядочены по `sku` (#177, Q5) — курируемый порядок файла
  не воспроизводится.

## Чего в формате нет

- **Фото.** Колонки «Фото» в импорте и в выгрузке нет (#177, Q4/Q12). Фото
  ведётся отдельным потоком: ZIP-импорт (`/upload-zip`) или карточка артикула.
  Колонка «Фото» остаётся только в рабочем файле `excel/final_catalog.xlsx`
  (локальный артефакт, в git не хранится) — наборы колонок файла и выгрузки
  различаются осознанно.
- **Удаление артикулов через файл** (#177, Q9).
- **Норма пары в «Парном профиле»** (#177, Q1).
- **Размерность, тип, вид упаковки** и прочие поля dump-файлов — игнорируются.

## Round-trip

Неизменённый справочник обязан пройти цикл «выгрузка → предпросмотр» без
ошибок и без изменений: все строки `skip`. Этот контракт защищён тестами
`backend/tests/test_catalog_excel_import.py` (секция `export-excel`) и
компонентными тестами меню «Операции».

Одно исключение — разовая нормализация, а не потеря значения: артикул, у
которого норма хранится скаляром (legacy, без привязки к длине), а длины уже
есть, при первом же импорте выгрузки раскроется в per-length-записи, и preview
покажет `update`. Значение нормы при этом сохраняется, повторный цикл даёт
`skip`.
