# Свежесть данных — обоснования

Правила — в [`frontend/AGENTS.md`](../../frontend/AGENTS.md), раздел «Свежесть
данных». Здесь причины и история.

**Когда читать:** при подключении нового запроса или мутации, правке
`cacheInvalidation.ts` / `queryKeys.ts` / `main.tsx`, при жалобе «изменение видно
только после F5» или при соблазне увеличить `staleTime`.

- Списки и карточки читаются **только** через `useQuery` из
  [`@tanstack/react-query`](https://tanstack.com/query). Список в локальном
  `useState` с `useEffect(load)` — дрейф: такой экран не видит чужих изменений
  и не может сообщить о своих.
- После мутации экран зовёт `invalidateAfter` из
  [`src/shared/api/cacheInvalidation.ts`](../../frontend/src/shared/api/cacheInvalidation.ts)
  с бизнес-действием. **Прямой `invalidateQueries` в фиче запрещён**: именно
  разбросанные списки ключей разошлись и дали баг «строка видна только после
  F5». Какие домены задевает действие — решение матрицы `CACHE_ACTIONS`.
- Ключи берутся из фабрики
  [`src/shared/api/queryKeys.ts`](../../frontend/src/shared/api/queryKeys.ts), а не пишутся
  литералами.
- Глобальный `staleTime` равен интервалу опроса — 12 с
  ([`src/app/main.tsx`](../../frontend/src/app/main.tsx)): операционные экраны держит
  12-секундный опрос, а возврат фокуса перечитывает только запросы старше
  `staleTime` — для неопрашиваемых экранов (склад, справочники, журнал, план)
  это единственный автоматический триггер свежести. Длинный `staleTime` не
  чинит свежесть, он прячет забытую инвалидацию.
- Правило и его история —
  [ADR-0041](../adr/0041-reestr-sbrosa-kesa-i-stale-time.md).
