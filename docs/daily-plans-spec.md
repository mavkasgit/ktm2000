# Спецификация дневных планов участка

## Назначение

Дневной план — сохранённый набор актуальных заданий участка на конкретную дату. Он используется для быстрого формирования рабочей выборки и фильтрации заданий, но не изменяет общий производственный план, маршрут или факт выполнения.

## Пользовательский сценарий

### Режим `Задания`

Страница участка показывает все актуальные задания. Справа доступен read-only список дневных планов:

- дата плана;
- время, если на одну дату создано несколько планов;
- процент выполнения;
- количество заданий.

Клик по плану добавляет его в фильтр. Повторный клик убирает план из фильтра. Несколько выбранных планов объединяются в один список без повторов. Кнопка `Все задания участка` снимает фильтр.

На вкладке `Задания` нет:

- создания планов;
- редактирования состава;
- отзыва заданий;
- отдельного изменения даты.

Все операции по изменению плана выполняются на вкладке `План`.

### Режим `План`

Порядок вкладок:

```text
Задания | План | Остатки
```

В режиме `План` есть:

- панель сохранённых дневных планов;
- кнопка создания плана;
- фильтрация по одному или нескольким планам;
- состав выбранных планов;
- отзыв незавершённых заданий из плана;
- печать текущего отображения.

В режиме `План` задания доступны только для чтения. Кнопки внесения выполнения и группового завершения отсутствуют.

### Создание

Создание выполняется без модального окна. В панели плана кнопка `Создать план` переключается в режим подтверждения: рядом появляются типовой `DatePicker`, порядковый номер плана для выбранной даты и кнопка `Подтвердить`. В этой версии создаётся пустой план; задания добавляются отдельным последующим сценарием. Дата фиксируется при создании. Номер отображается по порядку планов этой даты, без времени создания.

```json
{
  "section_id": 3,
  "plan_date": "2026-09-24",
  "work_task_ids": []
}
```

Дата сохраняется сервером в дневном плане и не редактируется. Несколько планов одной даты разрешены. При последующем добавлении заданий backend проверяет существование заданий, принадлежность одному участку, отсутствие terminal status и отсутствие membership в другом активном плане.

### Отзыв

Отзыв доступен для незавершённой позиции плана. Он:

- удаляет только связь `DailyPlanItem`;
- не отменяет и не изменяет `WorkTask`;
- сохраняет фактическое выполнение и ledger;
- пишет событие в `AuditLog`.

После отзыва задание можно включить в новый дневной план.

## Доменная модель

### `DailyPlan`

Хранит:

- `id`;
- `section_id`;
- `plan_date`;
- `created_at`;
- `created_by`.

Один участок может иметь несколько планов с одинаковой датой.

### `DailyPlanItem`

Хранит только membership:

- `daily_plan_id`;
- `work_task_id`.

Состав не хранится как snapshot. Все отображаемые данные задания читаются из актуального `WorkTask` и существующей доски.

### Инварианты

- Одно задание одновременно принадлежит максимум одному активному плану.
- Глобальный unique `work_task_id` в БД защищает правило от гонок.
- Одинаковая дата у нескольких планов разрешена.
- Завершённое задание нельзя добавить в новый план.
- Завершённое задание нельзя отозвать из плана.
- Завершённое задание остаётся в составе созданного плана и учитывается в его проценте.
- Дата дневного плана неизменна после сохранения.

### Создание

```json
{
  "section_id": 3,
  "plan_date": "2026-09-24",
  "work_task_ids": []
}
```

Создание выполняется без модального окна. В панели плана кнопка `Создать план` переключается в режим подтверждения: рядом появляются типовой `DatePicker`, порядковый номер плана для выбранной даты и кнопка `Подтвердить`. В этой версии создаётся пустой план; задания добавляются отдельным последующим сценарием. Дата фиксируется при создании. Номер отображается по порядку планов этой даты, без времени создания.

Ответ — summary созданного плана.

```json
{
  "id": 12,
  "section_id": 3,
  "plan_date": "2026-09-24",
  "item_count": 0,
  "progress_percent": 0
}
```


### Состав

```json
{
  "items": [
    {
      "id": "12:101",
      "daily_plan_id": 12,
      "work_task_id": 101,
      "task": {},
      "progress_percent": 50
    }
  ]
}
```

`task` — актуальная полная проекция доски, а не сохранённый snapshot.

## Прогресс

Процент плана — средний прогресс его текущих строк по актуальному фактическому прогресс задания. После полного выполнения задания его вклад фиксируется как 100%; отзыв меняет состав и пересчитывает процент.

## Печать

Печатается текущий отображаемый набор:

- на `Задания` — обычная выборка доски с активными фильтрами;
- на `План` — объединённый состав выбранных планов, включая завершённые строки;
- на одном плане — один блок;
- на нескольких планах — отдельные блоки плана.

Печать не использует отдельный API и не меняет текущий выбор.

## Права

- Просмотр планов и кандидатов: `READER_ROLES`.
- Создание и отзыв: `WRITER_ROLES`.
- Все операции выполняются в пределах выбранного участка.
- План принадлежит участку, а не отдельному пользователю; доступ пользователей участка общий.

## Проверка

Обязательные проверки:

- одинаковая дата у нескольких планов допустима;
- terminal task нельзя добавить;
- duplicate membership отклоняется;
- completed task остаётся в composition;
- revoke не меняет WorkTask и создаёт audit;
- миграция проходит с `060_length_model_cutover` до `061_daily_plans`;
- frontend собирается;
- section-тесты проходят;
- на вкладке `Задания` панель планов является read-only фильтром;
- на вкладке `План` нет completion actions;
- печать использует фактически отображаемые задачи.
