## 1. Учёт КПЗ: фактические нормы на подвес

### Как считали

Колонка «На подвесе» в обоих файлах **пуста во всех 81 358 строках**. Норма восстановлена из фактических записей:

- «Подвесы, шт» = 1 во всех 57 723 заполненных строках, то есть одна строка = один подвес;
- «Ламели, шт» — количество изделий на этом подвесе;
- норма = «Ламели, шт» / «Подвесы, шт» = «Ламели, шт».

Проверка: для `361` получается 61, для `228` — 72, для `318` — 76, для `324` — 86; это совпадает с нормами КТМ/РП из файлов «Кол-во изделий на один подвес». Значит, восстановление корректное.

Считались только строки, где артикул непустой и норма > 0. Составные записи (`ЮП-2616 + ЮП-2604`), размеры/листы, описания и пустые маркеры отброшены; парные завески требуют отдельного разбора (см. оговорки).

### Оговорки к сверке

1. **Длина.** Реестр хранит N для основной длины (часто 2700), а КПЗ агрегирует все длины. Для артикулов с несколькими длинами (например, `ЮП-009`) сравнение некорректно без разреза по длине.
2. **Парные завески.** `ЮП-2604`/`ЮП-2616` часто вешают вместе: 29+29 или 30+30. Норма «на артикул» в такой завеске — 29/30, а не 58/62. Это не ошибка реестра, а другой режим. `ЮП-2603` в 2025 году шёл одиночными строками по 25 — там причина другая.
3. **Малые выборки.** `ЮП-2396` (8 записей), `ЮП-3263` (9), `2020` (19) — этого мало для уверенного вывода, несмотря на статус `confident`.
4. **КПЗ — факт, а не стандарт.** В данных есть ошибки операторов и разные схемы завески; `ambiguous`/`insufficient` — это честная пометка, а не пропуск.

### 4.2. Правило, которое даёт «почву»

Норму в реестре меняем только при **двух независимых подтверждениях**:

1. **Чертёж/периметр** даёт теоретическую N для конкретной длины;
2. **Норма КТМ/РП** для той же длины совпадает;
3. **КПЗ** даёт моду на той же длине, в одиночной завеске, с ≥ 20 наблюдениями.

Достаточно любых двух пунктов. Если КПЗ расходится с чертежом, но совпадает с нормой — это не повод менять чертёж, это повод проверить, не смешаны ли длины/парные завески. Если ни один пункт не подтверждается — оставляем как есть и пишем `needs_review`.

Для парных завесок сравниваем **сумму на подвесе**, а не норму на артикул: 29+29=58 или 30+30=60 — это нормальная завеска, а не ошибка.

### 4.3. Порядок действий

1. **Заполнить P/W** у `2020` и `1212` — без них теоретическую норму не посчитать.
2. **Разобрать 371/2256** — самый показательный узел: старая норма 75, чертёж 97, КПЗ 58/53, реестр 49/58. Здесь нужно выбрать источник истины.
3. **Проверить 137 и 2397** по чертежам/нормам: 137 — 427 записей, 2397 — 135, это уже не случайность.
4. **2603/2604/2616** — зафиксировать парную схему: в реестре хранить норму для одиночной завески и отдельно норму на пару.
5. **3263/2396/2878** — не трогать, пока не наберётся ≥ 20 записей.
6. **2910/2077** — оставить текущее издание, старые нормы не возвращать.
7. **`ЮП-3178`** — в БД есть SKU, но нет длин и атрибутов; заполнить, иначе он останется «есть, но пустой».

### 4.4. Что считать успехом

- у каждого изменения есть ссылка на чертёж/норму и выборка КПЗ;
- после правки реестр и КПЗ сходятся в пределах ±2 шт. на той же длине;
- парные завески не путаются с одиночными;
- «не знаем» остаётся явным `needs_review`, а не подменяется средней цифрой.
