# Нормы «изделий на подвес» из учёта КПЗ

Статистика фактических норм по листам «Подвесы» файлов «Учет КПЗ 2025.xlsm» и «Учет КПЗ 2026.xlsm».
Собрано 2026-11-05. Два слоя данных:

- **[`kpz-hanger-norms.csv`](kpz-hanger-norms.csv)** — raw-слой: 267 пар «префикс + код», как они записаны в файлах
  (нужен для трассировки: видно, из каких написаний собрана каждая строка).
- **[`kpz-hanger-norms-consolidated.csv`](kpz-hanger-norms-consolidated.csv)** — сводный слой: 222 строки по коду
  артикула, где `СРМ361` + `СРЛ361` + `361` — одна строка `361`.

**Главное:** колонка «На подвесе» в обоих файлах не заполнена ни в одной строке. Норма восстановлена
из фактических записей: в 100 % строк «Подвесы, шт» = 1, поэтому число изделий на подвесе равно
значению колонки «Ламели, шт» (эквивалентно «Ламели, шт» / «Подвесы, шт»). Подробности — раздел 2.

| | raw-варианты | сводные артикулы |
|---|---:|---:|
| Строк | **267** | **222** |
| Уникальных кодов без префикса | 166 | 166 |
| Валидных записей | **38 681** | **38 681** |
| `confident` | 171 | 146 |
| `probable` | 53 | 41 |
| `ambiguous` | 9 | 8 |
| `insufficient` | 34 | 27 |
| Найдено в прод-БД по SKU/алиасу | 158 из 267 | 171 из 222 |

Итого: **267 raw-вариантов = 166 уникальных кодов → 222 сводных артикулов**.
Сводных строк больше, чем кодов (222 > 166): 103 кода
встречаются только с продуктовым префиксом (`ЮП`, `АТ`, `ALS`, `У`, `МС`, `ПП`, `ПТ`, `КП`, `AN`, `АВД`)
и остаются отдельными строками — `4040`, `У4040` и `ЮП-4040` разные SKU. У базовой группы
63 кода дают 74 строки: 12 из них — операции
(`гребенка`, `окно`, `растрав`, `обезжиривание`). За счёт слияния `СРМ`/`СРЛ`/пустого префикса
число строк сократилось с 267 до 222, а найденных в БД стало больше на 13.

## 2. Почему норма производная

1. Колонка «На подвесе» есть в шапке обоих файлов, но **пуста**: 0 непустых ячеек на 81 358 строк данных.
2. Формул в ней тоже нет: во всём листе «Подвесы» найдена ровно одна формула — `SUBTOTAL` в колонке
   «Профиль» (строка 323 в 2026 и 38 513 в 2025). То есть значение не вычислялось и не сохранялось.
3. «Подвесы, шт» = **1 во всех 57 723 заполненных строках** (2025 — 38 973, 2026 — 18 750).
   Значит, одна строка = один подвес, и количество изделий на подвесе — это «Ламели, шт».
4. Формально норма = «Ламели, шт» / «Подвесы, шт»; деление на 1 ничего не меняет и оставлено
   в методике как страховка, если в будущих файлах появится «Подвесы, шт» > 1.

Проверки, что «Ламели, шт» — это именно штуки изделий, а не метры и не норма:

- Среди строк с числовыми «Ламели» и «Подвесы» (52 586) отношение «Ламели/Подвесы» целое в 52 584 случаях;
  два исключения — заведомо битые составные записи «ЮП-2616,2604» (Ламели 30,3) и «ЮП-011.2020» (15,52).
- Простые суммы вида `5+4`, `26+26`, `30+30` (997 строк при «Подвесы, шт» = 1 плюс 3 строки
  без «Подвесы») встречаются **только** при «Подвесы, шт» = 1 и разбираются как сумма: 5+4 → 9 изделий
  на одном подвесе. Формы через `/` (`26/26`, `50/6`) не разбирались — см. раздел 4.
- Мода по артикулу устойчива: у 88 из 267 raw-вариантов встретилось ровно одно значение нормы.

Норма — это **факт учёта**, а не технологический стандарт: в ней видны и разные схемы завески, и ошибки
операторов. Поэтому у части артикулов ниже честно написано «неоднозначно».

## 3. Нормализация артикула

Правила (применяются к сырому значению «Профиль» после сжатия пробелов и замены `–`/`—` на `-`):

1. `Профиль алюминиевый 314`, `профиль алюминевый 362`, `профиль аллюминевый 2525`, `Профиль 361` →
   код без префикса (`314`, `362`, `2525`, `361`).
2. Голое число из 2–5 цифр (`228`, `361`, `4040`, `033`, `87`) → код без префикса. Числа из одной
   цифры (`1`, `2`) как артикул **не** трактуются: это маркер/количество. Двузначные `31`, `33`, `35`
   оставлены отдельными кодами (в БД их нет; возможно, это размеры уплотнения, а не профили) —
   записей по ним 9–21, статусы `probable`/`confident`, но проверить их стоит отдельно.
3. `ПРЕФИКС + число` → артикул с префиксом. Сокращённый суффикс из 1–2 цифр сохраняется
   (`ЮП-2464-1` — отдельный артикул, он же есть в БД).
4. Регистр и латиница/кириллица в префиксе — варианты написания одного префикса (таблица ниже).
5. Отбрасываются описательные хвосты: `(Окно)`, `окно`, `(Греб)`, `гребенка`, `(Растрав)`,
   `(1.8)`, `2.5м`, `L 3,09`, `3 метра`, `(Обезжиривание)`.
6. `рейка AN-100` → артикул `AN-100`; `рейка 100х200`, `рейка 30x200` — размеры, не артикулы.

Слитые варианты написания (только доказанные гомоглифы/регистр):

| Канон | Что слито (примеры из файлов) |
|---|---|
| `ЮП` | `ЮП-3233`, `юп-1880`, `Юп-011`, `ЮП-3270 ` (хвостовой пробел) |
| `АТ` | `АТ-7314`, `AT-7262`, `ат-7262` |
| `ALS` | `ALS-1103`, `АLS-1103` (кириллическая А), `ALS 1103`, `als-798`, `ASL-1103` (перестановка букв) |
| `СРМ` | `СРМ361`, `СPМ361`, `CPМ 229`, `СPM324` |
| `СРЛ` | `СРЛ3584`, `СPЛ-664`, `CPЛ2525`, `срл 3414` |
| `МС` | `МС 1620`, `МС1620`, `МС-1620`, `MC-16-20` |
| `ПП`, `ПТ` | `ПП-50`, `пп-95`, `ПТ80`, `пт 40` |
| `У` | `У1515`, `Уг-3030`, `угл 2020`, `Угл2020` (уголок) |

`ASL-1103`/`ASL-917` слиты с `ALS`, потому что других артикулов с такими кодами нет ни в номенклатуре,
ни в прод-БД (в БД есть только `ALS-1103` и `ALS-917`); всего это 26 строк.

**Что намеренно не склеивалось** (разные артикулы или нет доказательства тождества):

- разные префиксы: `СРМ` ≠ `СРЛ` ≠ `ЮП` ≠ `АТ` ≠ `ALS` ≠ `МС` ≠ `ПП` ≠ `ПТ` ≠ `У`;
- `361` ≠ `СРМ361`, `228` ≠ `СРМ228`, `3177` ≠ `ЮП-3177` ≠ `АТ-3177`, `7314` ≠ `ЮП-7314` ≠ `АТ-7314`;
- `033` ≠ `33`, `035` ≠ `35` (ведущие нули не нормализовались);
- `МС-1620` ≠ `МС-16-20` (в БД есть только `МС16-20`);
- `ЮП-2464-1` ≠ `ЮП-2464-1-1` (последнее осталось в отброшенных, 24 строки).

Это правила **raw-слоя**: здесь `СРМ361`, `СРЛ361` и `361` — три строки, чтобы была видна
трассировка. В сводном слое (раздел 6) `СРМ`/`СРЛ`/пустой префикс объединяются в один код,
а продуктовые префиксы по-прежнему остаются отдельными строками.

Всего 153 артикула имели больше одного написания; полный список вариантов — в колонке `article_raw`
(там самое частое написание) и в `values_json` (там же видно распределение норм).

## 4. Что отброшено

Строка участвует в статистике, только если «Профиль» распознан как артикул и «Ламели, шт» — число > 0.
Разбор всех 54 320 непустых значений «Профиль»:

| Категория | Уникальных значений | Строк | Примеры |
|---|---:|---:|---|
| Артикул, валидная запись | — | **38 681** | `ЮП-3233`, `Профиль алюминиевый 314` |
| Артикул, но нет нормы | — | 64 | Подвесы пусто/0 — 62, Ламели не число — 2 |
| Составная запись (2+ артикула) | 289 | 1 109 | `ЮП-2616 + ЮП-2604`, `ЮП-3452/ЮП-3453`, `ЮП-3284/АТ-7314` |
| Размер/лист (не артикул) | 388 | 6 853 | `0.5x600x1000`, `1500х3000х2.0`, `рейка 100х200` |
| Описание, не артикул | 574 | 7 346 | `лист(уплотнение)`, `Урны`, `Накладка двери`, `портал левый типовой` |
| Пустой маркер | 5 | 267 | `Профиль`, `профиль`, `0` |
| **Итого** | **1929** | **54 320** | |

Почему составные записи не разложены по артикулам: в одной строке учтены два разных изделия на одном
подвесе (`ЮП-2616 + ЮП-2604`), и приписать всю норму каждому из них — значит завысить её вдвое.
Их 1 109 строк; самые частые — `ЮП-2616 + ЮП-2604` (151), `ЮП-3452/ЮП-3453` (82), `ЮП-2616-2604` (71).

Отдельно: формы `Ламели` через `/` (`26/26`, `50/6`, `14/25/38`) не разбирались — неясно, деление это,
две партии или «N из M». Это 142 строки; все они и так отброшены, потому что в «Профиль» там
составная запись или размер (135 и 7 строк соответственно).

## 6. Сводка по коду артикула

Второй слой — одна строка на код артикула. Машинная таблица:
[`kpz-hanger-norms-consolidated.csv`](kpz-hanger-norms-consolidated.csv), 222 строки.

### 6.1. Правила объединения

1. Пустой префикс, `СРМ` и `СРЛ` (включая гомоглифы `CPM`, `CPЛ`, `СPМ` и т.п.) — **один код**.
   `СРМ361` + `СРЛ361` + `361` → `361`; `СРМ228` + `228` → `228`.
2. Продуктовые префиксы (`У`, `ЮП`, `АТ`, `ALS`, `КП`, `МС`, `ПП`, `ПТ`, `AN`, `АВД`) **не сливаются**
   с голым кодом: `100`, `ПТ-100` и `AN-100` — разные SKU; `4040` и `У4040` — разные;
   `2525` и `У2525` — разные.
3. Операция (`гребенка`, `окно`, `растрав`, `обезжиривание`) внутри базовой группы выносится
   отдельной строкой с пометкой операции: `314` и `314 / гребенка`.
4. Если внутри базовой группы моды по префиксам расходятся (у префикса ≥ 5 записей), строка получает
   `conflict=true`, а в `conflict_detail` перечислены моды и объёмы. Доминирующая мода остаётся.
   Подгруппы меньше 5 записей в конфликте не учитываются, но видны в `conflict_detail`.

## 13. Ограничения

- «На подвесе» не заполняется операторами; норма восстановлена косвенно (раздел 2), а не прочитана из колонки.
- Норма — фактическая, а не технологическая: разные смены вешают по-разному, часть значений — ошибки ввода
  (например, у `ЮП-011` встречаются 2, 14, 15, 17 при моде 52).
- Год — это файл, а не дата записи (раздел 1).
- Артикул `AN-100` и ещё несколько кодов не сопоставлены с БД; возможно, в 1С они называются иначе.
- Коды без префикса и с префиксом не склеивались в raw-слое, поэтому `СРМ-361`, `СРЛ-3584`, `СРМ-228`
  там показаны как «нет в БД», хотя коды `361`, `3584`, `228` в БД есть. В сводном слое они находятся;
  raw-слой оставлен для трассировки.
- Двузначные `31`, `33`, `35` могут быть размерами уплотнения, а не профилями; у них 9–21 запись.
- В сводном слое операция (`гребенка`, `окно`, `растрав`, `обезжиривание`) вынесена отдельной
  строкой только внутри базовой группы (`пустой`/`СРМ`/`СРЛ`). У продуктовых префиксов операции
  остаются внутри строки: например, `ЮП-460` включает 339 записей «окно» и 50 «гребенка».
- Составные записи (1 109 строк) в статистику не вошли; формы `Ламели` через `/` (142 строки)
  целиком лежат внутри отброшенных категорий «составная» (135) и «размер» (7).
- Строки с «Профиль» пусто (27 038) — это в основном пустые строки листа и записи по клюшкам/оснастке;
  они не относятся ни к одному артикулу.

## 14. Как воспроизвести

1. Открыть оба `.xlsm` через `openpyxl.load_workbook(..., read_only=True, data_only=True)`.
2. Взять лист «Подвесы», шапку из строки 3, данные с 4-й.
3. Колонки искать по тексту: `Профиль`, `Ламели, шт`, `Подвесы, шт`, `Дата`.
4. Норма строки = `Ламели, шт` / `Подвесы, шт` (в текущих файлах делитель всегда 1).
5. Нормализовать артикул по правилам раздела 3, отбросить строки по разделу 4.
6. Мода — самое частое целое значение нормы; доля = частота моды / число валидных записей.
7. Статус — по порогам из раздела 5.

_Файлы-источники не изменялись; прод-БД только читалась (`select sku, name, aliases from products`)._
