# T-381 — Синк цветов и безразмерного заказа

Спека: `ekranchik-modern/docs/specs/0003-color-dictionary-and-third-party.md`.
Зависит от: T-378, T-380, 0022, 0023. Блокирует: T-382.

## Задача

Синк перестаёт переносить только артикулы. Он забирает операции анодирования
и кладёт их в локальный справочник цветов Экранчика по правилу «новее —
правильнее». Безразмерный сторонний заказ (`урны`) приезжает с нормой 8, а не
с пустой карточкой.

## Объём

### Чтение KTM

- Новый запрос цветов: операции участка `ANODIZING`, группа `ANODIZING`,
  `operation_type=production`:
  `operation_code`, `operation_name`, `icon_color`, `updated_at`.
- Старые `ANOD_01…08` и новые `C0…C54` попадают в один список.
- `PACK_STRETCH`/`PACK_SPUNBOND` не попадают: они лежат в участке
  анодирования, но в группе `PACK`.

### План расхождений

- Новый раздел `colors`:
  - нет строки по `operation_code` — создание;
  - есть, и `updated_at` KTM строго новее — обновление `name`, `hex`, `code`;
  - есть, и локальная метка новее или равна — пропуск с причиной;
  - локальные строки без пары в KTM — не удаление, не пометка.
- `code` для старых `ANOD_*` остаётся пустым; для новых равен
  `operation_code`.
- `--check` печатает расхождения цветов так же, как артикулов.
- Перед записью проверить, что таблица `colors` есть (миграция 003
  Экранчика); если нет — понятная ошибка до записи.

### Запись

- `--apply` пишет цвета до/после артикулов в одной транзакции на SQLite.
- Бэкап `ekranchik.db` уже делается; цвета попадают в него автоматически.
- Локальные строки не перезаписываются и не удаляются.
- Повторный `--check` после `--apply` чист.

### Безразмерный артикул

- `effective_n` для продукта без длин читает
  `attributes.quantity_per_hanger.default` (`manual` при
  `hanger_mode=manual`, иначе `auto`).
- Создание профиля `урны`: `name=урны`, `description` из KTM,
  `length=NULL`, `quantity_per_hanger=8`.
- Для обычных артикулов правило по длине не меняется.
- `--prune-orphans` по-прежнему удаляет только по явной команде; цвета он не
  трогает.

### Тесты

- Цвета: новый код создаётся; изменённое название обновляется; локальная
  правка новее — остаётся; KTM новее — перекрывает; равное время — локальная.
- Локальный `RG` без пары в KTM переживает `--apply`.
- `урны`: профиль создаётся с `length=NULL`, `quantity_per_hanger=8`.
- Обычный артикул с длиной считает норму как раньше.
- `--check` на копии БД показывает только ожидаемые расхождения; `--apply`
  их устраняет; повторный `--check` чист.

## Приёмка

1. В Экранчике появляются `C0…C54` после синка.
2. Локальная правка цвета не теряется, если она новее.
3. Строка `урны` появляется в каталоге с нормой 8 и без длины.
4. Старые артикулы и их нормы не изменились.
5. `npm run verify:ekranchik` и `npm run sync:ekranchik` отрабатывают без
   трассировок.
