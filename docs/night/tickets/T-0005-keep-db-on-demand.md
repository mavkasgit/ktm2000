# T-0005 — На провале нечего смотреть: launcher всегда дропает run-DB

- **Категория:** диагностика падений
- **Статус:** DONE (коммит `362c795`)
- **Дата:** 2026-10-01, цикл 1
- **Файлы (тестовая зона):** `scripts/test-run.ps1`, `docs/testing-guide.md`

## Проблема и доказательство

`scripts/test-run.ps1` в `finally` (строки ~131-140) безусловно выполняет
`python scripts/test-db.py drop $TestDbName`. Флага «оставить БД» нет: в
разборе режимов (`--full`, `--mon`, `--lf`) его тоже нет.

Следствие: после падения теста посмотреть, **что именно осталось в БД**, нельзя —
ни таблиц, ни строк, ни состояния схемы `t_<uuid8>`. Схема на модуль не
дропается (`backend/tests/AGENTS.md`), то есть в момент падения все данные ещё
в БД, но launcher их стирает сразу после прогона. При этом осиротевшую БД без
owner-строки потом нельзя удалить даже руками (`test-db.py drop` печатает
`Skip drop …: no matching owner row`).

## План изменений

1. `scripts/test-run.ps1`: новый флаг `--keep-db`.
   - вычесть его из списка аргументов, которые уезжают в pytest (рядом с
     `--full`, `--mon`, `--lf`);
   - в `finally`: при `--keep-db` не дропать БД, а напечатать имя БД, готовый
     `TEST_DATABASE_URL` и команду уборки (`python scripts/test-db.py drop <db>`);
   - поведение по умолчанию не меняется (дроп как сейчас).
2. `docs/testing-guide.md`: строка в таблице npm-скриптов/флагов о `--keep-db`
   (одно-два предложения, без переписывания документа).

## Граница: что НЕ будет затронуто

- Продуктовый код, `conftest.py`, правила изоляции (run-DB, схема на модуль) —
  не меняются.
- `python scripts/test-db.py` — не меняется (owner-строка уже пишется, `drop`
  по имени работает).
- Поведение без флага — идентично прежнему (проверяется тестом-регрессом).

## Критерии готовности (измеримые)

1. `npm run test:pytest -- --keep-db -k <выборка>` → после завершения БД
   `ktm2000_test_<runid>` **существует** (`select datname from pg_database`);
   имя и команда уборки напечатаны в выводе; код возврата совпадает с кодом
   pytest (флаг не влияет на результат).
2. Без флага: та же выборка → БД **отсутствует** после прогона (прежнее
   поведение сохранено).
3. `python scripts/test-db.py drop <оставленная БД>` → удаляет её (owner-строка
   есть, `no matching owner row` не появляется).
4. Полный прогон без флага: `passed`/`failed` не меняются (1941 passed,
   1 pre-existing failed до T-0004).
