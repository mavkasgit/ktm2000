# T-0006 — Прогон идёт «в чёрном ящике»: вывод pytest виден только в конце

- **Категория:** диагностика / удобство запуска
- **Статус:** PLANNED
- **Дата:** 2026-10-01, цикл 1
- **Файл (тестовая зона):** `scripts/test-run.ps1`

## Проблема и доказательство

`scripts/test-run.ps1` (строки ~104-121) захватывает вывод целиком:

```powershell
$PytestOutput = & python -m pytest -n $NumWorkers @PytestArgs 2>&1
...
$PytestOutput | ForEach-Object { Write-Host $_ }
```

Следствия:

1. Во время прогона (медиана **350s** по baseline) на экране нет ничего, кроме
   шапки `[5/6] Running pytest...` — ни прогресса, ни текущего теста, ни первой
   ошибки. По логам ночи это ровно так: в `logs/baseline-run*.log` после шапки
   сразу идёт итог.
2. При зависании/ошибке инфраструктуры непонятно, на чём прогон встал: вывод
   появится только после выхода процесса.
3. Захват нужен ровно для одного — детекта падения воркеров xdist по
   регулярке `node down|maximum crashed workers`. Эту проверку можно делать
   по сохранённому потоку, не теряя живой вывод.

## План изменений

1. В `scripts/test-run.ps1` заменить захват на потоковую передачу с
   одновременной записью в файл (Tee-Object), сохранив:
   - код возврата pytest (`$LASTEXITCODE` после пайплайна);
   - детект `node down|maximum crashed workers` по записанному файлу
     (сейчас — по `$PytestOutput`);
   - путь к файлу прогона печатать в шапке (например
     `<repo>/logs/pytest-<runid>.log`), чтобы по завершении было что открыть.
2. `docs/testing-guide.md` — одна строка: где лежит лог прогона.

## Граница: что НЕ будет затронуто

- Состав тестов, флаги pytest, изоляция БД, семантика `-n`/`PYTEST_NUM_WORKERS`
  — не меняются.
- Логика «воркеры упали → код 2» сохраняется (проверяется тестом-регрессом).
- Продуктовый код и сами тесты — не трогаются.

## Критерии готовности (измеримые)

1. Прогон выборки (`npm run test:pytest -- tests/test_e2e_stand.py`) печатает
   строки pytest **по ходу** (проверка: во время прогона в выводе появляется
   `[5/6] Running pytest...`, затем строки прогресса/`PASSED` до завершения).
2. Код возврата сохраняется: успешный прогон → 0, прогон с падением → 1
   (проверяется подстановкой `-k` на заведомо падающий/несуществующий набор и
   на успешный).
3. Файл лога прогона создаётся и содержит тот же текст, что виден на экране.
4. Полный прогон: результат идентичен (после T-0004 — `1945 passed, 0 failed`).

## План отката

`git revert <commit>` — изменение в одном скрипте (+ строка документации).

## Риск

PowerShell и пайплайны: `$LASTEXITCODE` после пайплайна отражает последний
нативный процесс, но при `Tee-Object` надо убедиться, что это именно pytest, а
не Tee. Проверяется обоими случаями (0 и 1) — без этого тикет не закрывается.
