# T-0003 — Подобрать режим распределения xdist по замерам

- **Категория:** скорость (параллелизация)
- **Статус:** DONE — выигрыш подтверждён (см. «Замеры A/B» ниже)
- **Дата:** 2026-10-01, цикл 1
- **Файл (тестовая зона):** `scripts/test-run.ps1`
- **Связь:** B-0008

Артефакты: `logs/dist-loadfile-1..3.log`, `logs/dist-load-1..3.log`,
`logs/verify-T0003.log`.

## Проблема и доказательство

`scripts/test-run.ps1` запускает `python -m pytest -n <N>` **без** `--dist`,
то есть работает дефолт `--dist load` — тесты распределяются по одному,
и тесты одного модуля попадают на разные воркеры. При этом изоляция сделана
**схемой на модуль на воркер** (`backend/tests/AGENTS.md`: «одна схема
`t_<uuid8>` на модуль, `Base.metadata.create_all()` при старте модуля») —
значит, `create_all()` для одного модуля выполняется столько раз, на скольких
воркерах этот модуль оказался.

Суммы по `--durations=0` (baseline №1, `logs/baseline-run1.log`):

| Фаза | Сумма | Замеров |
|---|---|---|
| call | 681.4s | 1391 |
| **setup** | **339.9s** | 1395 |
| teardown | 17.5s | 1389 |

Setup — треть измеренного времени. Гипотеза: часть его — дублирующееся
создание схемы, и `--dist loadfile` (модуль целиком одному воркеру) её уберёт.

## План изменений

1. Прогнать 3 полных прогона с `--dist loadfile` (флаг — в `scripts/test-run.ps1`
   через переменную окружения или прямо в команде, чтобы не коммитить
   непроверенное).
2. Сравнить с серией baseline (`load`, 5 прогонов из `logs/flaky-*.log`):
   - wall time (медиана и разброс);
   - сумму `setup` из `--durations=0`;
   - `passed`/`failed`/`warnings` — должны совпасть;
   - список самых долгих тестов — тот же.
3. Если медиана wall time улучшилась **≥10%** при неизменных результатах —
   закоммитить `--dist loadfile` в `scripts/test-run.ps1`; иначе тикет
   **REJECTED** с числами (гипотеза не подтвердилась).
4. При коммите — одна строка в `docs/testing-guide.md`/`backend/tests/AGENTS.md`
   о выбранном режиме (не переписывая документы).

## Граница: что НЕ будет затронуто

- Продуктовый код, тесты, `conftest.py` — не меняются.
- `-n auto`/`PYTEST_NUM_WORKERS` семантика сохраняется (меняется только способ
  раскладки тестов по воркерам).
- Ни один тест не исключается и не скипается: `--dist` не влияет на состав
  набора.

## Критерии готовности (измеримые)

1. 3 прогона с `--dist loadfile`: `failed`/`passed` идентичны baseline
   (1941 passed + 1 pre-existing failure), `warnings` — 45.
2. Медиана wall time ≥10% лучше, чем медиана серии `load` (357.3s), иначе —
   REJECTED.
3. Сумма `setup` из `--durations=0` — в отчёте (до/после).
4. Диффа — только `scripts/test-run.ps1` (+ строка документации).

## Известный риск

Самый тяжёлый файл — `test_packing_plan_demo_seeder.py` (204s из 384s):
`loadfile` посадит его целиком на один воркер, остальные могут простаивать.
Поэтому решение принимается по медиане трёх прогонов, а не по одному.
