То есть эндпоинт **был сознательно удалён** при переходе на `StockTransaction`;

Современный аналог — `TRANSFER_RECEIVE`/`FINAL_RELEASE` в ledger и остатки
`StockBalance`, но «как именно consume должен писать проводки, у кого есть доступ
(роль), что делать с `idempotency_key` и габаритами» в репозитории не описано.

## Почему не решил сам

Вариант «добавить адресата» = завести новый публичный API и выбрать его
ledger-семантику. Это продуктовое решение (какой тип `StockTransaction`, какие
роли, совместимость с удалённым `remainder_id`), а не механическая чистка.
Вариант «удалить DTO» в условии тикета не предусмотрен и также меняет публичный
контракт модуля. Ни того, ни другого без владельца не делаю: тикет остаётся
BLOCKED_NEEDS_HUMAN.

Для решения владельца: в репозитории есть канон удаления мёртвых DTO
(`backend/tests/test_architecture.py::test_transfer_dead_dtos_removed`); если
владелец выберет этот путь, механическая часть — удалить класс из
`shopfloor.py` и добавить его в список сторожа — отдельная правка без
продуктовой семантики. В этом срезе она не выполнялась.
