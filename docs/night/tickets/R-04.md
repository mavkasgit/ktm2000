### 2. `fix(e2e)`: отобранный слот/лок сносился прежним держателем (#281) — `638022b`

**Дефект.** `releaseSlot` и `releaseLock` удаляли файл безусловно
(`fs.rmSync(file, { force: true })`). Слот семафора и лок дерева отбираются у
**живого** держателя по возрасту (`staleMs`); новый прогон занимает тот же файл.
Прежний прогон, завершившись, звал `releaseSlot`/`releaseLock` — и сносил лок
**из-под работающего соседа**. Семафор переставал считать: следующий прогон
занимал слот уже работающего.

Это прямое противоречие AC #281: «превышение — ожидание с логом, а не старт
поверх чужого прогона». Механизм живёт и сейчас (`run-slots.mjs`, `run-tier.mjs`),
поэтому находка не косметическая.

**Доказательство «до»** (пробники `docs/night/logs/r04-slot-release-probe.mjs`,
`r04-lock-release-probe.mjs`, реальный код модулей, без моков):

```
A занял слот 0 111
слот 0: держатель (pid 111, 41 мин) просрочен, но жив — снимаю без уборки
B занял слот 0 pid в файле: 222
после releaseSlot(A) файл слота существует: false
C занял слот: 0 — одновременно с B: true          ← семафор перестал считать

reclaimReason: держатель (pid 111, ярус ui-e2e) держит лок 41 мин (> 40) — снимаю | dead: false
после release(A) лок существует: false
C занимает лок, пока B ещё работает: true          ← лок дерева снесён под работающим
```

Тесты на этом коде красные — `vitest`: `releaseSlot не сносит слот, уже отобранный
соседу по возрасту` (`expected false to be true`), `releaseLock чужого лока не
сносит` — **2 failed | 24 passed**.

**Правка.** Отпускает ресурс только владелец: `releaseSlot` сверяет `pid` держателя
своим, `releaseLock` — `runId` прогона (`runId`, а не `pid`: у каждого прогона
свой, а pid после перезапуска машины может совпасть). В `run-tier.mjs` вызов
`release()` из `finalize()` передаёт `runId`; принудительное снятие в цикле
`acquire()` оставлено как было — там лок отобран по `reason` и следующая
итерация займёт файл заново.

**Доказательство «после»**: `vitest run e2e/run-lock.test.ts e2e/run-slots.test.ts` —
**26 passed**; те же пробники дают `после releaseSlot(A) слот B на месте: true` и
`C стартовал поверх работающего B: false`; для лока — `после release(A) лок
существует: true`, `C занимает лок, пока B ещё работает: false`.
`npx tsc --noEmit` чисто.
