# T-379 — Правило цвета: коды веера находят операцию

Спека: `ekranchik-modern/docs/specs/0003-color-dictionary-and-third-party.md`.
Зависит от: T-378. Блокирует: T-381.

## Задача

План может указать цвет кодом (`C31`, `С31`, `S120-0`) или названием
(«светлая шампань», «тёмная медь»). Правило `anod_colors` должно находить
соответствующую операцию участка `ANODIZING` и не ломать старые названия.

## Объём

### Правило

В `anod_colors` (фаза `resolve_operations`) добавить ключи:

- коды веера: `C0`, `C35`, `S120-0`, `S120-2`, `C31`, `C32`, `C33`, `C34`,
  `C41`, `C44`, `C51`, `C54`;
- кириллические варианты: `С0`, `С31`, `С32`, `С33`, `С41`, `С44`, `С51`,
  `С54`;
- названия: «старое золото», «светлая шампань», «тёмная шампань», «светлая
  бронза», «тёмная бронза», «тёмная медь», «нержавеющая сталь», «тёмный
  титан».

Порядок важен: составные названия (`светлая шампань`, `тёмная шампань`) стоят
раньше общего `шампань`, иначе старое правило перехватит их первым. Старые
ключи (`анодсеребро`, `серебр`, `шампань`, …) остаются на месте и ведут к
старым `ANOD_0x`.

### Извлечение цвета

- Если цвет приходит из наименования, `COLOR_TOKENS` дополняется токенами
  `анод.с31`, `анодс31`, `анод.с32`, `анодс32` и т.п., если это нужно для
  реальных имён заказов. Коды в колонке «Цвет» обрабатываются правилом
  `anod_colors`, а не токенами.
- Составное значение через `/` по-прежнему разбирается по последнему сегменту.

### Тесты

- Строка с `color=C31` → операция `C31`; `С31` → `C31`.
- Строка с `color=светлая шампань` → `C31`; `тёмная шампань` → `C32`.
- Строка с `color=шампань` → старая `ANOD_06`, не `C31`.
- Строка с `color=серебро` → старая `ANOD_01`.
- `S120-0` и `S120-2` не путаются.
- `C34`, `C44`, `C51`, `C54` находятся.
- Старые тесты `test_xls_route_selection.py` остаются зелёными.

## Приёмка

1. План с кодом `C31` получает операцию `C31` в маршруте.
2. План со словом `шампань` продолжает получать `ANOD_06`.
3. Новые и старые цвета не перекрёстно перехватываются.
4. Тесты правил и выбора маршрута зелёные.
