# T-20261123-A-N07 — мёртвая защита в горячем цикле `overview`

Срез A, ветка `night/2026-11-23-a`. **STATUS: REJECTED** (выигрыш не воспроизведён; код не изменён).

## Гипотеза и почему она отклонена

В `production_planning.py:757-762` (вызов bulka на `:711`) стоит
`if wt_cache is None: raise RuntimeError("task … missing from bulk task cache")`.
`get_tasks_cache_bulk` (`stock/services.py:568`) действительно всегда кладёт
запись для каждого id: на 342 задачах за 12 прогонов счётчик срабатываний
защиты — **0**. Вызов на `:2383` (`_group_work_tasks`) использует
`tasks_cache_bulk.get(wt.id, {})` — там защиты нет.

Но удаление guard'а **не даёт измеримого выигрыша**: это одна невыполняемая
ветка на задачу, SQL она не меняет вовсе, а разница wall time между сериями
меняет знак. Оптимизацию «ради галочки» не делаю.

## Методика

Временная инструментация в `production_planning.py` (переменные
`N07_GUARD_ENABLED` / `N07_GUARD_HITS`, переключаемые пробником) позволяла
чередовать A (guard на месте) и B (guard удалён) **в одном процессе на одной
БД и тех же данных**. Временный пробник и инструментация удалены;
`production_planning.py` побайтово равен HEAD (в `git diff` не значится).

- Счёт SQL: `SqlRecorder` (SELECT и writes раздельно).
- Ответ: полный JSON `get_production_planning_overview`, SHA-256 по байтам UTF-8.
- Непустота: 6 секций, 342 позиции, 342 задачи, 205 082 байт JSON.
- Чередование: `ABABAB`, затем `BABABA`, по одному разогреву перед каждой серией.

## Результаты

| Серия | A: SQL / writes | B: SQL / writes | A: медиана wall | B: медиана wall | guard hits | SHA |
|---|---|---|---|---|---|---|
| ABABAB | 25 / 0 | 25 / 0 | 342.414 мс | 313.192 мс | 0 | `b13f1315…8eec2` |
| BABABA | 25 / 0 | 25 / 0 | 318.714 мс | 381.140 мс | 0 | `b13f1315…8eec2` |

SHA полного JSON (одинаковый во всех 12 прогонах):
`b13f131505fcc9a8d08ab75211826b387a3113b3a9af3ad1ab2cb67f0078eec2`.

**Решение:** SQL 25 → 25, writes 0 → 0, ответ побайтово тот же; разница времени
в первой серии (−8.5%) опровергнута второй (+19.6%) — это шум машины. Медианы
по двум сериям: A ≈ 330.6 мс, B ≈ 347.2 мс, то есть выигрыша нет. Guard
действительно мёртвый, но удаление ничего не ускоряет. Рекомендация владельцу
B-N07: закрыть как «не требует исправления» либо удалить в рамках косметического
рефакторинга без притязаний на perf.
