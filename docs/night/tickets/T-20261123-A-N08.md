# T-20261123-A-N08 — маршруты грузятся дважды

Срез A, ветка `night/2026-11-23-a`. **STATUS: DONE**.

## Что исправлено

`load_position_route_batch_cache` читал все `production_routes` (вместе с
`selectin` по `route_stages`/`route_operations`) и `import_batches`, после чего
`load_route_selection_batch_cache` читал активные маршруты и батч импорта
второй раз. Теперь:

- `load_route_selection_batch_cache` принимает keyword-only `routes` — уже
  прочитанный снимок всех маршрутов; активные выбираются в Python с сохранением
  порядка `sort_order, id`. Без аргумента поведение прежнее (вызовы
  `plan_import_service.py:815`, `route_batch_cache_163`, `route_transit_stages_178`
  не тронуты).
- `load_position_route_batch_cache` принимает keyword-only
  `import_batches_by_id`; отсутствующие id догружаются одним SELECT.
- `resolve_position_routes_batch` пробрасывает этот словарь, а
  `list_import_positions` (`imports.py:595`) передаёт уже прочитанный `batch`.

Удалены ровно 4 дублирующих SELECT: `production_routes`, `route_stages`
(selectin), `route_operations` (selectin), `import_batches`.

## Методика (PLAYBOOK §3.2/§10.5)

- Счётчик — `backend/tests/helpers/sql_counter.py::SqlRecorder` на engine;
  SELECT считаются отдельно от `writes`.
- A — копия «до»-загрузчиков, встроенная во временный пробник; B — код после
  правки. Оба режима вызывают **настоящую ручку** `list_import_positions` на
  одной и той же dev-БД `127.0.0.1:5440/ktm2000_prod`, батч 6, 108 позиций,
  каждая сессия откатывается. Пробник удалён после замера.
- Ответ — полный JSON ручки (Pydantic → JSON, `sort_keys=True`),
  SHA-256 по байтам UTF-8. Проверка непустоты: 108 позиций → 108 строк ответа,
  68 690 байт.
- Чередование A/B/A/B, 3+3, с одним разогревочным прогоном вне медиан.
