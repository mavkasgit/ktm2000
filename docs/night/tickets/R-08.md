## Находки

### Сложная (исправлена) — #293: карта батча стала шире гейта выдачи

`queries_sections.py` после `a96e5e54`:

```python
transform_task_ids = [
    row[0].id for row in rows
    if (row[0].outputs or [])
    and (row[2].transforms_dimensions or row[0].input_quantity is not None)
]
```

Комментарий в коде и в комментарии тикета утверждает: «Набор для выбора не
изменился: гейт ниже по-прежнему требует `transforms_dimensions`». Это верно
про *набор для карточек*, но не про сам гейт. Гейт выдачи остался прежним:

```python
if task.id in transform_progress_map or (stage.transforms_dimensions and task_outputs):
```

`transform_progress_map` — это словарь **по заданиям с движениями в ledger**
(`get_transform_progress_bulk` возвращает `{*consumed, *scrapped, *produced}`),
а множество `transform_task_ids` после правки шире прежнего: в него попадают
задания с `input_quantity` **без** `transforms_dimensions`. Такое задание
возникает, когда маркер этапа сняли после создания задания (маркер выводится из
справочника операций участка и пересчитывается при правке маршрута, а
`input_quantity`/`outputs` в задании остаются).

Итог: такое задание получает `outputs_progress` и `input_consumed_quantity`
там, где до правки получал `null`. Это прямое нарушение AC #293
«Ответ доски не изменился: те же задачи/статусы/прогресс».

**Доказательство (до правки).** Пробный тест на не-трансформирующем этапе с
заданием, у которого `input_quantity` + `outputs` сохранены, и с движением
`TRANSFORM_CONSUME`:

```
assert [{'row_number': None, 'dimensions': None, 'quantity': '0', ...}] is None
1 failed
```

**Правка** (`0242e905`): гейт явно требует маркер этапа, прогресс по-прежнему
берётся из той же карты:

```python
if stage.transforms_dimensions and (task.id in transform_progress_map or task_outputs):
```

**Охранник** `test_board_hides_output_card_on_non_transform_stage` в
`tests/test_section_board_batching_293.py`. Проверен на коде без правки:
падает и печатает непустую карточку выходов; с правкой — 5 passed.

Почему сложная, а не лёгкая: это меняет выдачу доски на живых данных, и
ошибочная версия правки (например, «вернуть гейт к `transforms_dimensions` и
выкинуть из карты всё, что не маркер») тихо сломала бы синхронизацию
статусов — она требует прогресса именно по широкому набору. Отсюда и
расширение множества id в исходном коммите: оно нужно, ошибка была только в
гейте.

## Оси Standards — пройдено

Запахи из базового списка просмотрены по всем девяти коммитам среза;
кроме дубля в `_rule_out` (исправлен) находок нет:

* **Mysterious Name** — нет. Имена новых сущностей говорящие:
  `RuleOutPrefetch`, `_load_rule_out_prefetch`, `pair_length_candidates_bulk`,
  `_length_candidates_from_rows`.
* **Duplicated Code** — `_rule_out` (исправлено). `_length_candidates_from_rows`
  выделен именно чтобы убрать дублирование с `pair_length_candidates` —
  правильное решение, отмечено.
* **Feature Envy** — нет. `sync_work_task_status`/`sync_work_tasks_status_bulk`
  обращаются к `task.input_quantity`/`task.outputs` — это их собственный
  домен (статусы заданий), не вынос логики наружу.
* **Data Clumps / Primitive Obsession** — новых нет. `(product_a, product_b)`
  внутри `ResolvedPair` — доменная пара, не клэмп.
* **Repeated Switches** — нет. Перечисление причин ledger
  (`TRANSFORM_CONSUME/COMPLETE/SCRAP`) осталось в одной функции
  `get_transform_progress_bulk` и не дублировалось в новом коде.
* **Shotgun Surgery / Divergent Change** — нет.
* **Speculative Generality** — `_rule_out(prefetch=None)` (исправлено).
* **Message Chains** — нет. `RouteStage → operations → operation_code` в
  батчевой ветке не появилось: `stages_by_id` грузится с `selectinload`.
* **Middle Man** — нет.
* **Refused Bequest** — нет.

`backend/AGENTS.md`, `backend/tests/AGENTS.md` — соблюдены:

* правило «`db.get` по уже загруженной строке не ходит в БД» — автор
  #294 применил его как основание для отката места 2 (`product-wip-stats`),
  это ровно то, чего требует документ;
* `AsyncSession` везде, локальные импорты моделей в `shopfloor.py`
  сохранены (паттерн файла);
* тесты: динамические ID, фикстуры читают `product.id`/`task.id` из объектов,
