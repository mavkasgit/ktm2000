# T-0018 — Документация не знала о ручном CI, storage-изоляции и TEST_PYTHON

- **Категория:** документация по тестированию
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 5
- **Файлы:** `docs/testing-guide.md`, `backend/tests/AGENTS.md`

## Проблема и доказательство

Ночью в тестовой инфраструктуре появились три вещи, которых нет в
документации, — а документация здесь единственный вход для человека:

1. `.github/workflows/backend-tests.yml` (ручной CI-джоб, `T-0015`) — о нём не
   знает ни `docs/testing-guide.md`, ни канон; в разделе про тесты нет даже
   упоминания, что набор вообще не гоняется в push/PR.
2. Storage-каталог тестов стал **своим на прогон** и убирается (`T-0014`), но
   канон `backend/tests/AGENTS.md` этого не описывает — при следующем разборе
   «почему тесты видят чужие файлы» искать придётся в `conftest.py`.
3. `TEST_PYTHON` (`T-0017`) — новая переменная launcher'а; канон описывает
   `PYTEST_NUM_WORKERS`, но не её.

## План изменений

1. `docs/testing-guide.md`: новый короткий раздел «CI» — что авто-запускается
   (`migrations.yml`), что полный набор в push/PR не запускается (решение
   человека) и что ручной джоб существует + набор проверен на Linux.
2. `backend/tests/AGENTS.md`:
   - подраздел «Storage-каталог тестов» (свой на прогон, удаляется);
   - абзац про `TEST_PYTHON` рядом с `PYTEST_NUM_WORKERS`.

## Граница: что НЕ затронуто

- Продуктовый код, тесты, скрипты, конфиги — не менялись: только текст
  документации рядом с тестами.
- Ни одно утверждение о поведении не изменено — добавлены только описания
  фактического состояния (каждое подтверждено замером или проверкой этой ночи).
- Ничего не удалено из документации.

## Критерии готовности (измеримые)

1. Все три факта описаны в документации (`grep` по названиям: `backend-tests.yml`,
   `ktm2000_pytest_storage`, `TEST_PYTHON`).
2. Утверждения совпадают с фактами: имя каталога и переменной — из
   `conftest.py`/`test-run.ps1`, результат Linux-прогона — из `logs/linux-run.log`.
3. Полный прогон не затрагивается (документация не влияет на тесты).

`git revert <commit>` (правка текста в двух документах).
