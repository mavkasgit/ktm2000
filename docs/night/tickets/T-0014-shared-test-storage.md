# T-0014 — Storage-каталог тестов общий для всех прогонов и не убирается

- **Категория:** изоляция и детерминизм
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 4
- **Файл (тестовая зона):** `backend/tests/conftest.py`

## Проблема и доказательство

`backend/tests/conftest.py:20` задавал **один и тот же** каталог для всех
прогонов:

```python
_TEST_STORAGE_ROOT = os.path.join(tempfile.gettempdir(), "ktm2000_pytest_storage")
os.environ["STORAGE_ROOT"] = _TEST_STORAGE_ROOT
```

Следствия:

1. **Общий ресурс между прогонами.** Параллельные прогоны (несколько агентов,
  два стенда) пишут в один каталог: совпадающие имена файлов (например
  `backup_ktm2000_test_2026-01-01_10-00-00.zip` из тестов бэкапов) могут
  подменять друг другу вход и делать прогон недетерминированным.
2. **Мусор копится.** Каталог никто не удалял: замер `du -sh` —
  **25 МБ** накопленных файлов в `%TEMP%\ktm2000_pytest_storage`.

Проверено: сам каталог действительно общий (`ls` до/после прогонов — один и тот
же путь), а в `tests/` нет ни одной ссылки на него как на путь (значение
приходит только через `settings.STORAGE_ROOT`), то есть менять имя безопасно.

## План изменений

1. Каталог делается уникальным на прогон: суффикс из `TEST_RUN_ID` (его даёт
   launcher) либо случайного `uuid4().hex[:8]` в ручном режиме:
   `ktm2000_pytest_storage_<tag>`.
2. Новая session-scoped autouse-фикстура `_clean_test_storage` удаляет каталог
   после прогона (`shutil.rmtree(..., ignore_errors=True)` — best-effort, на
   Windows открытые файлы могут не удалиться, и это не должно ронять прогон).

## Граница: что НЕ затронуто

- Продуктовый код, `pytest.ini`, launcher, тесты — не менялись (кроме conftest).
- Правило «тесты пишут только во временный каталог» (ADR-0026) сохраняется:
  путь по-прежнему под `%TEMP%`, просто свой у каждого прогона.
- Легаси-каталог `%TEMP%\ktm2000_pytest_storage` (25 МБ) **не удалялся** — это
  чужой мусор; в отчёте указано, как его убрать руками.

## Критерии готовности (измеримые)

1. Во время полного прогона в `%TEMP%` есть каталог с суффиксом `TEST_RUN_ID`
   этого прогона; после прогона его нет (проверяется `ls` до/во время/после).
2. Полный прогон: `1951 passed, 0 failed, 43 warnings` — без регрессий.
3. Повторный прогон не находит каталог предыдущего (нет накопления).
4. Диффа — один файл (`backend/tests/conftest.py`).
