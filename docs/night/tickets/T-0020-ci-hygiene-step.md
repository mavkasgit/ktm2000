# T-0020 — Ручной CI-джоб не показывал отчёт по гигиене тестов

- **Категория:** CI-эффективность / чистота тестовой зоны
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 6
- **Файл:** `.github/workflows/backend-tests.yml`
- **Связь:** `T-0012` (чекер), `T-0015` (сам джоб)

## Проблема и доказательство

`T-0012` добавил report-only проверку мёртвых импортов (`npm run test:hygiene`),
но она запускается только вручную на машине разработчика: линтера в репозитории
нет, а ручной CI-джоб (`T-0015`) прогонял только тесты. То есть отчёт не
появлялся нигде автоматически — включая тот единственный сценарий, где его
удобно смотреть (лог джоба).

## План изменений

В `.github/workflows/backend-tests.yml` добавлен шаг

```yaml
      - name: Test hygiene report (report-only)
        run: python scripts/check-test-imports.py
```

Скрипт по устройству возвращает 0 (в блокирующий режим переводится `--strict`),
поэтому шаг не роняет джоб, а печатает находки в лог.

## Граница: что НЕ затронуто

- Тесты, продуктовый код, `conftest.py`, launcher — не менялись.
- Джоб по-прежнему только `workflow_dispatch` (в push/PR не включён — решение
  человека, B-0001).
- Блокирующего режима нет: `--strict` не используется.

## Критерии готовности (измеримые)

1. YAML валиден; шаги джоба: Checkout → Setup Python → Install backend
   dependencies → Run backend test suite → **Test hygiene report (report-only)**.
2. Локально `python scripts/check-test-imports.py` из корня: печатает отчёт
   (1 находка — файл из denylist) и завершается кодом **0**.
3. Прогон тестов не затронут (шаг независим от pytest).

## План отката

`git revert <commit>` (удаление четырёх строк из workflow).
