# T-384 — Ретро среды агента: локальные правила, гейт и шум тестов

Источник: ретро сессии 2026-11-19. Решения приняты владельцем; агент
исполняет, а не пересматривает.

## Объём

### 1. Правило прототипов UI — только локально

В `frontend/AGENTS.md` добавить правило:

- перед макетом/прототипом UI открыть реальный экран и прочитать реальный
  компонент;
- для модалки воспроизводить её фактическую структуру (фото 320 px, поля в
  три колонки, блок размерности/нормы, пары, примечания, футер), а не
  выдуманную панель.

**Не трогать** глобальный `~/.agents/skills/prototype`: пользователь обновляет
его извне, локальные пометки там потеряются.

### 2. Гейт не должен зависеть от `python` в PATH

Проблема: `npm run gate` из KTM в смешанной сессии взял `python 3.12.10` из
venv соседнего проекта, и `pins` + `backend-test-count` упали, хотя venv KTM
на 3.14.

Сделать так, чтобы python-шаги гейта использовали `backend/.venv` проекта
явно (резолвер пути, как `scripts/run-python.js` в ekranchik-modern), а не
первый `python` из PATH. Проверить `scripts/gate.mjs`, `scripts/test-count.js`
и остальные места, где гейт зовёт `python`.

Приёмка: гейт проходит, даже если в PATH первым стоит чужой `python`
(воспроизвести подменой PATH в тесте/ручной проверке; если тест на это
дорог — зафиксировать ручную проверку в PR).

### 3. Break-glass вход dev KTM — в `AGENTS.md`

В раздел про dev-стенд добавить указатель:

- раздел не открылся / редирект на `/login` → dev использует аварийный вход;
- креды — `BREAK_GLASS_USER` / `BREAK_GLASS_PASSWORD` в `.env.dev`, пароль в
  документации не дублировать.

### 4. `registry` должен ловить обновления actions

Проблема: dependabot обновил SHA actions в workflow, но не
`tools.json`/`docs/toolchain.md`; `main` был красным по шагу `registry`.

Добавить/включить проверку так, чтобы PR, меняющий action-SHA в
`.github/workflows/**`, но не обновляющий `tools.json`, падал в CI. Не
дублировать существующий шаг `registry`; использовать
`npm run check:registry`. Если для этого нужны настройки branch protection
вне репозитория — описать в PR, не менять настройки репозитория самовольно.

### 5. Убрать сетевой шум из полного frontend-прогона

Проблема: 1725 тестов проходят, но вывод забит `ECONNREFUSED :3000` и
`AggregateError`.

Найти тесты, которые ходят в реальный `:3000`, и замокать сеть/API. Приёмка:
`npm --prefix frontend run test -- --run` не печатает `ECONNREFUSED` и
`AggregateError`, все тесты зелёные.

## Отклонено

**`npm run prod:seed` не добавлять.** Владелец хочет запускать сид прода
вручную и жёстко контролировать этот шаг. Существующая процедура в
`docs/deployment.md` остаётся; автоматизацию не делать.

## Ограничения

- Не менять прод-данные и не запускать `prod:up`.
- Не трогать глобальные скиллы в `~/.agents/skills`.
- Работать в отдельной ветке от `main`, не в ветке T-383 (#440).
- Перед сдачей: `mise exec -- npm run gate` зелёный.

## Приёмка

1. `frontend/AGENTS.md` содержит правило прототипов UI.
2. Гейт резолвит python из `backend/.venv` и не зависит от PATH.
3. В `AGENTS.md` есть указатель на break-glass dev-входа.
4. PR с чужим action-SHA без tools.json краснеет в CI.
5. Полный frontend-прогон без `ECONNREFUSED`/`AggregateError`.
6. `prod:seed` не добавлен; решение зафиксировано.
