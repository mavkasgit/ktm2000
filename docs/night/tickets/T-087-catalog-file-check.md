# T-087 (проверка) — реальный файл каталога против нового парсера: можно грузить

- **Категория:** проверка совместимости перед ручным деплоем (#177)
- **Статус:** DONE — **можно загружать**, с одной оговоркой (ниже)
- **Дата:** 2026-10-03, ночная смена, срез D
- **Связано:** #87 (формат), #177 (загрузка `final_catalog.xlsx` в прод)
- **Продуктовый код:** одна правка в своей зоне — см. §4

## 1. Что проверял и на чём

Единственный реальный файл каталога в репозитории —
`frontend/e2e/testdata/Каталог E2E.xlsx` (его использует визард в
`full-cycle.spec.ts`). Он **старого формата**: 12 колонок, без «Размерности».
Прогнал его через настоящий HTTP-путь `preview-excel` → `apply-excel` на
тестовой БД (launcher создаёт свою), плюс выгрузку → обратный импорт.
Данные владельца не трогал, кроме SELECT на `:5440` (rollback).

## 2. Числа

| Проверка | Результат |
|---|---|
| `preview-excel` на реальном файле | **0 ошибок**, `stats={total:1, create:1}` |
| Состояние в item | `dimension_state=length`, `dimension_label='1D'`, `dimensions={}` |
| `apply-excel` | `imported=1, errors=[]`; создан ЮП-009 как **1D**, длины `[2000, 3000]`, осей нет |
| Повторный `preview-excel` того же файла | `skip=1, update=0, create=0` — идемпотентно |
| Выгрузка после импорта | `Размерность='1D'`, `Длины='2000, 3000'`, `Ширина/Толщина/Высота = None` |
| Обратный импорт этой выгрузки | `skip=1, update=0` — **оси и длины не теряются** |
| Файл с новыми колонками (2D) | `create=1`, item: `area` / `'2D'` / `{length 3000, width 1200, thickness 6}`; выгрузка отдаёт те же значения |

## 3. Про колонку «Размерность» на старом файле

Файл без этой колонки проходит **без ошибок**, и это правильная дефолтная
семантика: пустая колонка = «не трогаем».

- **create** → `dimension_state = length` (1D), как у всех артикулов, которые
  импорт создавал и до #87.
- **update** → размерность артикула не меняется: колонка пустая, а код правила
  «объявленная в файле размерность имеет приоритет» срабатывает только при
  заполненной ячейке.

Предлагать другую дефолтную семантику оснований не вижу: «требовать
размерность» сломало бы ровно тот файл, который лежит в репозитории и который
#177 собирается грузить.

## 4. Найденный дефект (исправлен) — тихо терялась вторая длина

Проверка на реальном файле вскрыла дыру в **моей** зоне: строка с двумя
длинами, применённая к 2D-артикулу файлом **без** колонки «Размерность»,
проходила без ошибок и при apply клала **первую** длину в ось размера, а вторую
молча теряла. Формально это выглядело как `action=update` с
`dimensions={length_mm: 2500}`, хотя в файле было «2500, 2700».

Починил: правило «у 2D/3D ровно одна длина» теперь проверяется по
**эффективной** размерности (объявленной строкой или уже заведённой в
карточке), а не только по объявленной. Обязательность полей размерности
оставлена только для строк, объявивших размерность — иначе сломался бы
partial update. Тест:
`test_legacy_file_cannot_silently_drop_a_length_of_a_2d_product`.

Коммит `7ec69a8`.

## 5. Что может сломаться у человека на загрузке

1. **Ничего для текущих данных.** Все 222 артикула в dev — `length` (1D), ни
   одного 2D/3D (проверено SELECT'ом на `:5440`, только чтение). Значит
   ветка «смена размерности» на загрузке не сработает вовсе.
2. **190 артикулов из этих 222 несут связь `length_mm` в `product_dimensions`**,
   хотя размерность у них 1D — наследие прежних миграций. Импорт их не
   трогает: миграция связей вызывается только для строк, объявивших 2D/3D, а
   для 1D-строк идёт обычная работа с реестром длин. Проверено: выгрузка таких
   артикулов даёт `Размерность='1D'` и пустые оси, обратный импорт — `skip`.
3. **Единственный способ увидеть новые ошибки** — заполнить «Размерность» +
   оси в файле. Если мастер этого не сделает, файл останется ровно тем же по
   смыслу, что и раньше (это и хорошо для повторяемости загрузки).

## 6. Вывод

**Можно загружать.** Реальный файл проходит без ошибок, идемпотентен и ходит по
кругу без потери; на текущих данных (все 1D) новая ветка не активируется вовсе.
Единственная правка, которую это потребовало, уже внесена и покрыта тестом.

Порядок для человека: залить `main` с `7ec69a8`, загрузить
`final_catalog.xlsx`, снять smoke — в превью ожидается одна строка `create`
(или `update`, если ЮП-009 уже заведён) и ноль ошибок.
