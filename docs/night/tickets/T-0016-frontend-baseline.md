## Проблема и доказательство

В baseline ночи frontend-набор не был измерен вовсе: в git-worktree нет
`frontend/node_modules` (каталог gitignored), поэтому `npm --prefix frontend run
test` там просто не запускается. Пока числа нет, любое утверждение «frontend-тесты
не деградировали» проверять нечем, а это половина набора репозитория (127
файлов).

## Что сделано

1. В worktree установлены frontend-зависимости по лок-файлу:
   `npm ci --no-audit --no-fund` в `frontend/` — 407 пакетов за 27s.
   Основное дерево человека при этом не тронуто (свой `node_modules` в worktree).
2. Три прогона `npm --prefix frontend run test` (`logs/vitest-baseline.log`,
   `logs/vitest-run2.log`, `logs/vitest-run3.log`):

| # | wall | Результат |
|---|---|---|
| 1 | 56.74s (холодный) | 127 files passed, 1 skipped; **1079 passed, 1 skipped** |
| 2 | 32s | то же |
| 3 | 32s | то же |

3. Разобран единственный скип: `frontend/scripts/verify-sync.integration.test.mjs`
   — `describe.skipIf(!KTM_SYNCGATE)`, реальный синк-гейт против соседнего
   репозитория `../hrms`; включается переменной окружения. Это осознанный
   гейт, а не спрятанная поломка.
