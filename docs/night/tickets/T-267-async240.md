# T-267 — ASYNC240: блокирующие path-операции в async-функциях (4 сайта) (#267)

- **Категория:** продуктовый код (backend), гигиена линтер-контура
- **Статус:** DONE — коммит `cde881d`
- **Дата:** 2026-10-01/02, смена B
- **Связь:** `ruff.toml:24-27` (пояснение семейства ASYNC), #259/#245 (закрытие контура)

## Проблема и доказательство

`ASYNC240` (blocking-path-method-in-async-function) включён в `select`, но
зелёный только за счёт подавлений. До правки:

```
ruff check backend --select ASYNC240 --ignore-noqa   → 4 находки
grep -rn "noqa: ASYNC240 — #267" backend/app         → 4 сайта
```

Сайты (номера строк — до правки): `catalog_import.py:108` (`mkdir` каталога
фото), `imports.py:645` (`exists()` перед `FileResponse`),
`products.py:1430` (`mkdir` каталога фото), `plan_import_service.py:535`
(`mkdir` хранилища импорта).

Сайты `backups.py` (`read_bytes`, `stat`, `exists`, `iterdir`) из брифа
подтверждения **не получили**: чек `--ignore-noqa` находок там не даёт —
операции лежат вне `async def` (модуль построен на синхронных хелперах,
`_save_upload_file` уже переведён на `anyio.open_file` в ASYNC230).

## Решение по каждому сайту

| Сайт | Что делает | Приём |
|---|---|---|
| `catalog_import.py` | `mkdir` каталога фото | `asyncio.to_thread(photo_dir.mkdir, parents=True, exist_ok=True)` |
| `imports.py` | `exists()` файла перед отдачей | `await asyncio.to_thread(path.exists)` |
| `products.py` | `mkdir` каталога фото | `asyncio.to_thread(storage_dir.mkdir, parents=True, exist_ok=True)` |
| `plan_import_service.py` | `mkdir` хранилища импорта | `asyncio.to_thread(storage_dir.mkdir, parents=True, exist_ok=True)` |

Почему `to_thread`, а не `anyio.Path`: операции одиночные и короткие —
выигрыш даёт вынос из event loop, а не асинхронный интерфейс поверх всей
цепочки; `asyncio.to_thread` в проекте уже принят (`backup_scheduler.py:88`).
`anyio` остаётся там, где важен именно асинхронный интерфейс целиком
(`_save_upload_file`, потоковая запись сотен МБ).

Порядок и блокировки не менялись: `mkdir`/`exists` идемпотентны и локов не
держат, поэтому стоп-условие тикета не сработало.

## Границы: что НЕ трогали

- `backups.py` — ни одной строки: находок нет, подавлений нет.
- Соседние блокирующие `.write_bytes`/`.read_bytes` в тех же функциях
  (`stored_path.write_bytes`, `full_path.write_bytes` и т.п.): ruff их не
  видит (вывод типа узкий — путь, собранный через `/`, не распознаётся),
  поведение не менялось, AC тикета их не требует. Остаток вынесен в
  комментарий к тикету как кандидат отдельного захода.
- Логика импорта/загрузки/разбора Excel не менялась — только обёртка вызова.

## Откат

`git revert cde881d`: возвращает `mkdir`/`exists` в синхронном виде и четыре
`noqa` со ссылкой на тикет. Данные не затрагиваются (операции идемпотентны).
