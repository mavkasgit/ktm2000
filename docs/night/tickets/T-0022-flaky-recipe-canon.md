# T-0022 — В каноне не было рецепта проверки flaky

- **Категория:** документация по тестированию (flaky-менеджмент)
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 7
- **Файл:** `backend/tests/AGENTS.md`

## Проблема и доказательство

Канон описывает запуск, изоляцию, правила написания тестов и уборку, но ничего
не говорит о **проверке нестабильности**: ни сколько прогонов нужно, ни как
сравнивать результаты. Между тем именно это требуется при любой правке, которая
может задеть тайминги/порядок/изоляцию (а также при разборе «тест иногда
падает»).

Ночная сессия наработала рецепт на практике: 5 прогонов baseline и 3 после
правок, сравнение набора `FAILED` и числа `passed`, плюс суммы фаз из
`--durations=0`. Без записи в каноне этот опыт остаётся только в журнале ночи.

## План изменений

Новый подраздел «Проверка нестабильности (flaky)» в `backend/tests/AGENTS.md`:

- цикл из 5 прогонов через launcher с `-q --durations=0` и записью в отдельные
  логи;
- две проверки-`grep`: одинаковый ли набор `FAILED`, не плывёт ли число
  `passed`;
- критерий: одинаковый набор и число тестов = стабильно; разброс wall time
  в пределах ~±7% — шум машины, а не флейк;
- ссылка на факт замера 2026-10-01 (5 + 3 прогона, наборы совпали).

## Граница: что НЕ затронуто

- Продуктовый код, тесты, конфиги, launcher — не менялись.
- Никаких новых инструментов/зависимостей: только команды, уже существующие в
  репозитории (`npm run test:pytest`, `--durations=0`).
- Ничего не удалено из канона; раздел добавлен.

## Критерии готовности (измеримые)

1. Раздел есть, команды из него работоспособны (использованы в этой сессии:
   `logs/flaky-*.log`, `logs/stability-*.log`).
2. Утверждение о критерии стабильности совпадает с фактом: 5/5 и 3/3 прогонов
   дали одинаковый набор результатов.
3. Тесты не затрагиваются (правка документации).
