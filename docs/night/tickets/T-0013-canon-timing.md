# T-0013 — Документация обещала «~3 мин» на прогон; замеры дают другое

- **Категория:** документация по запуску тестов
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 3
- **Файл:** `backend/tests/AGENTS.md` (канон pytest)

## Проблема и доказательство

В таблице команд канона стояло «Параллельный прогон (по умолчанию, ~3 мин)».
Замеры этой ночи (`PYTEST_NUM_WORKERS=4`, 4 ядра задействовано из 16):

- baseline-серия (5 прогонов): медиана **350.0s** (5:50);
- после `--dist loadfile` (T-0003): медиана **256.6s** (4:17), финальная серия
  — медиана **233.4s** (3:53).

То есть «~3 мин» не соответствовало ни одному режиму, а после ускорения стало
просто неверным ориентиром: человек, планируя прогон, ошибается в полтора-два
раза.

## План изменений

1. Строка таблицы: «~4.5 мин при `PYTEST_NUM_WORKERS=4` — замер 2026-10-01»
   (серийный `--full` намеренно не оценивается: не замерялся без coverage).
2. Добавлена строка про `npm run test:hygiene` (report-only проверка мёртвых
   импортов, появившаяся в `T-0012`) — иначе новый инструмент не виден из канона.

## Граница: что НЕ затронуто

- Продуктовый код, тесты, конфиги раннера — не менялись: только текст
  документации рядом с тестами.
- Ни одно утверждение о поведении не изменено, только числа времени и одна
  новая строка таблицы.

## Критерии готовности (измеримые)

1. Число в каноне совпадает с медианой замеров (`logs/stability-1..3.log`,
   `logs/verify-T0003.log`) — «~4.5 мин».
2. `npm run test:hygiene` существует и описан в двух местах (канон +
   `docs/testing-guide.md`).
3. Диффа — один файл документации.
