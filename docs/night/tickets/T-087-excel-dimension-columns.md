- **Тикет:** [#87](https://github.com/mavkasgit/ktm-2000/issues/87)
- **Файлы:** `backend/app/services/catalog_excel_import.py`,

## Проблема

Шаблон импорта знал 11 колонок и ничего не знал про `dimension_state`
(1D/2D/3D) и `product_dimensions`. 2D/3D-артикул через Excel было не завести:
размерность не создавалась, значения осей не записывались, длина уходила в
реестр длин — то есть в `product_lengths`, откуда плоский лист её и не читает.

## Что сделано

1. **Колонки.** В `TEMPLATE_HEADERS` добавлены `Размерность`, `Ширина, мм`,
   `Толщина, мм`, `Высота, мм`. Пустая ячейка — «не трогаем» при update, при
   create по умолчанию 1D. Значения — числа > 0, тем же разбором, что и
   остальные числовые колонки.
2. **Маппинг.** «Размерность» разбирается в `DimensionState` в любом
   регистре (`1D`, `1д`, `2`, `3` — все приводятся к `length`/`area`/`volume`).
3. **Валидация строки.** Неизвестный токен, ссылка на чужое измерение
   (высота у 2D, толщина у 3D, габарит у 1D), значение без «Размерности»,
   несколько длин у 2D/3D — ошибка `{row, sku, message}`.
4. **Обязательность полей** проверяется в `validate_row_counts`, куда
   передаются заведённые значения осей. Это ключевое решение: пустая ячейка при
   partial update означает «не трогаем», поэтому проверять обязательность по
   одной строке файла нельзя — иначе «поправить одну ширину» перестало бы
   работать. Первая версия проверяла в парсере и роняла именно этот случай.
5. **Apply.** Create: `Product(dimension_state=…)`, для 2D/3D `ProductLength` не
   заводится, длина и оси уходят в `product_dimensions.default_value`.
   Update: общий хелпер миграции + простановка значений; при переходе в 2D/3D
   реестр длин чистится — ровно как это делает карточка (`products.py`).
6. **Общий хелпер.** `_migrate_dimensions_for_state` вынесен из
   `app/api/routes/products.py` в `app/services/dimension_state.py`
   (`migrate_dimensions_for_state`) — карточка и импорт переводят размерность
   одним правилом. Рядом `set_dimension_defaults` для значений. Связи
   неразмерных типов (weight) при смене не трогаются — это и раньше было
   правилом миграции, теперь оно общее.
7. **«Кол-во на подвесе»** у 2D/3D не применяется (ADR-0012), а в preview
   приходит предупреждением: молча выбрасывать значение мастера нельзя.
8. **Preview и выгрузка.** В `preview-excel` item получил `dimension_state`,
   `dimension_label` («1D/2D/3D») и `dimensions` — значения осей. Выгрузка
   пишет размерность и оси, поэтому файл ходит по кругу без потери данных.

## Приёмка (проверяемая)

Тесты `backend/tests/test_catalog_excel_dimensions_87.py` — 23 штуки:

- разбор 2D и 3D (включая «3д»);
- ошибки: неизвестный токен, не хватает обязательного поля, чужая колонка
  размерности (высота у 2D, толщина у 3D, габарит у 1D), несколько длин у 2D,
  значение без «Размерности», нечисловая/неположительная ось;
- существующие 1D-конфигурации работают как раньше (`test_plain_1d_row_parses_as_before`);
- create 2D/3D: связи со значениями и пустой реестр длин; 1D без «Размерности»
  по-прежнему даёт `product_lengths`;
- update: 1D → 2D с сохранением связи `weight_kg`, 2D → 3D с удалением
  толщины, partial update одной оси без обнуления остальных;
- «Кол-во на подвесе» у 2D не применяется;
- preview показывает размерность, оси и считает смену размерности как update;
- выгрузка → импорт по кругу не даёт ложного update.

Регрессии существующего поведения проверены: `tests/test_catalog_excel_import.py`
(сюда входят round-trip идемпотентность и отказ сырьевых длин у 2D/3D) — зелёные.

Прогоны: `npm run test:pytest` — 2063 passed, 2 skipped; `npm --prefix frontend
run test` — 1277 passed, 1 skipped; `ruff check backend` — чисто.
