# T-0019 — `cleanup` убирает только БД; storage-каталоги копились (25 МБ)

- **Категория:** гигиена тестовой инфраструктуры
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 5
- **Файлы (тестовая зона):** `scripts/test-db.py`, `docs/testing-guide.md`,
  `backend/tests/AGENTS.md`

## Проблема и доказательство

`npm run test:db:cleanup` умел убирать только run-DB (`ktm2000_test_%`), а
каталоги storage тестов не трогал никто: замер этой ночи —
`%TEMP%\ktm2000_pytest_storage` весил **25 МБ** накопленного мусора
(`T-0014` сделал каталоги разовыми и удаляет их по завершении прогона, но
прерванный прогон каталог оставляет, а старый общий каталог не убирался
вообще).

## План изменений

1. `scripts/test-db.py`: `cleanup` после БД проходит по `%TEMP%` и удаляет
   каталоги `ktm2000_pytest_storage*` **старше TTL** (по mtime: у живого
   прогона mtime свежий, поэтому чужой каталог не задевается).
   - `--dry-run` работает как и для БД (`DRY …` вместо `DROP …`);
   - вывод в том же стиле (`SKIP … younger than Nh TTL`);
   - `shutil.rmtree(..., ignore_errors=True)` — на Windows открытые файлы могут
     не удалиться, и это не должно ломать уборку.
2. Документация: строка в `docs/testing-guide.md` и абзац в каноне
   (`backend/tests/AGENTS.md`) — уборка теперь покрывает и storage.

## Граница: что НЕ затронуто

- Продуктовый код, тесты, `conftest.py`, launcher — не менялись.
- Уборка БД не изменилась (тот же порядок, те же проверки владельца/соединений).
- Каталоги моложе TTL не трогаются вообще — чужой живой прогон не задевается.

## Критерии готовности (измеримые)

1. `cleanup --dry-run` на каталоге с mtime «2 дня назад» печатает
   `DRY  … storage older than 24h TTL`; на свежем каталоге — `SKIP … younger
   than 24h TTL` (проверено).
2. `cleanup` реально удаляет старый каталог (`Removed 1 storage dir(s)`),
   свежий остаётся (проверено).
3. Полный прогон тестов не затронут (`cleanup` в прогон не встроен).

`git revert <commit>` (правка одного скрипта + две строки документации).

## Артефакты

Прогоны уборки — в транскрипте сессии; замер 25 МБ — в `BASELINE.md`
(раздел «Frontend unit» и заметка про storage).
