## Что сделал merge (основание для обеих осей)

Все три коммита среза — merge, поэтому сперва проверено, **принёс ли merge
лишнего и не потерял ли чего**. Проверка деревьев, а не чтение сообщения о
merge:

| Merge | p1 (main) | p2 (ветка) | пересечение файлов | дерево merge vs p2 |
|---|---|---|---|---|
| `772d9e16` (#275) | `31691ac0` | `2a6b31e5` | **0 файлов** | `git diff --stat` — **пусто** |
| `9661ef9b` (#278) | `ad397277` | `91193168` | **0 файлов** | 16 файлов = ровно состав p1 |

- **#275**: merge-base = `232585ed`, обе стороны от него меняли **разные**
  файлы (main — 0, ветка — 15), поэтому конфликт мог быть только один —
  `frontend/e2e/AGENTS.md`, как и сказано в тикете. Дерево merge **побайтово
  равно** дереву ветки (`git diff 772d9e16^2 772d9e16` — пусто, и
  `git rev-parse` обоих деревьев даёт один хеш `09ffcc6d`). Ничего не потеряно.
- **#278**: обе стороны меняли 16 и 50 файлов соответственно, пересечение — 0,
  конфликтов не было. `git diff 9661ef9b^2 9661ef9b` показывает ровно 16
  файлов — это вклад main, логика merge ничего не переписал.
- **#276** — merge без второго родителя по содержимому (один файл workflow).

Все коммиты, названные в тикетах, вMerge попали: `7f0c5ef`, `d3a549a`,

вторая требует прогона данных и здесь опровергнута. В грилл уходит только
