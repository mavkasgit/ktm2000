# T-0017 — Launcher брал `python` из PATH: прогон зависел от окружения

- **Категория:** повторяемость окружения
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 5
- **Файл (тестовая зона):** `scripts/test-run.ps1`
- **Связь:** B-0006

## Проблема и доказательство

Launcher вызывал интерпретатор по имени: `& python -m pytest …` и
`& python scripts/test-db.py …`. Что именно попадётся в `python`, решал `PATH`
запускающего, а на этой машине это разные вещи:

- в `PATH` — системный Python 3.12.10, в котором и стоят зависимости
  (`pytest 9.1.1`, `pytest-xdist`, `testmon`, `fastapi 0.142.2`);
- `backend/.venv` — Python **3.14** без зависимостей (`pytest`/`uvicorn`
  отсутствуют), при этом `AGENTS.md` называет окружением проекта `.venv`.

То есть один и тот же скрипт в двух окружениях вёл себя по-разному, а при
неверном интерпретаторе падал глубоко внутри (импорт `pytest`), без намёка на
причину. Это ровно тот разрыв, который зафиксирован в B-0006 как «декларация
окружения расходится с фактом».

## План изменений

1. `$PythonExe = $env:TEST_PYTHON ?? "python"` — явный путь можно задать
   переменной окружения (по умолчанию поведение прежнее).
2. Ранняя проверка запускаемости интерпретатора с понятным сообщением:
   `TEST_PYTHON='…' is not a runnable interpreter (set TEST_PYTHON or fix PATH)`.
   Проверка обёрнута в try/catch — при `$ErrorActionPreference = "Stop"` сам
   вызов падал раньше проверки, и пользователь видел локализованную ошибку
   PowerShell вместо причины.
3. Шапка прогона печатает выбранный интерпретатор (`Python : …`) — при разборе
   «почему тесты не те» это первое, что нужно знать.
4. Все вызовы `python` в скрипте (pytest, `test-db.py` create/verify/drop)
   переведены на `$PythonExe`.

## Граница: что НЕ затронуто

- Продуктовый код, тесты, `conftest.py`, `pytest.ini` — не менялись.
- Поведение по умолчанию идентично прежнему: без `TEST_PYTHON` вызывается
  `python` из PATH.
- Никакие зависимости не устанавливались и не добавлялись; `.venv` не тронут.
- Файл остаётся ASCII-only (Windows PowerShell читает `.ps1` как UTF-8 без BOM
  и портит не-ASCII литералы) — проверено: 0 строк с не-ASCII.

## Критерии готовности (измеримые)

1. `TEST_PYTHON=<полный путь к системному python> npm run test:pytest -- tests/test_e2e_stand.py -q`
   → `6 passed`, в шапке `Python : <путь>`.
2. `TEST_PYTHON=C:/no/such/python.exe …` → код возврата **1** и понятное
   сообщение (до правки был локализованный `CommandNotFoundException`).
3. Без переменной: `Python : python`, `6 passed` — прежнее поведение.
4. Полный прогон: `1951 passed, 0 failed, 43 warnings`.
