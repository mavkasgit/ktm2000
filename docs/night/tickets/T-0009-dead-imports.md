# T-0009 — Мёртвые импорты в тестах: 107 имён в 36 файлах

- **Категория:** чистота тестовой зоны / подготовка к линтеру
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 3
- **Связь:** B-0003 (линтера в репозитории нет — эти замечания некому ловить)

## Проблема и доказательство

Линтера в репозитории нет (проверено: ни ruff/flake8/mypy, ни eslint; в CI нет
шага линта). Разовый AST-анализ `backend/tests/**` (скрипт
`logs/analyze_tests.py`, отчёт `logs/unused-imports-report.txt`) нашёл **114
имён**, импортированных и нигде в своём файле не использованных — с учётом
строковых аннотаций (строки парсятся как выражения, чтобы `"User"` в аннотации
не считался мёртвым).

## План изменений и что сделано

1. Скрипт `logs/strip_unused_imports.py` убирает имя из `from … import …`
   (однострочные и многострочные формы, с сохранением отступа и перевода
   строки), после каждой правки перепроверяет синтаксис через `ast.parse`.
2. **Не тронуто осознанно:**
   - bare-импорты модулей (6): `import app.models` в `test_migrations.py`
     регистрирует модели для `Base.metadata` (side-effect), `import pytest` /
     `import pytest_asyncio` оставлены в одном пакете с ними;
   - файлы из denylist: `tests/stock/test_shopfloor_stage3.py` (1 имя);
   - statements с комментариями внутри — скрипт их не переписывает.
3. Итог: **107 имён в 36 файлах**, `git diff --stat`: 23 вставки, 88 удалений.

## Инцидент и его разбор (важно для будущих чисток)

Первый полный прогон после чистки дал `1934 passed, 1 error`:
`tests/stock/test_stock_dimensions.py` не смог импортировать
`_release_via_take_to_work` из `tests.stock.test_transfer_stage2`.

Причина: `test_transfer_stage2.py` — **реэкспортный хаб**: сам он
`_release_via_take_to_work` не вызывает, но `test_stock_dimensions.py` берёт
его именно оттуда. Анализ «имя не используется в файле» такие хабы не видит по
определению.

Что сделано: имя возвращено с комментарием-предупреждением («не удалять при
чистке импортов»), в файле уже был такой же комментарий для
`tests.helpers.transfers`. Дополнительно прогнана AST-проверка «импортирует ли
кто-то удалённое имя из этого модуля» — конфликт был ровно один.

Урок в журнале: подобные чистки обязаны завершаться полным прогоном, и
реэкспортные хабы надо искать явно (в текстовом диффе имена в многострочных
`from … import (…)` не содержат слова `import`, из-за чего первая проверка их
пропустила).
