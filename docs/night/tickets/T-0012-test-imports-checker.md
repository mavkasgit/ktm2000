# T-0012 — Повторяемая проверка мёртвых импортов в тестах (report-only)

- **Категория:** чистота тестовой зоны / повторяемость
- **Статус:** DONE (коммит см. `JOURNAL.md`)
- **Дата:** 2026-10-01, цикл 3
- **Связь:** `T-0009` (разовая чистка), `B-0003` (линтера в репозитории нет) *(пометка 2026-11-03, #386: актуально на 2026-10-01, на 2026-11-03 неверно — ruff и ESLint включены; сноска ниже)*

## Проблема и доказательство

`T-0009` убрал 107 мёртвых импортов в 36 файлах, но **разовым** скриптом в
`docs/night/logs/`. Линтера в репозитории нет (проверено: ни ruff/flake8/mypy, ни eslint, ни шага линта в CI) *(пометка 2026-11-03, #386: актуально на 2026-10-01, на 2026-11-03 неверно — ruff включён и блокирует, ESLint настроен; сноска ниже)*, поэтому тот же мусор накопится снова, и заметить
это будет нечем. Нужна повторяемая проверка, не требующая новых зависимостей.

> **Сноска (2026-11-03, #386):** текст выше — снимок состояния на дату тикета
> (2026-10-01), а не текущее состояние репозитория; на 2026-11-03 он неверен.
> Проверка `ruff check backend` (команда `.github/workflows/ruff.yml`, пин
> `ruff==0.16.9`) блокирует сборку, а в `ruff.toml` в `select` стоит `"F"` —
> то есть `F401` (imported but unused) ловит ровно тот мусор, ради которого
> писался этот checker, и по `backend/tests/**` тоже. Доказательство — красное
> зондирование (файл на диске не создавался, текст подан на stdin с
> подставным путём `--stdin-filename backend/tests/_probe_f401.py`): вывод
> `F401 [*] os imported but unused` + `Found 2 errors`, код возврата 1;
> на чистом дереве той же командой — `All checks passed!`, код возврата 0.
> ESLint настроен (`frontend/eslint.config.js`, шаг `npm run lint` в
> `.github/workflows/frontend-tests.yml`; тикеты #336/#337). `mypy` и `flake8`
> как отдельные инструменты по-прежнему не настроены — эта часть утверждения
> не опровергается. Сам checker и `npm run test:hygiene` **не удалены**: решение
> о их нужде на фоне `F401` — к владельцу (вопрос внесён в комментарий тикета
> #386); отчёт report-only остаётся как исторически значимая проверка.
> Исторический текст не переписан — добавлены только пометка и эта сноска.
> Правило оценки таких строк — «архивные тикеты — снимок состояния на дату,
> утверждение о текущем
> состоянии вне архива требует проверки» (#382, `docs/quality/criteria.md`).

## План изменений

1. `scripts/check-test-imports.py` — report-only анализатор (только stdlib):
   имена из `from … import …`, не встречающиеся в своём файле ни как имя/
   атрибут, ни внутри строковой аннотации (строки парсятся как выражения).
   - по умолчанию печатает находки и возвращает **0** (не роняет сборку);
   - `--strict` — возвращает 1 (на будущее, если решат включить в CI);
   - осознанно не считает находками: bare `import X` (side-effect, например
     `import app.models`) и statements с комментарием (escape hatch для
     намеренных реэкспортов — так помечен `test_transfer_stage2.py`).
2. `backend/tests/test_check_test_imports.py` — 6 тестов на синтетических
   файлах в `tmp_path`: находка ловится; имя в коде/в строковой аннотации/
   через `as` не считается мёртвым; комментарий и bare-импорт пропускаются.
   Без них сломанный анализатор молча печатал бы «находок: 0».
3. `package.json`: `npm run test:hygiene`.
4. `docs/testing-guide.md`: строка в таблице команд.

## Граница: что НЕ затронуто

- Продуктовый код, `pytest.ini`, launcher, conftest — не менялись.
- Никаких новых зависимостей: только `ast`, `argparse`, `pathlib`, `sys`.
- Сборка не падает от находок (report-only) — как и требовалось для линтера.
- Ни один тест не удалён и не ослаблен; `T-0009` не откатывается.

## Критерии готовности (измеримые)

1. `npm run test:hygiene` → печатает находки и завершается кодом **0**
   (сейчас 1 находка: `text` в файле из denylist — незаконченная работа
   человека, трогать её нельзя).
2. `--strict` на тех же данных → код 1 (проверяется вручную).
3. `backend/tests/test_check_test_imports.py`: `6 passed`.
4. Полный прогон: `1945 + 6 = 1951 passed, 0 failed, 43 warnings`.
5. Диффа вне тестовой зоны/`scripts/`/`package.json`/`docs` нет.
