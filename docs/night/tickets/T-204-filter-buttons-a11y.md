# T-204 — значения фильтра кнопками, подписи и приоритет сортировки (#204)

- **Категория:** продуктовый код (frontend), доступность шапки таблиц
- **Статус:** DONE — коммит `d970fbc`
- **Дата:** 2026-10-01/02, смена B
- **Связь:** решения гриллинга в тикете; #285 (aria-sort вынесен туда), ADR-0037

## Проблема и доказательство

`SortableFilterHeader` — единственный потребитель — `DataTableColumnHeader`,
через него это 16 мест рендера в 15 файлах. Значение фильтра рисовалось как
`<div onClick>` без `role`/`tabIndex`/`aria-*`: клавиатурой выбрать значение
было нельзя нигде, скринридер объявлял пустой блок текста. `aria-label` кнопки
сортировки собирался из машинного поля (`Сортировка по sku (asc)`), приоритет
мультисортировки жил только в `data-sort-priority`.

## Что сделано

1. Значение фильтра — `<button type="button" aria-pressed={isSelected}>`:
   Tab проходит по значениям, Enter/Space переключает (штатное поведение
   нативной кнопки), `aria-pressed` объявляет выбор. `listbox` с roving
   tabindex не заводится — решение гриллинга.
2. `aria-label` кнопки сортировки: из подписи колонки, порядок словами,
   приоритет мультисортировки в тот же label —
   `«Артикул, сортировка по возрастанию, приоритет 2 из 2»`; у единственной
   сортировки приоритет не называется («1 из 1» — шум).
3. Машинное поле переехало в `data-sort-field` (новый атрибут данных): по нему
   тесты адресуют кнопку — доступное имя теперь человеческое и как селектор не
   годится. `data-sort-order`/`data-sort-priority` не тронуты.
4. Тесты: `SortableFilterHeader.test.tsx` — значение это кнопка с `tabIndex` 0
   и `aria-pressed`, переключение меняет `aria-pressed`; четыре теста на
   label (подпись колонки, «не задана», приоритет 2 из 2, отсутствие приоритета
   у единственной сортировки). Селекторы в 8 файлах фич-тестов переведены с
   `^Сортировка по <field>` на `data-sort-field`/`/, сортировка/`.
5. ADR-0037: раздел «Что не менялось» переписан, добавлен раздел «Доступность
   шапки (#204, #285)».

## Критерии готовности (измеримые)

1. `npx tsc --noEmit` → **0**.
2. `npx vitest run` → **1157 passed / 1 skipped** (проверка той же ревизии, что
   закоммичена; после #285 набор вырос до 1160).
3. Значение фильтра — элемент `BUTTON` с `tabIndex === 0` и `aria-pressed`

   (тест `not.toContain("Сортировка по sku")`).

## Ограничение доказательства (честно)

Клавиатурную активацию в **живом браузере** не прогоняли: happy-dom не
разыгрывает действия по умолчанию (`fireEvent.keyDown(button, Enter)` не даёт
`click` — проверено разовым скриптом), а e2e-стенд в этом дереве не поднимался
(AC тикета — vitest + tsc). Проверено структурно: элемент — нативная кнопка,
её активацию Enter/Space выполняет браузер. Если нужен браузерный прогон —
это отдельная проверка на e2e-стенде.

## Границы: что НЕ трогали

- `data-sort-order`/`data-sort-priority` — как были (их читают тесты).
- `aria-sort` — это #285.
- `listbox`/`roving tabindex` — не заводили (нет такого компонента в проекте).
- Логика фильтрации (одно-/множественный выбор, текст приоритетнее выбора) —
  не менялась: переключение значения всё тем же `toggleOne`.
