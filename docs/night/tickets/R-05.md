## #283 — массовый ввод факта в таблице доски + футер (`8a816eb9`, `f99e307a`)

### Исправлено (лёгкое)

**1. Порция, равная нулю, оставляла ввод во всех строках группы.**
`lib/bulkDraft.ts`, `applyGroupField`: условие `total === 0 || row.value > 0 ? value : ""`
заполняло поле **каждой** строки, когда сумма раскладки нулевая — вопреки
комментарию прямо над собой («строка, которой ничего не досталось, остаётся
пустой»). Воспроизводится: в группе с записанным фактом 40 и 20 ввод цели «60»
(= сумма записанного) или «+0» давал черновик `{1:{good:"40"},2:{good:"20"}}`
при нулевой порции к записи.

Следствия, которые видит оператор: черновик непустой → Escape и тумблер режима
спрашивают подтверждение выхода ради ничего; строки выглядят заполненными, а
футер отвечает «Введите количество» (`bulk_no_quantity`) при заполненных полях.

Правка: `row.value > 0 ? value : ""`. Тест `bulkDraft.test.ts` —
«порция, равная нулю, ввода не создаёт: черновик остаётся пустым» (проверяет и
цель, и «+0»).

**2. Записанный факт группы считался в трёх местах по-разному.**
`SectionTasksBoard.tsx:569-570` (шапка таблицы) и `:1661-1664` (шапка карточки
на узком экране) суммировали `parseFloat(task.cache.completed_quantity)`, тогда как
арифметика ввода считает от `recordedFact` → `toQtyInteger` (`quantityFormat.ts:73`).
`parseFloat` не округляет поштучно и даёт `NaN` на мусоре, где `toQtyInteger` даёт
`0`.

Число, а не рассуждение: `parseFloat("2.4") + parseFloat("0.4") = 2.8` → плейсхолдер
печатает «сейчас 3», тогда как база разбора — `2 + 0 = 2`. Цель «3» проходит, а
цель, совпавшая с плейсхолдером, оказывается ниже записанного; при пустом значении
плейсхолдер показывает «—» при фактически записанном факте.

Правка: `groupRecordedFact(tasks, field)` в `bulkDraft.ts` — единственное место
суммы; `resolveGroupFact` и обе шапки берут его. Тест пинит инвариант «плейсхолдер
и разбор ввода считаются от одной базы».

### Не исправлено (нужно решение / не лёгкое)

**3. Escape при непустом черновике выходит из массового режима, а не снимает
выделение.** AC #283, п. 4: «Escape — снять выделение (при непустом черновике —
подтверждение)». `SectionsTasksPage.tsx:636-641`: подтверждённое действие делает
`setBulkMode(false)` + чистит всё. Черновик и так уносится снятием выделения
(`useEffect` `:237-246` → `withoutDraftIds`), поэтому лишний именно выход из режима.
Это продуктовое поведение (Escape = «снять выделение» или «выйти из режима»), не
правка на строку — оставляю владельцу.

**4. Текст причины «Введите количество» при непустом черновике с нулевыми
порциями.** `SectionsTasksPage.tsx:973-980`: при `entries.length === 0` и
`skipped.length === 0` причина всегда `bulk_no_quantity` — даже если поля заполнены
(например, в строке набрано «+0»). Словарь причин — продуктовый текст
(`shared/lib/actionReasons.ts:50`), нужен новый код или переформулировка.

**5. Duplicated Code — обработчик клавиатуры строки.** `SectionTasksBoard.tsx:340-349`
(`renderTaskRow`) и `:455-464` (`renderMobileCard`) — 12 строк дословно, вместе с
комментарием. Правка на строку не нужна: это рефакторинг на общий обработчик, но
проверяется только существующими тестами доски; оставил под отдельный тикет, чтобы
не мешать в ночную смену.

**6. Мобильная карточка не несёт `aria-selected`.** AC п. 4: «строке даём
`aria-selected`». У desktop `<tr>` атрибут есть (`:328`), у карточки узкого экрана
есть только `tabIndex` (`:443`). Добавить «просто атрибут» нельзя: `aria-supported`
у `<div>` без роли невалиден (`aria-selected` держит `row`/`option`/`gridcell`/`tab`),
значит нужна роль для списка карточек — это решение по семантике, не лёгкая правка.

**7. Дубликат doc-комментария** над `groupFieldValue` (`SectionTasksBoard.tsx:1151-1157`):
старый блок и сразу за ним новый однострочный на ту же функцию.

### Проверено — расхождений с AC не найдено

  (`frontend/e2e/ui-helpers.ts:743`), `data-task-id` на строке доски.
- Документы: ADR-0064 создан, ADR-0031/0032/0037/0049 и `CONTEXT.md` правились.

## #285 — `aria-sort` на сортируемых `th` (`debfd226`, `0024550a`, `f60a656b`)

Тикет закрыт, AC выполнены — проверено, а не по отчёту коммита:

- `grep -rn "getAriaSort" frontend/src`: **одно** определение
  (`shared/lib/multiSort.ts:35`), остальные вхождения — импорт и вызов; локальных
  копий нет (AC 2).
- `aria-sort` проставлен в **16** местах рендера шапок, у всех — по одному условию
  `column.sortField ? getAriaSort(...) : undefined` (`TransfersPage` — два).
- `ReadyTransferPrintDialog` в список не попал **обоснованно**: его `<th>`
  (`:110-119`) не сортируются (печатный лист, порядок задан выборкой), `sortField`
  там читается только для значения ячейки (`:54`).
- `DataTableColumnHeader` `<th>` не рендерит — рисует содержимое, атрибут ему не
  нужен (это отмечено и в комментарии тикета).
- ADR-0037 переписан: раздел «Что не менялось» больше не говорит про дыру,
  добавлен пункт про `aria-sort` и общего хелпера.

**Замечание (не блокер, Standards):** условие «колонка сортируемая» продублировано
в 16 шапках — ровно тот класс дублирования, который ADR-0037 закрывал для фильтра
(«семантика колонки объявляется один раз»). Условие можно унести в компонент
`<SortableTh>`; это изменение контракта 16 мест рендера, ночью не делал.

`0024550a` — merge, переносящий ту же работу (`debfd226`, `f60a656b`); задвоения в
дереве нет: `getAriaSort` определена один раз, `BulkOperationsPanel` отсутствует.
