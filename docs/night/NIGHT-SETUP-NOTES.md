# Ночная смена: что нужно дереву, чтобы агент не спотыкался

Заметка для будущих ночей. Не про продукт, а про подготовку: список того, что
в дереве ночного worktree **нет**, а нужно почти всем срезам. Собрано по факту
смены 2026-10-02 (каждый пункт кого-то остановил).

## 1. Интерпретатор

`backend/.venv` в ночном дереве отсутствует — он не отслеживается. Нужна
переменная окружения:

```
export TEST_PYTHON='C:/Users/<владелец>/VibeCoding/ktm2000/backend/.venv/Scripts/python.exe'
```

Проверка: `"$TEST_PYTHON" -m pytest --version` → `pytest 9.1.1`. Это сам дешёвый
спасательный шаг: без него агент либо падает, либо (хуже) ставит зависимости
в чужое дерево.

## 2. `frontend/node_modules`

В новом worktree отсутствует. Нужен любому, кто трогает фронт или гоняет e2e:

```
npm ci --prefix frontend
```

Junction на основное дерево **не делать** — он ломает vitest и делит лок e2e
между деревьями (реальный случай прошлой ночи).

## 3. `.env.test`

Отсутствует в дереве worktree (не отслеживается), а нужен `docker compose` для
тестового Postgres. Агент берёт копию из соседнего дерева вручную.

**Предложение к следующей ночи:** положить пример `.env.test.example` в
репозиторий рядом с `.env.example` и добавить короткий раздел в
`frontend/e2e/AGENTS.md` — «подготовка ночного worktree». Тогда агент не
тратит цикл на выяснение, что копировать.

## 4. Env-файл стенда e2e

Каждый срез, который гоняет Playwright, обязан иметь **свой** namespace, иначе
прогоны делят клон БД и данные. Образец:

```
cp .env.e2e .env.e2e.night-<срез>.local
# DATABASE_URL и E2E_TEST_DATABASE_URL → база ktm2000_e2e_night-<срез>
# STORAGE_ROOT=../data/storage-e2e-night-<срез>
```

Файл под `.gitignore` (`*.local`) — в коммит не попадает. Проверять:
`git check-ignore -v .env.e2e.night-<срез>.local`.

## 5. Чего делать нельзя

- `git symbolic-ref`, `git checkout`, `git switch`, `git reset` **без `-C <путь к своему дереву>`** — команда разрешится в дереве, где вы оказались (реальный случай: команда среза переключила `main` на ветку среза).
- `git commit -a` и «точечный `git add`» как защита: **коммит берёт весь индекс**. Перед каждым коммитом — `git diff --cached --stat`.
- e2e в чужом worktree и e2e в основном дереве при живом WIP владельца.


## 6. `tsc` проверяется только с `-p`, иначе зелёное враньё

```
cd frontend && npx tsc -p tsconfig.json --noEmit
```

Вызов `npm --prefix frontend run tsc --noEmit` из корня **печатает справку и
проект не проверяет** — без `-p` tsc не находит конфиг и выходит с кодом 0.
То есть агент может отчитаться «tsc чисто», не проверив ни одной строки.
