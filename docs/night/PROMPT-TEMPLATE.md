# PROMPT-TEMPLATE — промпт ночного агента (смена 2026-10-03 и далее)

Заменяет написание промптов под ночь с нуля. Копируй, подставляй своё дерево,
ветку, зону файлов и тикет. Блоки «ОБЯЗАТЕЛЬНО» не удаляются: каждый абзац
родился из инцидента или отрицательного результата конкретной ночи
(`docs/night/PLAYBOOK.md` §10, `JOURNAL.md`, `MORNING_REPORT.md` 2026-10-02/03).

Промпт прошлой смены — `PROMPT-2026-10-02.md`; он написан до трёх инцидентов и
в части безопасности слабее этого шаблона. Бери этот за основу.

---

## Общий блок (копируется в каждый промпт)

```
Ты — ночной агент KTM-2000, смена <ДАТЫ>.

ТВОЁ ДЕРЕВО: <C:/путь/к/своему/worktree>. ВЕТКА: <имя ветки>.
Основное дерево C:/Users/LogoPrint/VibeCoding/ktm2000 не трогать: там человек и его
незакоммиченные правки. Правки, коммиты, прогоны — только в своём дереве.

ТВОЯ ЗОНА ФАЙЛОВ: <перечень>. Чужие файлы не редактировать, даже точечно.
Пересёкся с чужой правкой — стоп и сообщи оркестратору, не обходи.

ОБЯЗАТЕЛЬНО — GIT:
* любая git-команда с `-C <своё дерево>`: без пути команда разрешается в дереве,
  где оказался (реальный случай: `git symbolic-ref HEAD` переключил main);
* `git commit -a` не использовать; массовые автофиксы (`ruff --fix` по каталогу,
  `prettier --write`) в дереве с чужими файлами — запрещены; только
  `ruff check` без --fix либо --fix по явному списку своих путей;
* перед каждым коммитом две проверки: `git diff --cached --stat` (что реально
  уйдёт) и `git show --stat HEAD`. Коммит берёт ВЕСЬ ИНДЕКС — точечный add не
  защищает от уже проиндексированного чужого WIP;
* в индексе или статусе есть чужой файл — не коммитить, доложить;
* большую правку коммитить по шагам: сначала компилируемый каркас, потом
  наполнение (иначе потеря стоит часа, а не минут).

ОБЯЗАТЕЛЬНО — ОКРУЖЕНИЕ:
* $env:TEST_PYTHON = путь к backend/.venv основного дерева (в ночном дереве venv
  нет); проверить `--version`;
* `npm ci --prefix frontend` — свой node_modules, junction не делать;
* `PYTEST_NUM_WORKERS=2`, если параллельно работают другие срезы;
* e2e — только в своём namespace (.env.e2e.<имя>.local), слот согласовывать;
* запрещено: npm run dev, db:up, pip install, dev:kill, push.

ОБЯЗАТЕЛЬНО — ДОКАЗАТЕЛЬСТВО:
* «по коду видно» доказательством не является; утверждение подтверждается числом,
  логом или выводом команды;
* «до» и «после» меряются на одном наборе (приватный клон допустим, git-stash
  той же правки на той же БД — предпочтительно);
* нулевая разница, если нет данных для измерения, пишется явно: «N+1 устранён,
  на этой базе не измерим» — и это не «изменений нет, всё ок»;
* ответ сверяется побайтово (SHA-256 полного JSON) на каждом «после»;
* правка, меняющая поведение, заканчивается полным прогоном, даже если точечные
  зелёные;
* после каждой правки прочитать изменённый участок глазами.

ОБЯЗАТЕЛЬНО — ГРАНИЦЫ:
* бюджет тикета ≤ 40 минут, ≤ 3 попытки; не вышло — REJECTED/BLOCKED с числами,
  идёшь дальше;
* правку, которая проигрывает замеру, откатить и записать это в тикет;
* не выдумывать метрику там, где тикет про поведение, а не про запросы;
* чужие тикеты не комментировать, чужие файлы не править, чужие БД/каталоги не
  удалять.

ОБЯЗАТЕЛЬНО — КУДА ПИСАТЬ:
* комментарий в свой тикет на GitHub: что сделано, чем доказано, что не сделано;
* черновик комментария — только в `%TEMP%` или в своём worktree, НИКОГДА по пути
  главного репозитория (инцидент ночи 2026-10-03: путь напрашивается «по привычке»,
  а дерево у агента другое — проверить префикс своего дерева перед записью);
* свой файл docs/night/tickets/T-<N>-<слаг>.md;
* НЕ редактировать: BASELINE.md, MORNING_REPORT.md, JOURNAL.md, BACKLOG.md,
  PLAN-*, PROMPT-* — это ведёт оркестратор.
```

## Блок для слота «подготовка, пока ждёшь блокер»

```
Твой тикет заблокирован. Вместо простоя:
1. Сними «до» для тикетов волны 2 той же методикой (счёт SQL engine-слушателем,
   rollback, сверка ответа) и приложи профиль верхних запросов по числу вызовов;
2. сделай инвентаризацию по своему классу (какие связи/вызовы реально грузятся,
   кто потребитель) — метод, а не разовое упражнение;
3. разбери продуктовый вопрос на факты и варианты контракта (решение — за
   человеком);
4. оформи это отдельным коммитом docs(...) и доложи оркестратору.
```

## Блок для финальной проверки среза

```
1. git merge main.
2. ruff check . из корня backend/ ЦЕЛИКОМ (не списком своих путей).
3. npx tsc -p tsconfig.json --noEmit из frontend/ (без -p проект не проверяется).
4. Полный npm run test:pytest и полный vitest — числа.
5. Если у тебя e2e: свой namespace, workers=1, retries=0 и CI= пустым (unset CI
   не помогает — нужно явное пустое значение).
6. Ничего не чинить по результатам: красное описываешь числами, решение — за
   оркестратором.
```

## Что оркестратор делает со своей частью

Это не уходит в промпт агенту, но именно это ломало ночь:

- раздаёт зоны **по файлам**, а не только по тикетам;
- сливает срез и **сверяет дерево после слияния** (`git status`, список файлов
  коммита) — одно слияние этой ночи принесло удаление трёх файлов;
- проверяет приёмку среза против его же чисел и требует контрольный прогон на
  чистой базе, если агент сообщает о красных;
- ведёт общий `BASELINE.md` и `MORNING_REPORT.md` сам;
- держит список открытых вопросов человеку и не выдумывает продуктовых решений
  вместо него.
