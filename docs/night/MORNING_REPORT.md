## Приёмка ADR-0055 (#244) — визуальная проверка на живом стенде

Проверено в браузере на dev-стенде (`:5172`, ГХП → «Склады»), не по коду:

1. **Две строки одного артикула — две группы остатка.** ALS1288, «Сверловка»: `1159 шт` без
   признака и `396 шт` с подписью «без операций» — ровно тот разъезд `NULL` ≠ `[]`, ради которого
   писался ADR-0055.
2. **Фильтр и сортировка по колонке «Операции».** Значения фильтра — `<button aria-pressed>`;
   нажатие `Enter` на сфокусированном значении переключает `aria-pressed` (проверено живой
   клавиатурой — тот самый путь, который unit-тесты happy-dom не разыгрывают); после фильтра
   «без операций» таблица сузилась до 7 строк, все с этой подписью; сортировка даёт
   `aria-sort="descending"` на соответствующем `<th>`.
3. **Списание из выбранной группы.** Диалог «Ручная операция» при типе «Расход (manual_out)»
   показывает блок «Группа операций» с двумя строками остатка
   (`Сверловка · 1,8 м — 1159 шт`, `без операций · 1,8 м — 396 шт`) и подсказкой
   «Списание идёт строго из выбранной группы»; запрос `/api/stock/balance?product_id=2&location_id=2&quality_state=good` — 200.
   Сама проводка не выполнялась (дев-БД человека не мутируем) — путь записи покрыт backend-тестом
   `test_write_off_touches_only_matching_operations_row` и e2e-фикстурами.

Остальные AC приёмки на итоговом `main`: полный backend-прогон — зелёный (**2005 passed**,
3 warnings), фронт — **1173 passed / 1 skipped** + `tsc --noEmit`, `ruff check backend` чисто,
`alembic heads` — один head, полный e2e `test:e2e` — **код 0, `status: passed`**
(19 passed; один флейк `sawing-four-lengths-cycle` прошёл с retry в прогоне под нагрузкой,
после чего ярус `ui-narrow` прогнан трижды с `--retries=0` — 3/3 зелёные). Дополнительно:
диалог корректировки проверил и путь **прихода** — безусловная опция «без операций» на месте (#266).
