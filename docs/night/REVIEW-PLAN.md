## Что делает срез ревью

1. Читает свои тикеты: `gh issue view <N>`.
2. Читает дифы своих коммитов.
3. Две оси: **Standards** (документированные правила репозитория + базовый
   список запахов Фаулера) и **Spec** (AC тикета против дифа).
4. **Лёгкое — чинит сам** в своём worktree, отдельный коммит.
5. **Сложное — не чинит**, пишет в отчёт с доказательством.
6. Комментарий в свои тикеты и файл `docs/night/tickets/R-<срез>.md`.

## Правила границ

- Своё дерево: `../ktm2000-rev-<NN>`, ветка `night/2026-10-03-r<NN>`.
- Все git-команды с `-C`. Точечный `git add`, перед коммитом
  `git diff --cached --stat` и `git show --stat HEAD`.
- `npm ci --prefix frontend` — только если правишь фронт и гоняешь тесты.
- e2e: свой namespace `.env.e2e.rev-<NN>.local`, `CI=''`, `--retries=0`,
  `workers=1`, `E2E_MAX_PARALLEL_RUNS=3`.
- Запрещены: `push`, `npm run dev`, `db:up`, `db:seed`, `pip install`,
  коммиты в чужой зоне, «проверочные» тесты, которые не могут упасть.
