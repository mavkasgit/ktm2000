# ADR-0072: Изоляцию тестовой БД держит Cleaner, а не тест

Дата: 2026-11-03. Статус: принято.

## Контекст

Изоляция жила в двух местах и в обоих по-разному. В `conftest.py` — «хорошая»
схема: схема на модуль, транзакция на тест, `commit()` кода под тестом
превращается в SAVEPOINT. В шести модулях — своя: `engine.connect()`,
закоммиченный `SET search_path`, собственная `async_sessionmaker` и уборка
руками, `DELETE` по списку таблиц в обратном порядке (`_cleanup`). Плюс два
костыля вокруг id (`_bump_user_sequence`, `ALTER TABLE users … RESTART WITH 1`),
два event-листенера `_pin_search_path` и третий движок в демо-сидере только
ради `server_settings`.

Цена: один вопрос «как вернуть базу к базовой линии» отвечался в десяти
местах. Список таблиц в `_cleanup` — копия топологии, которая устаревает
молча: новая FK-связь даёт падение не в том тесте, который её добавил, а в
соседнем, и только при определённом порядке.

## Решение

Один объект на тестовый пакет — `backend/tests/dbcleaner.py`, порт
[mokevnin/dbcleaner](https://github.com/mokevnin/dbcleaner) (Го-библиотека
делает то же для `database/sql`; здесь — для SQLAlchemy async).

- **`Cleaner`** владеет базовой линией (`setup`: схема, enum-типы,
  `create_all`, триггеры) и выдаёт сессии через `cleaner.session()` —
  аналог `cleaner.DB(t)`. Пакет не открывает транзакцию для изоляции и не
  пишет уборку.
- **Стратегия — по умолчанию `Transaction`.** Тест идёт в одной транзакции,
  которая откатывается; `commit()` кода под тестом становится SAVEPOINT,
  поэтому вложенные транзакции приложения работают.
- **`Truncation` — только там, где код под тестом ходит в базу своим
  соединением** (эндпоинт коммитит сам, гонка на двух пулах, `LISTEN/NOTIFY`).
  Тогда данные обязаны быть реально закоммичены, а после теста
  `TRUNCATE … RESTART IDENTITY CASCADE` возвращает и строки, и
  последовательности. `Deletion` — та же роль, когда `TRUNCATE` недоступен:
  после `DELETE` она сбрасывает последовательности удалённых таблиц, иначе
  `id` уезжают ровно так же, как до Cleaner'а.
- **`Null`** — для закоммиченного среза, который только читают (демо-сидер).
- **Guard на имя базы:** коммитящие стратегии отказываются работать, если в
  имени нет **токена** `test`/`e2e`/`scratch`. Сравнение именно по токену, а не
  по подстроке: `latest`, `contest` и `attest` содержат `test`, но это чужие
  базы, и промах DSN на них обязан останавливать уборку. Ослаблять guard
  нельзя — иначе промах DSN вычистит чужую базу.
- **`search_path` — на уровне соединения** (`server_settings`), а не `SET`
  внутри транзакции: `SET` откатывается вместе с тестом, а код под тестом
  коммитит и получает новое соединение (NullPool).
- **Своя схема на пакет** вместо сериализации: `-p 1` аналога нет,
  `--dist loadfile` разводит модули по воркерам, и каждый получает схему
  `t_<uuid8>`. Это `WithTemplate` из dbcleaner, только на уровне схемы.

Миграционные пакеты (`test_migrations.py`, `test_hanger_norm_key_migration_218.py`)
не переводятся: им нужна **своя база** на проверку (`ktm_mig_*`), чтобы
гонять alembic с нуля. Это `ScratchDatabase` из той же библиотеки, а не
изоляция транзакцией, и трогать её незачем.

## Последствия

- Тест, который трогает базу, берёт сессию у Cleaner'а и не открывает
  транзакцию руками. Правило записано в `AGENTS.md` и
  `backend/tests/AGENTS.md`; исключение — миграционные пакеты со своей базой
  `ktm_mig_*` (`ScratchDatabase`), и оно названо в обоих файлах.
- Уборка коммитящей стратегии не opt-in: её включает сама объявленная
  `DB_STRATEGY`, а не отдельный `pytest.mark.usefixtures("cleaner_reset")`.
- Уборка — одно выражение вместо списка таблиц; топология берётся из
  `Base.metadata.sorted_tables`, поэтому новая FK-связь не может «забыть»
  попасть в порядок удаления.
- Видимый минус: `Truncation` стоит ~36 мс на тест против ~3 мс у транзакции
  и растёт с числом таблиц. Поэтому она — исключение для пакетов с чужим
  соединением, а не общий случай. Замер полного набора до/после:
  2262 passed, 280.70 с → 277.92 с (разница в пределах шума).

## Альтернативы

- **Оставить как есть.** Работает, но список таблиц в `_cleanup` — вторая
  копия схемы, которую никто не сверяет с `Base.metadata`.
- **База на каждый тест** (`CREATE DATABASE … TEMPLATE`, testcontainers).
  Точнее всего и не нужно убирать, но ~78 мс на тест: на 2280 тестах это
  минуты, а не секунды.
- **Сессия-фикстура на каждый тест без Cleaner'а.** Так и было в
  `conftest.py`; проблема не в ней, а в шести модулях, которые её обходили.
