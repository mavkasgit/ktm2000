# ADR-0017: Нетто по причине — компенсация как общая способность ledger

Дата: 2026-08-12. Статус: принято.

## Контекст

Формула нетто-количества (активные минус компенсирующие транзакции) копировалась
в 4+ местах и разошлась для FINAL_RELEASE: в одном модуле существовали три
неконсистентных чтения одного понятия «уже выпущено» (gross, comp-excluded,
канонический net). Канонический примитив `_net_quantity_expr()` жил в
`stock/transfer_ledger.py` и был намеренно ограничен TRANSFER_SEND/RECEIVE.

## Решение

Компенсация — **общая способность ledger**, а не семантика только
TRANSFER_SEND/RECEIVE. Нетто по причине определяется так:

`net(reason) = Σ активных транзакций причины − Σ компенсирующих транзакций причины`

(транзакция компенсирует другую через `compensates_tx_id`; вычитается
компенсирующая запись, а не исключается скомпенсированная).

Capability и policy разделены явно:

- **Ledger** (модуль `stock/ledger.py`) определяет семантику компенсации и умеет
  вычислять net для **любой** причины через единственный публичный примитив
  `net_quantity_expr()`.
- **Решение о том, какие причины бизнес-операция вправе компенсировать,
  принадлежит этой операции, а не ledger.** Сегодня компенсируемы только
  передачи (`cancel_transfer`); FINAL_RELEASE читается по net-семантике, потому
  что домен уже требует компенсационного поведения.

COMPLETE/SCRAP остаются gross **не потому, что ledger не поддерживает их net**, а
потому что в текущем доменном контракте для них нет требования компенсационного
поведения.

## Рассмотренные альтернативы

- **Reason-restricted примитив** (SEND/RECEIVE-only): оставляет копии формулы и
  провоцирует следующую дивергенцию.
- **Превентивный net для COMPLETE/SCRAP**: расширяет behavioural surface без
  требования со стороны домена, меняет поведение без возможности проверить.

## Последствия

- Единственная реализация компенсационной арифметики — `net_quantity_expr()`;
  ни один consumer не интерпретирует `compensates_tx_id` для вычисления net.
- Появление capability **не означает** автоматический переход всех потребителей
  на net: переход происходит там, где домен требует, и остаётся доменным
  решением.
- Будущие компенсации (например, отмена выпуска) получают net-поддержку в
  ledger бесплатно; конкретные чтения переводятся на примитив точечно.
- Модуль `stock/transfer_ledger.py` переименован в `stock/ledger.py`; alias не
  оставлен.
