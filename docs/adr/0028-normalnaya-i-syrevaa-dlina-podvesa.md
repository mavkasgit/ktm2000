# ADR-0028: Нормальная и сырьевая длины для расчёта подвеса

Дата: 2026-09-24. Статус: принято (гриллинг).
Связанные: ADR-0001, ADR-0002, ADR-0003, ADR-0012, ADR-0013, ADR-0023;
заменяет ADR-0024.

## Контекст

Длина 2700 мм не является универсальной: у каждого артикула есть собственные нормальные длины. Дополнительная физическая длина нужна только для расчёта количества на подвесе; материализовать её в плане, остатках, заданиях или ledger нельзя. ADR-0024 подменял нормальную длину плана на 2750 мм, из-за чего сырьевая длина распространялась на всё движение и конфликтовала с новым правилом.

## Решение

1. **Единственный реестр нормальных длин** линейного артикула — записи
   этого реестра; отдельное общее значение длины не используется. У каждой
   записи есть необязательное поле `raw_length_mm`: сырьевая длина не меньше
   нормальной; если она не задана, эффективная сырьевая длина равна текущей
   нормальной. При увеличении нормальной длины поверх явного сырьевого
   значения поле очищается.
2. **Сырьевая длина — только параметр подвеса.** Авторасчёт одиночного профиля
   и пары использует эффективную сырьевую длину в формуле площади. Ручное
   количество `N` хранится по нормальной длине и не сбрасывается при изменении
   сырьевой длины. В таблице подвесов показываются обе длины, в остальных
   представлениях — только нормальная; поиск в подвесах работает по обеим.
3. **Пара:** кандидаты — пересечение нормальных длин A и B. Автоматический
   расчёт для длины возможен только при равных эффективных сырьевых длинах A и B;
   несовпадение блокирует только эту длину в автоматическом режиме, ручное `N`
   по общей нормальной длине продолжает работать.
4. **План и учёт:** длина из Excel остаётся нормальной и переносится в
   PlanPosition/WorkTask/ledger без подстановки и без «ближайшей сверху».
   Неизвестная нормальная длина — ошибка только для затронутой позиции;
   рассчитанное N фиксируется снимком импорта и не меняется при последующем
   изменении карточки. На пиле используется нормальная длина; отдельная длина
   2750 и 50 мм торцовки в ledger не материализуются.
5. **Каталог и Excel:** сырьевая длина хранится в карточке каждой нормальной
   длины и переносится параллельным списком в Excel. Пустой сегмент означает
   fallback, отсутствие всей колонки при частичном обновлении сохраняет
   существующие значения, а предоставленный список заменяется целиком после
   проверки числа сегментов.
6. **Миграция без угадывания:** старый общий `length_mm` автоматически
   переносится в единственную запись реестра; старый
   `product_dimensions.default_value` удаляется при совпадении, а конфликт
   требует ручного разрешения. Старые планы переимпортируются и до этого
   доступны только для чтения; остатки переоцениваются штатными операциями.
   Старые API-поля линейных артикулов удаляются после миграции.
7. **Область действия:** поле сырьевой длины и правила её использования
   применяются только к линейным артикулам; листы и объёмные изделия
   сохраняют отдельную размерную модель.

## Последствия

- `ProductLength` получает необязательное поле сырьевой длины; все потребители
  переводятся на реестр, без двойной записи и скрытых совместимых полей.
- Удаляются материализация `raw_length` и правило «ближайшая сверху» из импорта
  плана; ошибки неизвестной нормальной длины и несовпадения сырьевых длин
  становятся позиционными ошибками или ошибками отдельной длины, а не
  предупреждениями о подмене.
- Старую ADR-0024 и её кодовые последствия нельзя сохранять как альтернативный путь: изменение выполняется чистым cutover с миграцией и переимпортом.
