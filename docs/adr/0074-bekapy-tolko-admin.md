# ADR-0074: Ручки бэкапов — только admin, гейт на роутере

Дата: 2026-11-18. Статус: принято.

## Контекст

`backend/app/api/backups.py` держал заглушку:

```python
def _validate_admin(current_user: str = "admin") -> None:
    ...
```

Проверка проходила всегда, а «пользователь» приходил query-параметром, который
клиент подменял. Любой, кто дотягивался до `/api/backups`, мог создать и удалить
бэкап, восстановить БД и скачать файл из каталога бэкапов (path traversal в
скачивании закрыт отдельно, но авторизации не было вовсе).

Цена ошибки здесь выше, чем в справочниках: restore перезаписывает диск
приложения (`database.dump` + `data/…`), а скачивание отдаёт полный дамп базы.

## Решение

- **Политика — `admin`.** Бэкап читает и перезаписывает весь диск приложения,
  поэтому набор ролей не «писатели справочников», а один администратор.
- **Гейт висит на роутере**, а не на каждой ручке:
  `APIRouter(prefix="/backups", dependencies=[Depends(require_role([UserRole.admin]))])`.
  Это не стилистика: ручек 16, и новая, добавленная без `Depends`, была бы
  открытой. Тест-матрица (`backend/tests/test_backups_auth.py`) сверяет обход
  маршрутов с таблицей ожидаемых гейтов в обе стороны, поэтому пропуск или
  ослабление набора валит прогон.
- **Заглушка удалена**, а не переписана на `require_role` внутри: вызов,
  который можно забыть, — это тот же класс дефекта, что и заглушка.
- **Dev/e2e-стенд не получает отдельного флага.** Он работает через общий
  `DEV_BYPASS_AUTH` в `get_current_user` (магия `Bearer admin` / `system@local`).
  Второй флаг означал бы вторую точку, где «авторизация выключена», и стенд,
  который проходит бэкап-сценарии при выключенном первом.
- **Фронт скачивает бэкап через `apiClient` + `saveBlobAsFile`** (ADR-0052 п.9),
  а не `window.open`: ссылка уводит браузер в навигацию без `Authorization`,
  и пользователь видит JSON `401`. Раздел `/settings/backups` и его карточка
  закрыты тем же admin-гейтом (`POLICIES.editSettings`).

## Последствия

- Роль без `admin` больше не видит раздел и получает `403` на API — это
  ожидаемое поведение, а не регресс: до правки раздел был виден всем, а ручки
  «только для админа» были обманкой.
- Скачивание идёт через blob: файл приходит целиком в память вкладки. Дамп
  бывает сотни мегабайт, но браузер и раньше скачивал его одним потоком;
  отличие — заголовок авторизации теперь есть.
- `restore` и `upload-restore` по-прежнему восстанавливают текущую БД: гейт
  роли не заменяет подтверждение именем базы (`db_name` в теле), а дополняет
  его.

## Альтернативы

- **`REFERENCES_WRITER_ROLES` (admin, planner, section_manager).** Шире, чем
  нужно: восстановление БД — операция над всей системой, а не правка
  справочника; у planner и section_manager нет раздела настроек.
- **`Depends(require_role(...))` в каждой ручке.** Работает ровно до первой
  новой ручки без гейта. Матрица в тесте ловит пропуск, но лучше, когда
  открытой ручки нельзя создать по умолчанию.
- **Токен/пароль в query-параметре.** Уходит в логи прокси и историю браузера;
  заголовок `Authorization` уже есть у клиента и проверяется `get_current_user`.
