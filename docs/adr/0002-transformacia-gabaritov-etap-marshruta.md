# ADR-0002: Трансформация габаритов — способность этапа маршрута

Дата: 2026-07-30. Статус: принято.

## Контекст

Участок пилы (SAWING) режет заготовки: 100 шт × 2,7 м → 100 × 0,9 м +
100 × 1,8 м. Завтра то же самое может делать гильотина или фрезеровка.
SKU при резке **не меняется** — меняются только dimensions.

## Решение

1. **Трансформация — маркер этапа маршрута / операции**, не хардкод
   `if section == "SAWING"`. Любой этап может быть объявлен трансформирующим.
2. **Модель операции**: задание несёт вход и выходы:
   - вход: `input_quantity` × `input_dimensions` (из плана);
   - выходы: список `(quantity, dimensions)` — 1..N позиций.
3. **Атомарное движение ledger при завершении** (полном или частичном):
   - списание входа: N шт × `{"length_mm": 2700}`;
   - приход всех выходов: N шт × `{"length_mm": 900}` + N шт ×
     `{"length_mm": 1800}` (годный остаток — автоматически, всегда).
   Штуки входа/выхода не обязаны совпадать (из 1 заготовки — 3 куска).
4. **Годный остаток — не отход**: недоиспользованная длина всегда приходуется
   как полноценный остаток (излишек, если её не ждёт ни одна позиция плана).
   Пропил игнорируется, отдельного учёта отходов нет.
5. **Одна позиция плана → одно задание → одна карточка** на доске
   трансформирующего участка. Поскольку позиция плана — это группа
   строк Excel с общим входом (ADR-0003, п. 1), карточка показывает
   всю операцию целиком: «150 × 2,7 → 150 × 0,9 + 150 × 1,8».
   Вход списывается один раз, все выходы приходуются вместе —
   эвристическая склейка по SKU не нужна: группировку задаёт сам файл.
6. **Частичное выполнение**: оператор вводит факт порциями; каждая порция —
   отдельное атомарное движение (п. 3) пропорционально введённому количеству.

## Отклонённые альтернативы

- **CuttingPattern (карта раскроя)** — избыточно: план уже сбалансирован,
  вход/выходы заданы группой строк, оптимизацию раскроя система не делает.
- **Отдельная карточка на каждый выход** (первоначальная редакция этого
  ADR) — отклонено после разбора реального файла: две карточки с общим
  входом либо списывают его дважды, либо требуют скрытой зависимости
  между ними; физически это одна операция резки.
- **Автогруппировка позиций по SKU при генерации заданий** — не нужна:
  границы операции уже зафиксированы группой строк в файле плана.

## Последствия

- `WorkTask` получает `input_dimensions` и выходную спецификацию
  (`outputs: [(qty, dimensions)]`) из позиции плана.
- Секции без трансформации «проносят» dimensions без изменений
  (списали и приходовали один и тот же габарит).
- Сид участка SAWING: пометить этап/операции как трансформирующие.
