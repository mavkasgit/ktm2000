# 0023. Упразднение техкарт — продукт как единый справочник

Техкарты (`Techcard`/`TechcardLine`) совмещали три несвязанные роли: gate валидации плана
(«активная ТК с ≥1 строкой существует» — состав при этом не читался), состав продукта
(`TechcardLine`) и нормы подвеса (одиночные уже мигрированы на `Product.attributes` по
ADR-0012, парные оставались). Решение: техкарты упраздняются целиком; состав («компонент +
количество») переезжает на `Product`, парные профили — в таблицу `product_pairs` между
сырьевыми артикулами с ручной N по длинам на связи; план валидируется без техкартного gate.
Детальные решения — тикеты #141 (модель пары) и #142 (план) карты
[wayfinder «Страница Продукты»](https://github.com/mavkasgit/ktm2000/issues/138).

## Considered Options

- **Оставить техкарты, страница «Продукты» только отображает состав** — отклонено: состав
  одиночных техкарт мёртв в рантайме (никто не читает `TechcardLine` вне CRUD/парного
  резолва), двойная модель «состав в ТК + нормы на Product» путает владельцев данных.
- **Поле-партнёр `pair_partner_id` на Product** — отклонено: пара симметрична по природе
  (инвариант `N×A + N×B`), хранение отношения в одной из двух строк создаёт «владельца»
  и расходимость при редактировании.
- **Пара как продукт-комплект со своим SKU** — отклонено (решение заказчика): подвес и пары
  не должны жить на ГП-продукте; комплект потребовал бы «взрыва» на компоненты в плане,
  складе и ledger при том, что пара и так ведёт себя как один артикул в плане (глоссарий
  «Пара (артикул A+B)»).

## Решение

1. **Состав — на Product** (аналог BoM, как в Odoo/SAP: связь отдельно от карточки).
   Отображается на странице «Продукты»; редактируется там, где решит спека (#143/#145).
2. **Пара — `product_pairs`**: `product_a_id`/`product_b_id` (канонический порядок a<b,
   уникальность неупорядоченной пары), ручная N — JSONB `{length_mm: {auto, manual}}` на
   строке пары, зеркально одиночным нормам ADR-0012. **Несколько пар на артикул разрешены**;
   режим пары выведенный (авто, только если оба артикула `auto` на этой длине); длины пары =
   пересечение длин A и B. Формулы авторасчёта не меняются (глоссарий «Подвес»).
3. **Создание/редактирование пар — в CatalogForm сырьевого артикула**, симметрично,
   без владельца записи. Отдельного справочника пар нет.
4. **Целостность**: артикул, состоящий в паре, нельзя удалить/деактивировать до разрыва пары.
5. **План без техкарт**: gate «активная техкарта» удалён (валидация = продукт найден,
   активен, маршрут валиден); пара при импорте резолвится прямым поиском `product_pairs` по
   точной неупорядоченной паре SKU (не найдена → `product_pair_not_found`), резолв имеет
   одного владельца-модуль; N пары при импорте — из нормы пары (manual) или движка
   (`min(by_area, by_size)`); эффективный продукт парной позиции — `product_a`.
6. **Снапшот = норматив позиции**: позиция с записанным снапшотом пары не ревалидирует пару
   и нормы; справочник меняется — импортированный план не переинтерпретируется (прецедент —
   копия BOM+routing в production order в SAP). Payload-ключ — `product_pair` (поправка T2,
   #171): верхнеуровневые `quantity_per_hanger`/`source`, структура `inputs[]` сохранена
   (в элементе — `quantity_per_hanger` вместо `techcard_quantity`; читатели
   `ImportDiffTable`, `PlanHangerDisplay`).
7. **Чистый лист**: реальных данных в системе нет — миграции данных не проводятся.

## Consequences

- Точки кода к переписыванию (реализация — вне карты wayfinder): `plan_import_service.py`
  (резолв пары, N, payload), `plan_validation.py` (gate, резолв), `plan_generation.py`
  (effective product, `_validate_active_techcard`), `production_planning_rows.py` /
  `production_planning.py` (effective product), `products.py` (флаги `has_*_techcard`,
  каскадное удаление), `HangerCalcTable`/`hangerCalcRows.resolvePairs` (pairs-API);
  `TechcardsPage`, роутер techcards и модели `Techcard`/`TechcardLine` удаляются.
- Флаг `is_paired_profile` становится выведенным (у артикула есть пары).
- Мёртвые поля техкарт (`version`, `quantity_total`, `hangers_a/b/total`) не переносятся.
- Словарные правки глоссария («парная техкарта» исчезает, «пара» = отношение в
  `product_pairs`) — отдельно, после освобождения `CONTEXT.md` от чужих правок.
