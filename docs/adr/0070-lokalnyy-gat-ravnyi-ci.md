# ADR-0070: Локальный гейт = CI, а не его пересказ

Дата: 2026-11-03. Статус: принято.

## Контекст

До 2026-11-02 проверки, которые решают судьбу merge, жили только в шести
workflow. Локально их надо было вспоминать руками: `npm run check:docs`,
`npx tsc -b`, `ruff check backend`, `alembic check`, `npm run lint`, pytest,
vitest. Замер M2 в `docs/night/BASELINE.md`: **0 из 14** проверок CI были
доступны одной командой, и агент, решавший «пушить или нет», опирался на
память, а не на факт. Отсюда два класса аварий, которые волна и закрывает:
проверка не запущена вовсе («забыли») и проверка запущена, но её красный ход
никто никогда не видел («молчит и потому кажется зелёной»).

Донор (`mokevnin/dev-quality-gates`, `mise.toml`) предлагал готовый набор
задач в `mise`. Протирали на нашем стеке (критерии —
`docs/quality/criteria.md`) и отвергли как основу: у проекта уже есть
npm-скрипты, PowerShell-launcher для изоляции БД и Windows-машина, где
`mise` — четвёртый менеджер окружения ради одной функции. Полезное взяли:
единую точку входа, ярусы по бюджету времени и правило «инструмент обязан
быть виден в реестре».

## Решение

1. **Одна точка входа.** `npm run gate` (`scripts/gate.mjs`) — единственный
   способ запросить «пройдёт ли этот код». Ярусы: `gate:fast` (бюджет 60 с,
   перед коммитом), `gate` (полный, перед пушем), `gate:e2e` (отдельный,
   потому что берёт слот машинного семафора). Статусы шага: `ok`, `fail`,
   `missing`, `not-run`, `warn`.
2. **Карта проверок — единственный список того, что проверяется.**
   `docs/quality/gates.md` перечисляет шаги вместе с ярусом, CI-адресом и
   ссылкой на доказанный красный ход. Шаг `reconcile` сверяет имена из карты
   со списком `STEPS` в `scripts/gate.mjs`: расходится — гейт красный.
   Добавить проверку без записи в карту невозможно.
3. **Красный ход обязателен.** `scripts/prove-checks.mjs` ломает вход каждой
   проверки намеренно (свой файл, правка, touch) и требует, чтобы шаг
   покраснел с ожидаемым текстом; результат — `docs/quality/proven-checks.json`
   с датой. Шаг `prove-coverage` требует, чтобы у каждого шага карты запись
   была; исключения перечислены явно с причиной: `alembic-drift` и `e2e-smoke`,
   которые локально не запускаются как шаги гейта, и `test-hygiene`, который
   печатает находки, но возвращает 0 — краснеть ему не на чем. Проверка,
   которую не видели красной, не считается существующей.
4. **Хуки — удобство, а не сила.** `lefthook.yml` запускает подмножество
   гейта по staged-путям (pre-commit) и `gate:fast` (pre-push). Сила — в CI:
   обход хука (`--no-verify`) не отменяет required check. Поэтому правило:
   проверка, живущая только в хуке, не считается включённой в проект.
5. **Версии инструментов — из реестра, а не из литералов.** `tools.json` (в корне репозитория)
   хранит «чем проверяем, где запускается, какой пин»; `.nvmrc`,
   `.python-version` и `backend/requirements-dev.txt` — источники, которые
   читают и CI, и локальный гейт (шаги `pins`, `registry`);
   `docs/toolchain.md` генерируется из реестра и руками не правится.

## Что это стоит

- **Локально дороже, чем кажется.** Полный ярус в тишине — 445.95 с из 19
  шагов (артефакт `docs/night/baseline/gate-full-quiet.json`, разбирается в
  `docs/night/BASELINE.md`): сопоставимо с самым длинным CI-джобом (537 с),
  хотя в CI четыре среза идут параллельно, а локально все ядра заняты одним
  прогоном. Под нагрузкой четырёх параллельных сессий тот же ярус давал
  551.7 с. Ценность не в скорости, а в том, что вердикт приходит до пуша и до
  чужого ревью.
- **Новый шаг требует четырёх мест**: `STEPS`, строка в карте, адрес в CI,
  пробник. Это рутину превращает в защиту: `reconcile` и `prove-coverage`
  ловят любое из четырёх пропусков.
- **`--strict` меняет смысл warn'ов.** `codegraph-age` без `--strict` только
  предупреждает (свежесть индекса — не дефект кода), в CI и в хуках тот же
  шаг красный. Разница объясняется в карте, а не в коде шага.

## Альтернативы, от которых отказались

- **Только git-hooks (husky).** Проверка существует ровно столько, сколько
  стоит хук на машине: свежий clone без `npm run prepare` не проверяет ничего.
  Противоречит п.4.
- **`mise tasks` как раннер.** Четвёртый менеджер окружения ради синтаксиса
  задач; наш launcher (`scripts/test-run.ps1`) владеет жизненным циклом run-DB
  и в `mise` не переносится без дублирования. Записано в
  `docs/quality/not-adopted.md`.
- **Повторить CI-логий в локальном скрипте.** Расхождение началось бы через
  неделю: два описания одного набора проверок. Поэтому карта + `reconcile`
  вместо второго списка.

## Последствия для агента

Решение «пушить или нет» принимается по выводу `npm run gate` (`--strict`
там, где CI строгий), а не по здоровью отдельно запущенного теста. Если шаг
красный и его невозможно починить — он либо нужен в карте с объяснением, либо
не нужен вовсе; «оставим красным и пусть CI разберётся» теперь не вариант,
потому что тот же шаг стоит в required check.
