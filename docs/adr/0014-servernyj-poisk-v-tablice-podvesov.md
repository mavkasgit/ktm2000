# ADR-0014: Серверный поиск в таблице «Расчёт подвесов»

Дата: 2026-08-09. Статус: принято.

## Контекст

Таблица «Расчёт подвесов» (HangerCalcTable) загружает все артикулы сырья
одним запросом `limit=2000` (спека #64 п.20) и делает поиск/фильтры/
сортировку **клиентски** (п.21). Клиентские фильтры работают только по
загруженному набору: при каталоге >2000 артикулов поиск не находит то,
что не влезло в лимит — обрезка теряет данные, а warning-баннер лишь
сообщает об этом. Размер каталога не гарантирован («кто ж знает сколько
достаточно»), поэтому лимит не может быть внутренним ограничением,
теряющим данные.

## Решение

Поиск/фильтры/сортировка таблицы переводятся на серверный режим (как в
основной таблице сырья `RawMaterialsPage`): `q`, колоночные фильтры,
`sort` через `listProductsPaginated`. `limit=2000` остаётся только как
максимальная выгрузка для batch-расчёта, а не как граница доступности.
Осознанное отклонение от спеки #64 п.21 (клиентские фильтры).

## Отклонённые альтернативы

- **Оставить клиентский режим с warning** — дешево, но при каталоге
  >2000 поиск бессилен (то, что ревью назвало «молчаливым обрезанием»).
- **Кнопка «показать ещё» (offset)** — не решает: клиентский поиск всё
  равно не видит недогруженное без поиска по всем данным.

## Последствия

- Инфраструктура серверного поиска уже есть в проекте (та же, что в
  `RawMaterialsPage`); переключение HangerCalcTable на неё — переиспользование,
  не новая подсистема.
- Batch-расчёт по-прежнему оперирует выгруженным набором; лимит 2000 —
  параметр выгрузки, а не семантика доступности.
