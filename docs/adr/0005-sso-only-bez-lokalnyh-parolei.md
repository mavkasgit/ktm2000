# ADR-0005: SSO-only — без локальных паролей

Дата: 2026-08-03. Статус: принято.

## Контекст

Исторически KTM-2000 несла полный локальный парольный стек: колонка
`users.password_hash`, хэширование (passlib/pbkdf2_sha256), эндпоинты
`POST /api/auth/login` и `reset-password`, OTP-флоу с `setup-password`
(единственный боевой писатель хэшей) и парольные сиды.

После внедрения OIDC-моста с Authentik этот стек стал мёртвым грузом:

- Вход в продакшене — только единый вход (Authentik); парольный логин уже
  отдавал 403, OTP-флоу не имел потребителей в UI.
- Две системы учёта аккаунтов (локальная + IdP) создают рассинхрон:
  пароли в БД никто не ротировал, JIT-записи создавались с пустым хэшем.
- Парольное хранилище — поверхность атаки (кража дампа, подбор) при нулевой
  пользе: реального парольного входа не существует.

## Решение

Приложение — **SSO-only relying party**:

1. **Аутентификация — только Authentik (OIDC Authorization Code + PKCE).**
   Локальных паролей нет: колонка `users.password_hash` удалена миграцией
   `029_drop_users_password_hash`, хэширование/верификация (`get_password_hash`,
   `verify_password`, passlib) удалены из кода, эндпоинты `/auth/login`,
   `reset-password` и все `/auth/otp/*` удалены (404).
2. **Локальные записи пользователей создаются JIT** при первом успешном
   OIDC-входе (`OidcAuthService._resolve_user`): из claims берутся username,
   email, full_name, роль (`ktm_role`), ссылка `authentik_sub`. Никаких
   парольных данных запись не несёт.
3. **Break-glass — единственный непарольный-в-БД аварийный вход.** Проверка
   идёт по env-конфигу (`BREAK_GLASS_ENABLED`/`BREAK_GLASS_USER`/
   `BREAK_GLASS_PASSWORD[_HASH]`), таблица `users` не трогается; выдаётся
   короткоживущий JWT с claim `is_break_glass`. Назначение — доступ при
   недоступном Authentik, не повседневный вход.
4. **Сиды не создают пароли**: обязательные пользователи (`system`, `akadmin`,
   `admin`) создаются без парольных полей; `admin` остаётся как локальная
   запись для администрирования и связки с break-glass-аудитом.
5. **Сессии**: `login_method` сужен до `{"oidc"}`; исторические строки
   `user_sessions` с удалёнными методами остаются как данные аудита.

## Последствия и rationale

- Положительные: одна точка управления жизненным циклом аккаунтов (Authentik:
  provisioning, MFA, блокировки, ротация); нет секретов пользователей в нашей
  БД; меньше кода (удалены OTP-флоу, парольные эндпоинты, хэширование).
- Отрицательные/принятые риски: при недоступном Authentik вход только через
  break-glass (осознанный trade-off, см. п. 3); downgrade миграции не
  восстанавливает хэши (данные осознанно потеряны).
- Зависимости: `bcrypt` остаётся только для опционального
  `BREAK_GLASS_PASSWORD_HASH`; `passlib` удалён из requirements.

## Связанные изменения

- #27 — удаление OTP-флоу (коммит `1d2b21f`).
- #28 — удаление парольного хранилища и верификации, миграция 029.
