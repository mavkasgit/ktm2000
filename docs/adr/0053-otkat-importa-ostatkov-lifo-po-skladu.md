# ADR-0053: LIFO отката импорта остатков — по складу, а не глобально

Дата: 2026-09-30
Статус: принято (гриллинг, развитие ADR-0025)
Контекст: ADR-0052 п.3; сверка с кодом (`app/reversal/stock_compensator.py`,
`app/stock/import_service.py`), разбор `clear_existing`
Связанные: ADR-0019, ADR-0021, ADR-0025, ADR-0052

## Контекст

ADR-0025 ввёл LIFO-откат батча импорта плана: откатывать можно только
последний применённый. Правило выводится из того, что батч плана пишет
`PlanPosition` с состояниями (`draft` → `released`), и откат не-последнего
восстановил бы `before_data` поверх более поздних правок.

У импорта остатков такой зависимости между батчами **нет**, кроме одного
случая. `apply_remainders_import` при `clear_existing=True` сперва гасит
баланс по `(location_id, quality_state)` проводками `ADJUSTMENT_OUT`, затем
заливает `MANUAL_IN`. Откат зеркалит обе фазы, поэтому два батча с очисткой,
применённые к одному складу, **зависят**: A(гашение 100 + заливка 250), затем
B(гашение 250 + заливка 40). Откат A после B даёт 150 шт — состояние,
которого на складе не было никогда, и которое не соответствует ни одному
моменту времени.

## Решение

1. **Область LIFO — `location_id`.** Откат доступен только у последнего
   батча, залитого на этот склад. Импорты, залитые на другие склады, не
   делают батч неоткатываемым.
2. **Глобальный LIFO отвергнут:** два склада, импорт утром на оба — откат
   был бы доступен только одному из них, и второй пришлось бы «не считать».
3. **Сужение до `(склад, качество)` отвергнуто.** `clear_existing` гасит по
   паре, но компенсация `MANUAL_IN` зеркалит `to_quality_state`; правило «не
   последний по складу» уже закрывает ту же дыру, а лишнее измерение даёт
   правило, которое надо отдельно объяснять и отдельно отлаживать.
4. **Правило — UI-гейт, как в ADR-0025 п.2.** У последнего батча кнопка
   активна, у остальных disabled с тултипом. Бэкенд-гейта не заводим:
   повторная проверка «последний ли ты» на сервере потребовала бы третьего
   эндпоинта ради правила, которое оператор и так видит на экране.
   Плата та же, что принята в ADR-0025: клиент, игнорирующий правило, может
   откатить не последний батч.
5. **Действующий блокер на сервере один — покрытие.** Если материал после
   импорта израсходован, `MirrorLedgerMixin._deficit_for` возвращает
   дефицит, и откат падает с `CoverageShortfall` (ADR-0019 п.8). Это гейт по
   состоянию склада, а не по порядку батчей, — он остаётся обязательным
   независимо от LIFO.

## Последствия

- Старые батчи одного склада не откатываются, пока не откатан более новый.
  Это осознанно: альтернатива — остаток, которого не было.
- Бэкфилл-строки (ADR-0052 п.7) упорядочены по `Action.id`; LIFO по складу
  считается от него, порядок восстановим.
- Откат батча склада A никак не влияет на списки и кнопки склада B.
