# ADR-0078: Фото и чертёж артикула — три изображения, чертёж в приоритете

Дата: 2026-11-26. Статус: принято.
Источник: [#463](https://github.com/mavkasgit/ktm2000/issues/463) (слот чертежа,
разметка изображений, сверка размеров).
Связанные: ADR-0073 (группа эквивалентов), ADR-0023 (Product как единый
справочник), ADR-0012 (`Product.code`).
Глоссарий: «Чертёж», «Плакат», «Фото изделия», «Чертёж алиаса».

## Контекст

У `Product` два поля изображений — `photo_thumb` и `photo_full` — и оба названы
«фото». По факту в них лежит всё подряд: у 188 артикулов прод-каталога
изображения есть, и это вперемешку чертежи со штампом и периметром (например,
`АТ-4863` — P=90,53; `ЮП-2413` — P=126,9), каталожные плакаты и снимки изделий.
Что именно на картинке, нигде не записано, поэтому ни человек, ни агент не может
ответить на вопрос «можно ли верить размерам на этом изображении».

При этом роли у изображений разные. Чертёж — единственный источник истины по
геометрии профиля: по нему сверяют периметр, габарит и толщину. Фото — про
узнаваемость: в списке артикулов нужно видеть изделие, а не чертёжную рамку со
штампом. Одно поле не может обслуживать обе роли: если положить чертёж в
`photo_full`, список теряет узнаваемость, а если оставить фото — размеры
недоказуемы.

Отдельно: у эквивалентных артикулов бывает один товар в разных изданиях с разными
размерами (`325` — 26×8 против `ЮП-2910` — 23,2×8,5), поэтому «взять чертёж у
алиаса» — законный, но не всегда верный ход, и его нельзя делать незаметно.

## Решение

- **Три слота на артикул.** `photo_thumb` — малое фото для списков,
  `photo_full` — каталожное фото изделия, `drawing_full` — новое поле под чертёж.
  Храним три изображения, показываем два: список берёт `thumb`, полный просмотр —
  фото или чертёж.
- **Чертёж в приоритете.** В полном просмотре переключатель «чертёж / фото», по
  умолчанию открывается чертёж. Порядок отражает роль: сначала доказательство,
  потом узнаваемость.
- **Плакат занимает слот чертежа**, пока настоящего чертежа нет. Появление
  чертежа вытесняет плакат из слота; плакат остаётся в реестре как источник для
  тех артикулов, у кого чертежа нет вовсе.
- **Изображение алиаса помечается.** `visual_origin=own|alias` и бейдж «чертёж
  алиаса» в карточке. Пометка — не косметика: она говорит, что размеры надо
  сверить с текущим артикулом.
- **Разметка — вход, реестр — выход.** Классификация (`drawing` / `plakat` /
  `photo` / `none`), происхождение и доказательство живут в
  `docs/catalog/visual-truth.csv`; `npm run docs:profiles` выводит из него
  колонки в реестр. Ручные решения переживают пересборку, а сам реестр остаётся
  генерируемым.
- **Две страницы обзора — артефакт, а не документ.** `npm run docs:reviews`
  собирает `data/reviews/`: `visual-review.html` (216 карточек с превью,
  фильтры по виду и происхождению, переключение превью «чертёж / плакат-фото»,
  пробелы, расхождения) и `skipped-review.html` (реестр исключений ОСВ). Обе
  страницы генерируются из источников — разметки, прод-БД и storage; руками не
  правятся. Один модуль на страницу (`scripts/reviews/visual.py`, `skipped.py`) и
  общий шаблон (`template.py`), поэтому вид и фильтры у страниц совпадают.
  Переключатель превью показывает те же два слота, что и карточка в UI: это
  репетиция пилота, а не альтернативная модель.
- **Сверка размеров обязательна.** С чертежа читаются периметр и габарит и
  сравниваются с БД; расхождение — отдельный разбор у заказчика, а не тихая
  правка ни в изображении, ни в карточке.
- **Проверка перед коммитом, не в CI.** `npm run docs:reviews:check` падает,
  если у артикула в карточке есть изображение, которого нет в разметке, файл
  пропал из storage, разметка ссылается на несуществующий артикул или реестр
  перекрывает каталог. Шаг локальный: источник — прод-БД и storage, в CI их
  нет, поэтому в гейт он не подключён и запускается перед коммитом руками.

## Последствия

- Миграция добавляет nullable-поле `drawing_full`; существующие карточки
  остаются валидными, бэкфилл не нужен — слот заполняется по мере разметки.
- В списках ничего не меняется: там по-прежнему фото. Меняется только полный
  просмотр.
- Появляется постоянная обязанность: изображение без записи в
  `visual-truth.csv` — это дефект, а не «просто картинка». Держится
  `npm run docs:reviews:check`.
- 28 артикулов без изображений остаются пустыми сознательно: заглушка
  маскировала бы пробел, а список пробелов идёт в заявку на съёмку.
- Разметка 188 существующих изображений — разовая работа глазами; повторный
  прогон только проверяет наличие файлов и не переоценивает вердикты.

## Альтернативы

- **Одного поля достаточно** — нет: чертёж вытесняет фото, список теряет
  узнаваемость; фото вместо чертежа оставляет размеры недоказуемыми.
- **Отдельная таблица изображений (галерея)** — гибко, но у артикула ровно три
  роли, и четвёртая не просматривается; лишняя сущность и лишние связи на 216
  строк.
- **Хранить только ссылки на архив `Чертежи`** — не годится: там сырьё (83 PDF на
  124 файла, сканы без кадрирования), показывать его в карточке нельзя.
- **Размечать автоматически по имени файла** — не работает: чертежи и фото лежат
  под одинаковыми именами (`*_full.jpg`), признак «есть размеры» машинно не
  выводится.
