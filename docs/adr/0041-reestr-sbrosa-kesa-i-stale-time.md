# Реестр сброса кэша и короткий staleTime

Свежесть данных на экранах обеспечивается одним реестром в
`frontend/src/shared/api/cacheInvalidation.ts`: бизнес-действие однозначно
задаёт, какие домены query-кэша нужно сбросить, а глобальный `staleTime`
опущен с пяти минут до трёх секунд. Раньше каждый экран вызывал
`invalidateQueries` сам, списки ключей расходились, и любая забытая строка
превращалась в баг «данные появились только после F5» — `staleTime` в пять минут
делал его тихим и плохо диагностируемым.

## Considered Options

- **Оставить разбросанные вызовы, добавить проверку линтером.** Отклонено:
  проверка ловит нарушение, но не сообщает правильный список ключей, и знание
  «что задевает утверждение позиции» осталось бы в голове автора вызова.
- **Теги поверх react-query (`useMutation({ meta: { tags: [...] } })` +
  `invalidateTags`).** Отклонено: своя абстракция поверх уже выбранной
  библиотеки ради шести-семи доменов; при таком количестве явная таблица
  читается без прыжков по коду.
- **Оставить `staleTime` длинным, чинить только инвалидацию.** Отклонено:
  длинный `staleTime` — усилитель, а не причина. Он превращает любую будущую
  забытую инвалидацию в немедленно воспроизводимый баг вместо тихого.
- **Поллить экраны, чтобы не полагаться на инвалидацию.** Отклонено как
  дороже: постоянный трафик и невозможность отличить «нет изменений» от
  «изменения не доехали». Вынесено в отдельную задачу (тикет #206) для
  сценария «чужие изменения на другом терминале».

## Consequences

- Экран, который меняет данные, обязан вызвать `invalidateAfter(queryClient,
  действие)`. Прямой `invalidateQueries` в фиче — дрейф, который реестр
  предотвращает.
- События с сервера (фаза 2) обязаны звать тот же `invalidateDomains`. Второй
  способ сбросить кэш вернёт баг.
- Префиксы в реестре записаны сырыми корнями ключей, а не собраны фабрикой
  `queryKeys`: фабрика подставляет параметры (`params ?? {}`, `spgId`,
  `key ?? null`), и префикс из неё не совпадает с реальным ключом, если тип
  параметра не совпал. Так были сломаны инвалидации `transfers.readyAll`,
  `transfers.historyAll` и `plan.duplicates` — они молча не сбрасывали ничего.
- Лишний сброс домона стоит одного лишнего запроса; недостаточный — это баг,
  видимый пользователю. Матрица склоняется в сторону запаса.
- `staleTime` в три секунды означает «пришёл на экран — перечитай», а не
  «каждые три секунды делай запрос»: опроса в проекте нет.
