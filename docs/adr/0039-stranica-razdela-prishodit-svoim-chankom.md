# 0039. Страница раздела приходит своим чанком

- **Статус:** принято
- **Дата:** 2026-09-27
- **Связано с:** #199

## Контекст

Роутер объявлял все страницы разделов статическими импортами: двадцать одна
страница из девяти фич. Сборка складывала их в один чанк — 2 538 КБ (653 КБ
gzip) на весь контур.

Оператор открывает приложение ради одного раздела и ждёт этот вес целиком:
сначала обзор, потом, через клик, — нужный раздел. Все страницы приезжали до
того, как оператор успел выбрать, куда идти.

В dev-режиме это не видно: Vite отдаёт модули по файлам, и ленивая загрузка
выглядит как отсутствие изменений. Видно только в боевой сборке.

## Решение

### 1. Страница раздела — динамический импорт

`app/lazyRoute.tsx::lazyPage(loader, name)` даёт `React.lazy` по
именованному экспорту модуля. Все двадцать одна страница в
`app/Router.tsx` объявлены через него; ни одна не импортируется статически.

Обзор (`DashboardPage`) остался в начальном пакете: это экран, на который
оператор попадает сразу, и ждать его чанк после загрузки каркаса — значит
добавить спиннер к первому экрану.

### 2. Ссылка на модуль страницы — по файлу страницы

Раньше страницы справочников брались из барела `features/references`.
Один импорт барела кладёт в чанк все страницы фичи: `raw-materials`,
`products`, `spg` и `routes` ехали бы вместе, и ленивая загрузка перестала бы
экономить. Роутер импортирует файл страницы напрямую — тем же способом, каким
он и раньше брал страницы planning, settings, auth, execution и остальных.

Баррелы `features/references`, `features/planning` и `features/admin`
удалены: после перехода они нигде не импортировались, а барел, из которого
есть чем импортировать страницу, — это ровно тот путь, которым #199 вернётся
незамеченным. Теперь такой импорт не компилируется.

### 3. Граница Suspense стоит на содержимом маршрута, а не на странице

`RouteBoundary` наматывается на `<Outlet />` в `Layout` и на маршруты вне
каркаса (`/login`, `/auth/callback`). Пока едет чанк, на месте раздела —
`RoutePending` (`role="status"`, `aria-label="Загрузка раздела"`), а меню и
профиль остаются на месте.

Граница одна на всё дерево маршрута, включая вложенные страницы
(`/references/*`): оборачивать каждую страницу своей границей — значит
забыть одну и получить белый экран на ровно том переходе, который никто не
проверял.

### 4. Навигация идёт через `startTransition`

`RouterProvider` в `app/main.tsx` включает `future.v7_startTransition` —
это то, что react-router 6 делает по умолчанию в v7.

Без этого флага переход в ещё не загруженный раздел — синхронное обновление.
React 18 на таком обновлении не перерисовывает содержимое границы, а прячет
уже показанное (`display: none`) и рисует фолбэк. Спрятанный элемент теряет
фокус, и обратно фокус не возвращается: управления фокусом на смену маршрута
в приложении нет (`installDialogFocusTracker` работает только для окон).
Оператор, который перешёл по ссылке изнутри таблицы, терял бы место в
клавиатуре.

С `startTransition` React ждёт готовности нового раздела, не трогая старый:
пока едет чанк, видно прежний экран, фокус остаётся на месте, а фолбэк
приходится на первое появление раздела — прямую ссылку и перезагрузку, где
предыдущего экрана нет.

Покачивать прошлую страницу во время загрузки новой «вручную» не стали: для
этого пришлось бы держать в памяти предыдущий раздел целиком, а с флагом
React делает ровно то же самое.

## Последствия

**Хорошо**

- Начальный пакет: 654 КБ (213 КБ gzip) против 2 538 КБ (653 КБ gzip) — почти
  в четыре раза меньше. Оператор ждёт каркас и обзор, а не весь контур.
- Первый переход в раздел тянет ровно этот раздел. Переход между уже
  открытыми разделами мгновенный: модуль в кеше браузера.
- Прямая ссылка и перезагрузка работают: маршрут разбирается до рендера,
  чанк приезжает по нему же.
- Пока едет чанк, прежний раздел остаётся на экране вместе с фокусом на нём.
  Замер на медленной сети: переход из «Передач» в «ГХП» 6,8 с — всё это время
  видны прежние передачи, фолбэк не показан, фокус стоит на элементе внутри
  раздела.
- Раздел добавляется в роутер одной строкой и стоит в начальном пакете ноль
  байт.

**Плохо**

- Прямая ссылка на ещё не открытый раздел показывает спиннер там, где раньше
  был мгновенный экран. В локальной сети это десятки миллисекунд, по
  мобильному интернету — заметно.
- Фокус после смены раздела уходит на `body`: элемент, на котором он стоял,
  демонтируется вместе со старой страницей. Это поведение приложения, а не
  ленивой загрузки: управления фокусом на смену маршрута здесь нет вовсе.

- `shared/ui` и табличный слой склеились в один общий чанк на 769 КБ: он
  нужен почти всем табличным страницам и достаётся при первом входе в любой
  из них. Дальше эту связку стоит резать по `@user/ui` и `EntityDialog` —
  отдельная задача, здесь она не начата.
- Упавшая загрузка чанка (после деплоя с новым бандлом) не имеет своего
  обработчика: граница отвечает только за ожидание. Отдельный обработчик
  ошибки загрузки не заведён — восстановление через перезагрузку страницы.
- `lazyPage` намеренно не различает named-экспорт компонента: имя проверяется
  один раз, при первом рендере.

**Нейтрально**

- Мёртвые барелы фич удалены вместе с переходом. Это побочный эффект решения,
  а не отдельная чистка: оставить их — значит оставить открытым путь, которым
  начальный пакет снова станет 2,5 МБ.
