# Backend — KTM-2000

FastAPI + SQLAlchemy async + Alembic. Python 3.12+.

## Структура

```
backend/app/
├── api/routes/     # Эндпоинты FastAPI
├── core/           # Config, database, deps
├── models/         # SQLAlchemy ORM
├── schemas/        # Pydantic
├── services/       # Бизнес-логика
├── stock/          # Stock Ledger (StockTransaction, StockBalance)
├── transfers/      # Передачи между участками
└── seeds/          # Демо-данные
```

## Правила

- Все операции с БД — через `AsyncSession` (async).
- Миграции: `npm run db:makemigrate -- "описание"` → `npm run db:migrate` (из корня).
- Seed: `npm run db:seed`.
- API docs: `http://localhost:8012/docs` (dev).

## Stock Ledger

Единый источник правды — `StockTransaction` (append-only). Legacy `SpgRemainder`, `Movement` удалены.

- `Transfer` → 2 транзакции (`TRANSFER_SEND` + `TRANSFER_RECEIVE`) через `StockCommandService.record()`.
- Отмена = компенсационная транзакция с `reverses_id` (журнал действий — `action_journal`, ADR-0019).

## Форма запросов: identity-map и «связь не нужна»

Два правила, выросшие из ночной смены 2026-10-02. Оба — про то, как
**выглядит** код, а не как он работает; оба ломают оптимизацию, которая
по разбору кода выглядит верной.

### `db.get` по уже загруженной строке не ходит в БД

Async-сессия SQLAlchemy держит **identity map**: строка, уже прочитанная в этой
сессии, лежит в памяти, и `db.get(Entity, id)` по ней не выдаёт SQL. Поэтому
per-row `db.get`/`scalar` в цикле часто даёт **нулевую или отрицательную**
разницу при замере, а батчинг, наоборот, добавляет свои запросы.

Числа этой ночи — три независимых случая одного и того же:

| тикет | было → стало | вывод |
|---|---|---|
| #294 место 2 (СПГ по участку) | 11 → **13** SQL | `db.get(SPG)` по уже загруженному — бесплатен, батчинг дороже |
| #299 пп. 1–3 (строки плана, габариты) | 14 → **14**, первая правка 14 → **15** | строки плана уже приезжали join'ом; правильно — взять их из результата, а не грузить ещё раз |
| #300 (снимок цепочки авто-передачи) | 96 → **97** SQL | цепочка из одного шага: к моменту вызова всё уже загружено `complete_task` |

Как оценивать: **выигрыш считается по `SELECT count(*)` на данных, где цикл
реально разворачивается**, а не по виду кода. Батчинг оправдан там, где цикл
разворачивает выборку (много разных `id`, разные строки БД); там, где строка уже
в памяти, он стоит лишнего. Разборы целиком: `docs/night/tickets/T-294b-*`,
`T-299-*`, `T-300-*`.

Рецепт замера (слушатель движка, `rollback`, сверка ответа) — раздел
«Замер SQL до/после» в `docs/testing-guide.md`.

### «В профиле нет связи» ≠ «связь не нужна»

Два независимых наблюдения:

1. **Ветка могла не выполниться.** Отсутствие связи у объекта в конкретном
   прогоне ничего не доказывает: если условие выборки не нашлось, строка не
   читалась вовсе. Прежде чем писать «связь не нужна», докажи это **замером на
   данных, где ветка точно выполняется** — счётчиком SQL или отдельным кейсом.
2. **Связь может читаться через свойство или сериализацию.** `from_attributes`
   у Pydantic-схем и `lazy="raise"` ловят обращение, которое grep по
   `user.sections` не находит. Стандартный приём — **тест-проба: временно
   поставить на подозреваемую связь `lazy="raise"`** и прогнать: если ручка упала
   с `MissingGreenlet`/`InvalidRequestError`, связь действительно читается и её
   оптимизация имеет смысл.

## Dev-режим

- `npm run backend` (из корня) поднимает `backend/scripts/dev_server.py`, а не
  `uvicorn --reload` напрямую. Скрипт нужен на Windows: uvicorn перезапускает
  рабочий процесс через `CTRL_C_EVENT`, который бьёт по всей консоли и уносит
  FRONTEND/DB из `npm run dev`. Там же — скоуп `app/` (правки `tests/`, `alembic`,
  `scripts` не перезапускают backend) и пропуск рестарта, если изменённый файл
  не компилируется: тогда backend продолжает работать на последней валидной
  версии кода.
- Источник правды для DSN — env-файл (`.env.dev`, `$ENV_FILE` для
  `.env.prod`/`.env.test`), а не переменная окружения `DATABASE_URL`.
  `app.core.env_file.apply_env_file(override=True)` грузит файл **поверх**
  окружения и вызывается до импорта приложения: `dev_server.py` и
  `alembic/env.py`. Тесты изолированы через `TEST_DATABASE_URL` и это не
  затрагивают. Прод-контейнер файла не содержит — там DSN задаёт compose.
