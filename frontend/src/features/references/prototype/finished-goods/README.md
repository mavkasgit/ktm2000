# ПРОТОТИП (throwaway) — страница «Продукты», issue #143

**Вопрос:** как выглядит страница «Продукты» — список наименований ГП (отдельно от сырья)
+ карточка продукта (состав из 1–2 компонентов, размеры/длины/цвета, спорный блок операций).
По образцу RawMaterialsPage + CatalogForm/CatalogCard.

**Форма:** три варианта на существующем маршруте `/references/products`, переключение
через `?variant=` и плавающую панель внизу (стрелки или клавиши ←/→). Только в DEV-сборке.

## Варианты (сходятся ровно в одном: список ГП отдельный, только норматив)

| | Список | Карточка | Блок операций на карточке |
|---|--------|----------|---------------------------|
| **A** | таблица (как у сырья) | модалка по клику на строку | **главный блок**: «Маршрут» со всеми секциями и переходами |
| **B** | две панели: список слева, карточка справа всегда видна | вкладки, по умолчанию «Состав» | **вкладка** — есть, но не навязывается |
| **C** | сетка плиток (как «Сетка» у сырья), состав виден прямо на плитке | «паспорт изделия» по клику | **нет**: только строка «N операций → страница Маршруты» (позиция research Odoo/SAP) |

## Данные

- Список ГП — реальный API (`type=finished_good`), маршруты — реальный
  `GET /products/{id}/route-stages`.
- **Состав** — мок (детерминированный из артикула, компоненты берутся из реального
  сырья `type=component`): модели состава на Product ещё нет. Помечен бейджем
  «данные прототипа».
- Прототип read-only: никаких мутаций.
