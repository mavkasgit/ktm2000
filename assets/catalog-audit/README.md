# Входы аудита реестра профилей

Данные, из которых собирается [`docs/catalog/ktm-profile-register.md`](../../docs/catalog/ktm-profile-register.md)
(`npm run docs:profiles`). Аудит — единственный источник доказательств для
уверенности в размерах и фото: без него скрипт считает размеры, фото и
классификацию пустыми, и реестр теряет уверенность (100% → 0). Поэтому
`scripts/build-profile-register.py` без этого каталога падает с exit 2 и ничего
не пишет.

## Состав

| Путь | Что внутри |
|---|---|
| `groups/<группа>/results.csv` | вердикт по фото артикула (`verdict`, `confidence`, `note`, `evidence`) и ячеек 2024 (`cells_2024`) |
| `dimensions/dimensions-reconciled.csv` | сверка периметров/габаритов: архив, плакат, лучшее значение, источник |
| `decisions-applied.csv` | применённые решения по спорным артикулам |

## Происхождение этой копии

Оригинал жил в `data/tmp/poster-photos/audit` (каталог `data/` в gitignore) и
был утерян. 19.11.2026 входы восстановлены из закоммиченного
`docs/catalog/ktm-profile-register.json` его же полями (`audit_*`,
`perimeter_*`, `dimension_*`, `applied_decision`, связи `shared_cell_2024`) и
проверены пересборкой: у всех 214 артикулов реестра поля, зависящие от аудита,
совпали с прежней версией. Отличия остались только там, где изменились сами
данные прода (фото, `attributes`, длины, состав каталога).

Артикулы, появившиеся в KTM после аудита (`389`, `367`, `урны`), аудита не
имеют: они собираются по БД и попадают в реестр как `unknown`/требуют
проверки. Это ожидаемо, а не ошибка.

## Обновление

При новом аудите положите его результаты сюда той же раскладкой и пересоберите
реестр:

```bash
npm run docs:profiles
npm run docs:profiles:check
```
