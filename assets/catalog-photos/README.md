# Архив фото и чертежей артикулов

Здесь лежит рабочая копия всех фото артикулов — оригинальные снимки с плакатов,
чертежи профилей и сгенерированные «типизированные» изображения. Ровно те файлы,
которые приложение отдаёт из `/static/products/`.

## Зачем архив в git

Рабочий storage (`data/storage-dev`, `data/storage-prod`, прод-`storage/`) целиком
в `.gitignore`: он машинно-локальный, его теряют при переезде, сносе `data/` или
чистом клоне. Архив — единственная копия картинок, которая живёт вместе с кодом и
восстанавливается на любой машине.

## Что внутри

- 370 файлов `*.jpg`, около 24 МБ, без подкаталогов.
- Имена совпадают с файлами в `storage/products`: `<артикул>_full.jpg`,
  `<артикул>_thumb.jpg`, встречаются суффиксы `_v2`, `_<id>`.
- Содержимое `data/storage-dev` и `data/storage-prod` на момент снятия архива
  совпадало байт-в-байт; `storage-dev` содержал три лишних файла (`31_163_*`),
  они тоже здесь.

## Восстановление

```bash
npm run photos:restore                     # в data/storage-dev/products
npm run photos:restore -- --target <dir>   # в другой storage, например прод
```

Скрипт не перезаписывает байт-в-байт одинаковые файлы. Это важно: версия фото в
URL считается по `mtime_ns + size` (#404), и перезапись идентичного файла сбросила
бы кэш всех фото. Реально изменённый файл копируется и получает новый `mtime` —
URL получает новую версию, браузер скачивает только его.

## Обновление архива

После замены или добавления фото в storage:

```bash
npm run photos:save      # data/storage-dev/products → assets/catalog-photos
git add assets/catalog-photos && git commit -m "chore(catalog): обновить архив фото"
```

Проектная копия хранится в `data/storage-prod`: если меняли её, укажите источник
явно — `npm run photos:save -- --source data/storage-prod/products`.
